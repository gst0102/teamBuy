# AScript + ESP32 HID 专项规则

本文件仅对 `automation/ascript/` 及其子目录生效，并继承根目录 `AGENTS.md`。它把单次测试和生产运行明确分开。

## 1. 通用规则

- AScript 项目入口是 `automation/ascript/__init__.py`；脚本应按 AScript 项目方式运行，不在本机 Python 中模拟设备运行。
- 不确定的 AScript API 先查已安装模块文档或官方示例，不凭记忆发明参数。
- Android HID 模式优先使用与运行模式一致的 UI 树/选择器模式；当前 HID 页面感知统一使用 `mode=6`。
- 页面操作采用“控件树感知 + ESP32 HID 执行 + 状态复核”：控件树只负责解析唯一目标和 `rect`/中心点，实际点击、长按、滑动、输入、返回和 Home 均必须通过官方 `BleDevice`；不得用 `node.click`、`action.click` 或 `action.swipe` 代替 HID 执行。
- OCR、截图和颜色证据只用于辅助确认，不得为动作目标提供默认坐标；控件树未暴露唯一目标时停止。禁止用固定坐标兜底，也不得通过反复盲滑来“碰运气”找控件。
- 每次动作前确认页面锚点、目标唯一性和没有阻塞弹窗；动作后检查页面锚点、日志或可观察结果。无法判断当前页面时立即停止。
- 不用固定 `sleep` 作为主要判断方式；等待必须由界面状态、日志或明确的超时条件驱动。
- 官方 ESP32 BLE HID 只用于发送用户明确要求的普通输入动作。禁止注入微信进程、私有协议、协议构造、XML 解析、服务器模拟、token/session/key 提取和安全检测规避。
- `BleDevice.click()` 无返回值时得到 `None` 属于正常接口行为；不能把 `None` 当作点击失败，也不能把无异常当作手机 UI 已成功改变，必须继续做界面验证。
- 日志应包含步骤号、动作、观察到的状态、失败原因和停止原因；不得记录敏感凭证。

## 2. `TEST_SINGLE` / `TEST_ONLY`：单个 c 编号测试范围完整链路

只有当前用户明确指定 `TEST_SINGLE`（或把目标标记为 `TEST_ONLY`），且范围限定为本人设备、本人微信账号及一个明确配置的 c 开头 PC 群编号/批次时，才使用本节规则。该编号下由 PC 返回并通过营销资格校验的目标群共同构成本次测试范围；AScript 不另配群名或候选 ID 静态名单。

- 每次只允许一个 c 开头群编号、一个批次、一条固定文字和一张微信客户端中已经存在的卡片；可发送该 PC 编号下返回的全部合格目标，并按微信原生上限分块。禁止跨编号扩展、循环重跑、自动加群和自动加好友。
- `TEST_SINGLE` / `TEST_ONLY` 允许自动化完整执行到一次最终 UI 发送并验证结果，不默认停在发送前等待人工操作。这个权限只覆盖当前明确的单次测试，不转移到其他群、其他账号或生产任务。
- 文字测试必须确认目标群顶部标题、输入框焦点、输入内容和发送后消息气泡；卡片测试必须从现有聊天中定位卡片，使用微信原生转发入口，确认目标群后只转发一张并验证聊天窗口出现卡片。
- 目标群、卡片、输入框或发送按钮无法唯一定位时停止，不盲点、不重试造成重复发送。
- 发生异常时只做有界恢复，例如返回到可识别的上一层、重新定位一次；恢复后仍无法确认状态就停止并保留日志/截图。
- 结果必须区分“设备动作调用成功”和“微信界面结果已验证”。只有后者才可输出测试成功。

## 3. `PRODUCTION`：生产/运营路径

- `PRODUCTION` 不继承 `TEST_SINGLE` 的完整发送权限。AScript + ESP32 HID 不得直接承担生产营销执行或无人值守群执行。
- 生产默认只能做设备连接、页面观察、任务准备、预览或 dry-run；生产发送必须有单独批准的官方能力、账号白名单、审计、频控、幂等和回滚设计。
- 不因为 ESP32 已连接、插件已导入、坐标点击无异常或测试群成功，就推断生产发送链路可用。
- 任何生产任务都必须显式标注环境、账号、目标范围、内容数量和允许的动作；缺少任一项就停止。

## 4. 最小验证顺序

1. 检查当前 AScript 工程、设备连接和运行模式。
2. 确认 ESP32 官方模块导入成功，并用小范围动作验证 HID 通道。
3. 观察当前手机页面，确认应用、聊天对象和目标控件。
4. 执行动作并立刻检查界面状态，不用固定等待代替判断。
5. 对发送结果检查唯一消息/卡片、目标群标题和时间顺序，记录日志和截图。
6. 完成单次测试后立即停止，不自动进入其他群或其他任务。
