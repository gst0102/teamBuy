# 微信助手 AScript 统一入口

`automation/ascript/__init__.py` 是唯一需要在 AScript 中启动的入口，显示
“微信助手”功能网格。手机端只负责扫描和执行，群、卡片和批次内容由 PC
端配置；PC 端以 `c1001` 这类群编号维护一对多发送方案。

## 当前入口

当前只保留一个“群发微信”入口。它会先按 `g10` 搜索并同步当前账号的群台账，
再读取 PC 端批次、群名、文字和卡片编号，执行微信原生转发。独立的“全部微信群”、
“每日新增群”、设备状态和任务日志占位入口已移除；扫描器仍作为群发前置模块保留。

旧的探针工程不属于微信助手入口；清理时只删除已确认的旧工程，不批量删除未知工程。

## 群发微信标准流程（SOP）

1. 用户在“群发微信”中选择发送批次。当天第一次进入默认第 1 批；再次进入可重选第 1 批或其他批次。PC 只为该群编号实际配置且启用的批次生成任务，因此不同群编号可以有不同批次数量。
2. 手机在打开微信前请求 PC 批次任务。PC 按“唯一微信账号 ID + 群编号”返回账号级任务，任务必须包含真实微信群名、文字内容、小程序卡片编号和批次号；日志记录“读取 PC 批次映射”。
3. 打开双开选择器。两个同名“微信”入口只能从 `mode=6` 实时控件树中各自 GridView 单项容器的矩形确定槽位，并由官方 ESP32 `BleDevice` 点击。进入微信后先打开“我”，读取唯一微信号核对任务账号；昵称“高同学”或“leo”只作可读展示与人工核对，不能作为账号唯一键。
4. 返回微信会话列表并确认位于顶部，打开置顶第一位的“卡片素材群”。第一行目标必须来自实时控件树矩形，不能用固定坐标。
5. 在素材群中定位卡片编号标记（例如 `act-001`），只长按紧挨该标记的小程序卡片，选择“转发”后进入微信原生“选择聊天”页，再点击“多选”。
6. 输入群编号搜索候选，然后按 PC 返回的真实微信群名逐一匹配。每次最多选择 9 个群；页面出现歧义、目标不唯一或无法确认时，立即截图、记录日志并停止。
7. 点击“完成”，在“分别发送给”确认页复核群名单；任务有文字时填入底部输入框，没有文字时保持为空，然后点击“发送”。只有发送后 UI 或聊天页状态确认成功，才把这些目标记为成功并回写 PC。
8. 同一群编号超过 9 个群时，按 9 个一组重复步骤 4–7，直至该编号完成；再处理本账号的其他群编号。
9. 当前微信账号完成后，切换另一个微信并重复步骤 1–8。每个账号单独建任务、单独记录目标结果，不允许按昵称合并。

正式测试只能通过实际 `wechat_assistant` 工程的 `run_project` 或 `deploy_and_run` 执行，不使用 `eval_python`。控件树只负责感知和提供矩形；点击、长按、滑动、输入、返回和 Home 全部由官方 ESP32 HID 完成。
