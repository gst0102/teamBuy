# 历史文档归档

本目录保存 teamBuy 早期阶段文档、测试报告、交接记录、旧规则和迁移材料。

## 归档规则

- 归档文件不属于当前 Codex 指令，不得覆盖根目录 `AGENTS.md`、`docs/CURRENT.md` 或 `docs/decisions-active.md`。
- 归档文件保留原文，便于追溯历史实现、验证旧结论和恢复遗漏背景；引用时必须检查它是否已经被当前文档替代。
- 新的当前事实写入 `docs/CURRENT.md`，新的长期决策写入 `docs/decisions-active.md`，不要继续向历史流水账追加规则。
- 旧的阶段性发送门禁、测试状态标记、无人值守方案和 AScript/ESP32 实验结论只在归档中保留为历史证据，不作为当前测试默认行为。

## 目录

- `root-docs/`：旧的项目记忆、决策、坑点、开发日志、交接文档、产品草案和迁移参考。
- `stage2-docs/`：阶段二产品规划、技术规格、SOP、架构方案、阶段任务和旧启动提示词。
- `qa/`：历史测试清单、自测报告、验收报告、复测报告和审查报告。
- `prompts/`：旧 Codex 启动、交接和阶段开发提示词。
- `deploy/`：旧部署说明和部署脚本记录。

## 当前引用方式

遇到历史实现问题时，先从 `docs/CURRENT.md` 确认当前基线，再按主题查阅本目录。历史文档中出现的旧产品名、旧环境、旧路径、旧版本和旧发送规则都必须重新核对，不能直接复制到当前开发任务。
