# 用户内容安全与违禁词配置：测试清单与验收标准

## 本轮范围

实现规则配置、统一文字扫描、后台审核队列、规则版本、审计记录和高暴露内容的服务端发布门禁。图片、二维码、OCR、外链安全不在本轮。

## P0 验收项

1. 未配置规则时，已有内容链路行为不变。
2. `block > review > warn > allow` 决策优先级稳定。
3. 全角、大小写、零宽字符、空格和常见分隔符不能绕过匹配。
4. 普通用户不能读取规则、修改规则或审核队列；规则词不返回给普通用户。
5. 资料、名片、商机、微信群、互助任务、任务提交和评论的发布/写入路径使用同一服务端判定。
6. 已发布内容修改后，旧安全判定不能放行新 revision；分享快照不能绕过新判定。
7. 规则停用、重新扫描和人工审核可追溯且幂等。
8. 审核记录、日志不保存完整正文、手机号、微信号或二维码内容。
9. 规则导入、规则测试不会写入业务内容，也不会阻塞列表首屏。

## P1 验收项

- 作用域只影响匹配到的内容类型或字段。
- 模糊命中进入审核，不直接误杀；白名单具备内容类型和有效期范围。
- 规则更新能生成新的 rule version 并返回待复检统计。
- 审核通过/拒绝后，过期或不匹配的旧操作不能覆盖新状态。
- 后台规则列表、审核队列、规则测试和统计状态可正常刷新。

## 对抗式样例

- `测试违禁词`、`测 试 违 禁 词`、全角字符、插入零宽字符、常见标点拆分。
- 同一词在普通行业语境下应可配置为 review 或 warn，不能默认全部 block。
- 同一规则限定某一字段后，其他字段和其他内容类型不应被误伤。
- 旧规则命中后更新正文为安全文本，旧 blocked/reviewing 结果不能继续阻止新版本；反向更新也不能继续沿用旧 allow。
- 连续点击发布、重复提交审核、并发规则更新和异步复检不能产生错误的最终状态。
