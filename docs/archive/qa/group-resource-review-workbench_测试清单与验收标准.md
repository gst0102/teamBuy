# 微信群审核子工作台：测试清单与验收标准

## 范围

PC 运营后台“业务工作台 → 微信群”子工作台，覆盖用户发布的群资源审核、投诉保护、查看积分退款、发布奖励和管理员处罚。现有“群二维码批量上传/单条上传”属于管理员录入工具，本清单不把两者混为同一队列。

## 状态与积分规则

- 用户提交后前台显示“审核中”，审核中仍允许查看和加群，但明确提示二维码可能失效。
- 查看二维码扣 15 基础积分；同一用户查看同一二维码版本只扣一次。
- 管理员确认有效后，发布奖励 +10 奖励积分正式到账；审核中只显示待发放，不算已到账。
- 更新已有群二维码不重复奖励；奖励累计上限 100 分。
- 2 个不同用户针对同一二维码版本投诉，并且两人都实际支付过查看积分时，系统自动暂停该版本、停止后续扣分并退回受影响用户的 15 基础积分。
- 投诉只触发保护和退款，不自动处罚上传者；管理员最终决定是否追回奖励、额外扣分、暂停发布或永久下架。
- 追回奖励和处罚不得把账户扣成负数；余额不足时记录处罚欠分并限制继续发布，流水和原因必须可追溯。

## P0 验收项

### 权限与队列

- [ ] 未携带或携带错误 `X-Admin-Token` 无法读取队列、详情和执行动作。
- [ ] 队列默认按更新时间倒序，能按审核状态、投诉状态、关键词、城市、行业筛选，并返回总数和待处理统计。
- [ ] 队列只展示真实用户提交的 `group_resources`，不读取旧的管理员手工录入列表。
- [ ] “审核中”是用户可见文案；不能再把“待确认”作为新发布状态展示。

### 详情与审核动作

- [ ] 详情展示当前二维码、群名称、城市/行业/用途、发布者、创建/更新/到期时间、查看/确认/投诉数、奖励状态、查看积分流水和审核日志。
- [ ] 确认有效可重复点击但只能发放一次 +10 奖励，并写入奖励积分账本和管理员日志。
- [ ] 驳回不发奖励；已到账奖励不能通过普通驳回重复处理。
- [ ] 暂停后不再出现在公开有效列表，查看接口不再扣分；恢复后按原奖励状态恢复“审核中”或“已发布”。
- [ ] 标记无效支持退款受影响查看者、追回已发奖励和额外处罚，所有操作要求原因并写日志。
- [ ] 管理员处罚支持额外扣分和发布限制，余额不足时产生欠分而不是负余额。

### 投诉保护与幂等

- [ ] 未实际支付查看积分的用户不能投诉；发布者不能投诉自己的资源。
- [ ] 同一用户对同一二维码版本只能投诉一次；同一用户重复提交不会重复计数或重复退款。
- [ ] 同一用户多次查看同一版本只扣一次 15 分；更换二维码版本后可按新版本独立计费。
- [ ] 恰好 2 个不同且已付费用户投诉时触发自动暂停；不能要求第三个投诉。
- [ ] 达到保护阈值后，所有受影响付费查看者各退回一次 15 基础积分；重复处理不能重复退款。
- [ ] 投诉保护不自动扣上传者积分，必须等管理员动作。
- [ ] 资源自动暂停与查看扣分并发时，不能在暂停后新增一笔查看扣分。
- [ ] 尚未进入互助页的发布者被处罚时，仍先初始化并计入共享基础积分 100 分。
- [ ] 永久下架后重复调用审核、无效处理或处罚接口必须被拒绝；退款补救仍保持流水幂等。

## P1 验收项

- [ ] 列表和详情对不存在资源返回明确 404；对已删除资源不能恢复成公开资源。
- [ ] 审核原因、处罚原因、操作者和时间在日志中完整保存。
- [ ] 页面按钮在动作中有禁用/处理中状态，动作成功后刷新队列和详情，避免旧数据覆盖新状态。
- [ ] 二维码加载失败时详情仍能查看元数据和流水，不出现整页空白。
- [ ] 旧数据缺少新增审核字段时可正常读取，并按 `rewardState` 推断为“审核中”或“已发布”。

## 自动化测试建议

- `backend/tests/test_group_resource_review_workbench.py` 覆盖上述 P0 规则。
- 运行 `pytest -q backend/tests/test_group_tools.py backend/tests/test_group_resource_review_workbench.py`。
- 运行 `node --check` 检查运营后台内联脚本，并用 Python 解析后台路由模块。

## 人工验收

- 使用 PC 运营后台真实管理员 Token 打开“业务工作台 → 微信群”。
- 分别验收空队列、审核中、已发布、投诉暂停、已驳回、已过期六种状态。
- 人工确认二维码预览、按钮文字、积分颜色和审核日志均与操作结果一致。
