# 互助任务分享卡与过程记录对抗式审查报告

日期：2026-09-02

## 结论

代码和定向测试通过；发现的边界缺陷已修复。微信开发者工具和真机验收仍未完成，因此不能把本轮静态/后端通过等同于已上线。

## 已发现并修复

1. 分享卡业务层新增字段会在 `share-snapshot` 归一化时被丢弃。已补齐步骤、奖励和平台记录字段，并增加字段断言。
2. 参与统计如果只看事件类型会串入同一发布者的其他任务。已按 `taskId` 过滤，并排除 owner。
3. 行为接口在生产环境可能直接信任请求体的 `userId`。已改为优先使用认证会话身份。
4. 打开/返回/失败事件可针对不存在的任务写入。已对新增行为事件做服务端任务存在校验。
5. 发布者页原先只筛待验收提交，已结算记录会消失。已改为全量记录，并按状态显示操作按钮和结算信息。

## 剩余风险

- `onHide`/`onShow` 只能近似记录跨小程序生命周期；系统异常退出或网络中断可能造成事件缺失，但不会影响积分结算真源。
- 外部目标小程序没有回调时，无法验证用户是否真正完成了外部动作；当前以完成标准、提交和验收结算闭环为准。
- 需人工验证实际生成图是否在目标机型清晰、原生分享是否返回当前任务路径，以及两个真实账号的管理数据是否符合预期。
