# 互帮互助双积分账本 Codex 自测报告

日期：2026-09-02（Asia/Shanghai）

## 结论

双积分核心、旧数据兼容、奖励入账、账本筛选、任务侧积分类型传播和用户端展示已完成本轮自测；后端测试通过，生产后端已部署并恢复健康。小程序仍需要用户手动上传体验版，正式任务数据尚未迁移为服务端权威数据。

## 已覆盖

- 新用户首次初始化：基础积分 100，奖励积分 0，总积分 100。
- 基础/奖励账本分别扣减和增加，余额不会串账。
- 同一账本重复幂等键不重复入账；不同账本允许独立流水。
- 未知积分类型被拒绝。
- 历史 JSON 单余额和历史 `recharge` 流水迁移：旧奖励流水进入奖励账本，其他流水进入基础账本。
- 互帮互助状态接口同时返回 `account` 兼容汇总、`accounts` 双账本、`points` 三个展示值和合并流水。
- 支付完成只向奖励账本入账；重复支付确认不会重复增加奖励积分。
- 管理开关可关闭奖励入口/功能；提现仍关闭。
- 任务发布保存积分类型；小程序任务结算、普通任务结算、羊毛解锁/打赏通过对应账本读写。
- 群资源查看扣基础积分，但返回双账本总览。
- 用户端及运营页显示使用“奖励积分/获取奖励积分”，未发现中文“充值”文案。

## 2026-09-02 统一积分账户复测补充

上一版报告记录的是双账本早期状态，以下结论覆盖本轮统一账户优化后的状态：

- 三个工具使用同一 `mutual_help` 账户；基础账本承载初始 100 分和平台积分，充值账本承载充值积分，平台消费按基础优先、充值其次执行。
- 旧平台奖励、旧资源钱包和充值混合数据已补充迁移边界测试；已使用的平台奖励不重复迁移，充值流水不因当前余额计算被搬到基础账本。
