# 互帮互助双积分账本对抗式审查

日期：2026-09-02（Asia/Shanghai）

## 审查状态对象

- 目标：基础积分与奖励积分独立记账；历史数据可迁移；任务/群资源不扣错账本；用户能看到一致的总积分；奖励入口可由运营开关控制。
- 成功标准：余额、流水、幂等键、PostgreSQL 约束和 API 返回值都包含正确积分类型；旧数据不凭空制造奖励积分；生产服务健康。
- 证据：330 个后端测试、8 个积分定向测试、本地双账本脚本、生产 schema 只读核验、生产健康检查和线上关键源码哈希核验。

## 攻击路径与结果

| 攻击路径 | 结果 | 严重度 |
| --- | --- | --- |
| 历史 PostgreSQL 补列默认都是 `base`，导致旧奖励流水误归基础 | 已修复：迁移优先识别 `ledgerType=recharge`，再使用 payload/物理列 | 已关闭 |
| 迁移更新不存在的物理 `balance_after` 列导致全服务重启失败 | 已修复：只更新流水 JSON 的 `balanceAfter`；生产重启验证通过 | 已关闭 |
| 两个账本使用相同幂等键互相冲突 | 已修复：内存、唯一索引和查询均包含 `pointType` | 已关闭 |
| 奖励支付入到基础账本 | 已修复：订单固定 `pointType=reward`，完成支付只 grant 奖励账本 | 已关闭 |
| 群资源扣基础分后页面把基础余额当成总余额 | 已修复：接口返回双账本状态和汇总 | 已关闭 |
| 关闭/隐藏奖励入口后已有奖励余额消失 | 已防护：非零奖励余额仍展示，隐藏只控制入口/零余额行 | 已关闭 |
| 重复完成任务造成重复奖励 | 本地提交 settlement 有幂等保护；服务端任务结算尚未迁移 | P1 未完成 |
| 客户端篡改本地任务或本地积分绕过扣分 | 当前本地演示可被本机存储修改；正式任务服务端权威化前存在 | P1 未完成 |
| 生产支付真实链路 | 未创建生产订单，未做真实支付验收 | 未知/需人工 |

## 最小后续动作

1. 小程序上传体验版后人工验证双账本显示、开关隐藏、发布时账本选择、完成任务后的对应积分变化。
2. 下一阶段把任务与提交结算迁移到服务端事务，以 PointsCoreService 做唯一扣增入口，再补跨请求并发和重复提交测试。
3. 真实支付开启前，继续保持提现关闭，并由人工确认奖励积分的支付、退款和运营开关。

## 审查结论

双积分账本及其生产迁移达到本轮目标；没有发现仍会阻断服务启动或直接串账的 P0/P1 实现缺陷。P1 风险集中在既有本地任务演示边界，不应把当前小程序本地结算宣传为生产级防篡改账本。

## 2026-09-02 统一积分账户复审

### 审查范围

- 统一账户是否真的被群资源、商机合作和互帮互助共同使用。
- 平台积分、充值积分和旧数据迁移是否发生串账、重复迁移或重复扣分。
- 暂不增加积分中心时，三个工具入口和现有“我的”是否保持稳定。
- 页面余额文案是否与真实余额含义一致。

### 对抗场景与结果

| 对抗场景 | 结果 | 严重度 |
| --- | --- | --- |
| 新用户首次访问商机、群资源和互帮互助，分别初始化余额 | 通过：同一基础账本为 100，充值账本为 0 | 已关闭 |
| 账户为基础 100、充值 100，一次消费 105 | 通过：基础先扣至 0，充值剩余 95 | 已关闭 |
| 同一资源/名片重复消费请求 | 通过：按目标幂等，不重复扣分 | 已关闭 |
| 旧资源钱包余额为 100，首次读取或消费 | 通过：只写一次迁移标记，不重复发放初始 100 | 已关闭 |
| 旧奖励账本同时存在充值 100、平台奖励净额 10 | 通过：只把可识别的平台净额迁入基础，充值仍留在充值账本 | 已关闭 |
| 旧平台奖励已被历史消费 | 通过：按可识别净额迁移，不把已使用部分再次迁移 | 已关闭 |
| 管理员首次审核发放平台奖励 | 通过：先初始化基础账本，再发放奖励，不丢初始 100 | 已关闭 |
| 本地 v3 缓存中的 reward 可能是充值积分 | 通过：不凭余额猜测，保留 reward，等待服务端权威覆盖 | 已关闭 |
| 用户通过页面寻找第四个“积分账户”入口 | 通过：仍保持互帮互助、微信群工具、商机合作三个入口 | 已关闭 |
| 商机 Banner 把总余额标成基础积分 | 已修复：改为“我的可用积分” | 已关闭 |
| 任务管理把充值账本显示成“奖励” | 已修复：改为“充值” | 已关闭 |

### 复审结论

本轮没有发现新的 P0/P1 账本串用、重复扣分或迁移重复缺陷。当前最大上线风险不在本地实现，而在生产 schema 迁移和微信开发者工具人工验收：部署前必须确认旧唯一索引已清理，真机需确认三入口、总积分/充值积分展示和跨设备余额刷新。独立积分中心暂不应作为本轮上线阻断项。
