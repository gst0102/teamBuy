# 五类内容编辑器：测试清单与验收标准

更新时间：2026-08-13

开发规格：

- `docs/stage2-docs/39-content-editor-product-design-decisions.md`
- `docs/stage2-docs/40-five-editor-data-route-attachment-spec.md`

## 1. 验收结论规则

- 任一 P0 未通过：结论必须为“不通过”。
- 自动化无法覆盖的微信分享封面、PDF 微信预览、腾讯地图导航和真机布局：标记“需要人工确认”，不得伪报通过。
- UI 与 `docs/png/editor-design/` 参考图明显不同：即使接口通过，也不得判定通过。
- 本轮只验收测试环境，不部署或验证生产 `/api`。

## 2. P0 数据与权限

- [ ] 五类编辑器均加载并更新同一 `noteId`；保存、换类型、换样式、预览返回均不重复创建资料。
- [ ] 拥有者 A 无法通过 GET/PUT/DELETE 编辑拥有者 B 的资料。
- [ ] 公共 API 不返回任何 `privateData`、私密附件、内部标签、客户信息、统计快照或跟进记录。
- [ ] 房源公开数据不含具体楼栋/单元/房号、密码、私密精确坐标、上游联系人和佣金。
- [ ] 商品公开数据不含供应商、成本、利润、内部库存、采购链接和接龙名单。
- [ ] 服务公开数据不含历史内部管理字段。
- [ ] 电子名片公开身份来自资料拥有者的统一销售资料，不能显示旧资料中另一套过期电话或微信。
- [ ] 所有分享资料后端统一开启基础 SCRM；前端没有关闭 SCRM 的入口。
- [ ] 拥有者自己预览、自己打开附件不计入客户信号。
- [ ] 生成同款产生新 `noteId` 和新统计链路，不覆盖来源资料。
- [ ] 生成同款幂等键重复提交只生成一次。
- [ ] 电子名片生成同款不复制原姓名、头像、职位、公司、二维码、联系方式、个人介绍和精选资料。
- [ ] AppSecret、Token、私钥和 `.env` 内容未进入前端、日志、文档或 Git diff。

## 3. P0 附件模型

- [ ] 图片上传后得到稳定附件 ID、正确 URL/MIME/大小/顺序，首图正确成为封面。
- [ ] PDF 上传保留真实 PDF 字节和 `application/pdf`，未被图片处理器改写。
- [ ] 非 PDF 伪装成 `.pdf` 被后端拒绝。
- [ ] 超过20MB PDF、超过5份PDF、超过9张图片或总附件超过12时，前后端都给出明确错误。
- [ ] 外部链接只接受 HTTPS，拒绝 `javascript:`、`file:` 等危险协议。
- [ ] 客户能通过 `wx.openDocument` 打开有效 PDF；失败时有重试/删除/重新上传路径。
- [ ] 删除资料中的附件引用不会误删另一份资料仍在使用的同一底层资源。
- [ ] 公共客户页无法访问私密附件。
- [ ] PDF/链接点击事件中的附件 ID 必须属于当前资料，伪造其他附件 ID 被拒绝。
- [ ] 雷达只表述“打开PDF/点击链接”，不出现“读完、看到第N页”等虚假结论。

## 4. P0 路由与创建

- [ ] 统一路由解析器覆盖全部已知 `cardType`；未知类型必须失败关闭，保留资料但不渲染任何旧编辑器 DOM。
- [ ] 通用旧页只接受 `text_note/image_ocr/mixed_content/pdf_document`；`link/article/property_listing/groupbuy_product/service_offer/business_card` 及任何未知类型必须在渲染前离开通用旧页。
- [ ] URL 编辑页不得出现“轻 CRM/留言表单/预约/接龙/基础信息/通用附件管理” DOM。
- [ ] 首页、资料页、导入认领、笔记页、旧卡片入口、新建页均使用统一路由解析器。
- [ ] 新建文字/图片/链接/房源/商品/服务/名片后跳转到正确编辑器。
- [ ] 类型确认只修改当前资料并跳转，不创建第二条资料。
- [ ] 一个用户已有主电子名片后再次点击新建名片，进入原名片编辑器。
- [ ] 编辑器“保存并预览”统一进入同一 `noteId` 的 `note-preview`。
- [ ] 分享路径完整携带 `sid/from/src/ref`，二次分享不丢失来源归因。
- [ ] 旧 `property-same` 链接仍能进入兼容流程，不出现404。

## 5. 通用编辑器

### 5.1 文字

- [ ] 只显示标题、正文、选填插图及必要更多设置，不出现摘要必填、能力插件、客户反馈和浮动保存按钮。
- [ ] 无图资料生成排版型客户预览和微信分享封面，不出现空白图片占位。
- [ ] 短文不强制摘要；长文摘要可自动生成并允许修正。

### 5.2 图片

- [ ] 1～9张图片可添加、删除、排序；第一张同步为客户页和分享封面主图。
- [ ] OCR失败不阻止资料保存和分享。
- [ ] OCR全文默认不在客户页重复显示。
- [ ] 检测到房源/商品时只提示切换，不自动创建重复资料。

### 5.3 链接

- [ ] 展示原文标题、封面、来源、简介、销售推荐语和“查看原文”。
- [ ] 客户页不复制第三方全文。
- [ ] 页面打开和原文点击为两个独立事件。
- [ ] 无封面或元数据抓取失败时有可用的文字降级样式。

## 6. 房源编辑器

- [ ] UI 与 `04-property-editor.png` 核心结构一致。
- [ ] 出租/出售是单一值；默认只展示当前值，切换后只显示对应字段。
- [ ] 小区与展示标题分开，具体房号不会进入公开标题。
- [ ] 图片、核心信息、亮点、更多信息、公开位置、私密管理采用渐进结构。
- [ ] 腾讯地图公开导航到小区/楼盘公共位置。
- [ ] 房源拥有者可在私密区域使用精确位置，但客户不可见。
- [ ] 咨询和预约看房可提交，并关联客户雷达。
- [ ] 地图无坐标、选点失败和导航失败都有明确降级提示。

## 7. 商品 / 团购编辑器

- [ ] UI 与 `05-product-editor.png` 核心结构一致。
- [ ] 咨询购买/团购接龙为单一销售方式，界面只展示当前值。
- [ ] 单价和简单多规格可用，不出现属性组笛卡尔积 SKU。
- [ ] 新金额使用整数分保存，列表、客户页和分享封面格式一致。
- [ ] 咨询模式不显示接龙设置；接龙模式显示截止、限购和履约说明。
- [ ] 页面不出现在线支付、退款、物流、优惠券等未实现能力。
- [ ] 自提位置腾讯地图可导航。
- [ ] 接龙提交同时产生履约记录和客户高意向信号，不脱离 SCRM。

## 8. 服务 / 合作编辑器

- [ ] UI 与 `06-service-collaboration-editor.png` 一致，以附件组织为主。
- [ ] 只显示名称、介绍、选填说明、图片/PDF/链接、选填范围和合作条件。
- [ ] 不出现行业子类型、适合人群、交付内容、流程、案例、资质、SOP和模板选择。
- [ ] 空的服务范围、合作条件或附件模块在客户页隐藏。
- [ ] 客户点击PDF、链接和咨询均产生准确事件。
- [ ] 旧服务复杂字段迁移后内容不丢失，但不重新暴露为大表单。

## 9. 电子名片

- [ ] 资料库卡、客户主页、分享封面与 `07-business-card-three-scenes.png` 的层级一致。
- [ ] 第一版每个用户只有一张主名片。
- [ ] 头像、姓名、职位、公司、电话、微信、二维码来自统一销售资料。
- [ ] “我能提供”最多6个关键词；“精选资料”最多3项，只保存引用ID。
- [ ] 精选资料被删除/下架后，客户页自动隐藏，不报错或展示破损卡片。
- [ ] 商务蓝、简洁白、暖灰金、清新绿4种样式均可切换。
- [ ] 样式切换只改 `styleId`，不修改任何内容，不新增资料，不重置统计。
- [ ] 4种样式同时作用于客户主页和微信分享封面；资料库列表仍统一。
- [ ] 查看二维码、点击拨号和打开精选资料分别记录；不宣称已加微信或完成通话。

## 10. 生成同款、分享与分佣

- [ ] 微信分享封面保留轻量“免费生成同款”利益提示，不显示平台署名。
- [ ] 客户页标题下有轻入口，底部只有一行入口，无正文中段弹窗。
- [ ] 分享确认页向原作者展示既定50%分佣利益提示。
- [ ] 生成同款自动建立唯一直接邀请归因；已有邀请关系不被非法覆盖。
- [ ] 来源资料的私密字段、统计、客户、跟进和附件事件不进入新资料。
- [ ] 生成完成直接进入新资料预览/分享，不绕回首页。

## 11. UI与兼容性

- [ ] 全部核心尺寸使用rpx，按钮/标签采用flex上下左右居中。
- [ ] iPhone普通尺寸、大屏手机和iPad模拟器无按钮挤压、数字变形或底部安全区遮挡。
- [ ] 自动保存状态真实显示“保存中/已保存/保存失败”。
- [ ] 接口失败、上传失败、真实零数据和筛选空态语义不同。
- [ ] 旧文字、图片、链接、房源、商品、服务、名片资料仍能打开、编辑、预览和分享。
- [ ] 旧服务模板和旧名片模板迁移时不覆盖用户内容。

## 13. 对抗式审查重点

全部五类开发完成后统一审查：

1. 用另一个用户ID读取、修改、克隆私密数据。
2. 构造伪PDF、危险链接、超大文件和跨资料附件ID。
3. 连续保存、返回、切类型、换样式、重复点击生成同款，寻找重复资料。
4. 检查所有公开响应和分享路径是否泄露私密字段。
5. 检查旧数据迁移是否覆盖用户内容或改变金额/联系方式。
6. 检查客户行为是否被自己预览或重复点击污染。
7. 对照7张参考图，检查关键模块、文案、操作和空态是否缺失。
