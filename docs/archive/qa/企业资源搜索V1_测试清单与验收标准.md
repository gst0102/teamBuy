# 企业资源搜索 V1 测试清单与验收标准

更新时间：2026-06-28

## 1. 验收结论规则

P0 未全部通过时，不得判定通过。

第一版只验收：

- 资源库里的企业搜索入口
- 搜索候选
- 高频查询功能
- 积分扣减
- 缓存
- 保存企业资源卡

不验收：

- 162 个全量工具开放
- 自动爬取
- 导出 PDF
- 企业摘要卡分享

## 2. P0 测试项

### 2.1 入口与搜索

- 用户能从资源库进入企业资源搜索。
- 资源库入口采用九宫格或九宫格风格布局，不做长列表堆叠。
- 第一版即使只有部分能力可用，也要为行业黄页、商机线索等资源入口预留统一九宫格位置。
- 搜索框支持企业名称和统一信用代码。
- 搜索候选结果能展示企业名称、状态、法人、成立时间、注册资本、所在地等基础字段。
- 搜索候选不直接扣积分。

### 2.2 企业卡

- 点击候选企业后能进入企业卡页。
- 企业卡页能展示企业名称、状态、法人、成立时间、注册资本、地址、行业。
- 页面文案清楚说明深度查询会扣积分。

### 2.3 查询功能

- 基本信息功能可用。
- 至少 3 个深度查询功能可用：司法风险、历史变更、股东结构/经营情况/知识产权其一。
- 查询前会先判断用户积分是否足够。
- 查询成功后才扣分。
- 查询失败不能错误扣分。

### 2.4 缓存与频控

- 同企业同功能 24 小时内再次查看优先走缓存。
- 命中缓存时不重复扣分。
- 短时间重复点击同一功能不会连续扣分。
- 后端存在用户维度或接口维度限流保护。

### 2.5 保存企业资源卡

- 用户能把企业查询结果保存到我的资源。
- 保存后的企业资源卡包含企业名称、状态、法人、注册资本、成立时间、城市/地址、查询时间。
- 企业资源卡能打系统标签和自定义标签。
- 保存企业资源卡不暴露原始 API Key 或不必要字段。

### 2.6 安全与密钥

- Tianyancha API Key 不出现在前端、小程序包和 Git 中。
- API Key 只通过后端环境变量或服务器密钥文件读取。
- 前端只调用自家后端接口。
- 后端负责积分、缓存、频控和日志记录。

## 3. P1 测试项

- 开放 6 个高频查询功能。
- 企业资源卡展示风险提示摘要。
- 资源库首页展示企业查询已开通状态。
- 搜索页展示热门搜索和最近搜索。
- 标签筛选和搜索支持自定义标签。

## 4. P2 测试项

- 生成企业摘要卡。
- 企业摘要卡分享。
- 导出 PDF / 图片。
- 更复杂企业资源筛选。

## 5. UI 验收

- 搜索框、查询按钮、积分文案、保存按钮都必须居中且不重叠。
- 企业卡片字段在手机和 iPad 上都不能错位。
- 查询按钮区不要挤成两行残缺按钮。
- “搜索候选免费，深度查询按功能扣积分”提示必须清楚可见。
- 保存企业资源卡页要看起来像资源沉淀页，不像临时弹窗。
