# 客户跟进状态与客户详情 Codex 自测报告

日期：2026-08-27

## 结论

本轮本地代码、自测接口和页面对象级回归通过。跟进状态现在由服务端持久化结果作为唯一真源，客户端即时反馈只负责体验，不再把乐观状态当作最终结果。真实微信开发者工具、真机网络和生产数据库尚未在本轮执行，需要人工验收。

## 本轮实现

- `LeadReminder` 增加单调递增 `version` 与 `lastOperationId`。
- 跟进动作接口支持 `operationId`、`expectedVersion`，在服务端单次完成建档/状态迁移/动作日志写入，并在提交后回读确认。
- 重复操作号幂等返回同一条已持久化记录；版本过期返回 409，避免并发覆盖。
- 雷达提醒、跟进中和已放弃画像统一携带线索版本、最近跟进时间和最近日志。
- 雷达与客户详情动作成功后清理相关内存缓存；超时/未知结果先对账，无法确认时保持已出队状态，不用旧数组恢复客户。
- 客户详情优先使用 owner、环境、场景和客户隔离的短时内存缓存，后台重新校准；手机号、微信号、客户身份和详情不写入 `wx` 持久化存储。
- 详情热路径按当前客户身份读取最近 50 条浏览/动作记录，避免读取该资料全部历史事件。
- 客户留言只在拥有者与已知登录客户的精确会话关联时展示；匿名访客不做昵称、手机号或文本模糊匹配。
- 雷达和详情来源资料统一使用 canonical `noteId` 进入 `/pages/note-preview/index`。
