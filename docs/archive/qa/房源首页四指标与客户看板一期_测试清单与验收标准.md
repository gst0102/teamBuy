# 房源首页四指标与客户看板一期_测试清单与验收标准

更新时间：2026-06-23

## 1. 验收目标

验证 `docs/stage2-docs/18-property-home-customer-dashboard-v1.md` 中的一期要求是否落地：

- 房源首页四个指标让用户看得懂。
- 四个指标都能点击到对应处理页。
- 客户看板默认服务“待跟进客户”，不是默认展示 BI。
- 展示页在房源场景中作为“推荐包效果”保留。

## 2. P0 测试项

### P0-01 首页四指标文案

前置条件：

- 当前 `workspaceMode=property`。

预期结果：

- 房源首页四指标显示为：`房源 / 打开 / 访客 / 待跟进`。
- 不出现 `SCRM` 作为首页前台词。
- 第四项不能继续只叫 `客户`。

### P0-02 首页四指标点击

预期结果：

- 点击 `房源`：进入资料页，并默认筛选房源资料。
- 点击 `打开`：进入客户看板的房源效果视图。
- 点击 `访客`：进入客户看板的最近访客视图。
- 点击 `待跟进`：进入客户看板的待跟进视图。

### P0-03 客户看板默认页

预期结果：

- 从首页客户看板入口或 `待跟进` 指标进入时，默认展示 `待跟进`。
- 首屏能看到待跟进客户、最近客户动作或明确空态。
- 不默认进入 `展示页效果`。

### P0-04 展示页边界

预期结果：

- 原展示页能力不删除。
- 房源场景中展示页作为 `推荐包效果` 或等价命名出现。
- 页面文案能体现“多套房源一起发给客户”的含义。

### P0-05 匿名访客保护

预期结果：

- 匿名访客只显示匿名或计数。
- 不把匿名访客包装成实名客户。
- 不展示不存在的电话、微信或头像。

### P0-06 发布者预览不计入客户

预期结果：

- 发布者自己打开房源客户页，不增加客户打开和访客。
- 真实客户打开后，打开/访客能回流到首页和客户看板。

## 3. P1 测试项

### P1-01 房源效果列表

预期结果：

- 房源效果视图按打开或最近客户动作排序。
- 每行至少展示房源标题、打开、访客、待跟进。
- 可以查看某套房源相关客户。

### P1-02 最近访客列表

预期结果：

- 最近访客按时间排序。
- 能看到访客看过哪套房源。
- 有联系方式的访客能升级为可跟进客户。

### P1-03 待跟进客户卡片

预期结果：

- 有电话时可拨号。
- 有微信时可复制微信。
- 可标记已联系或进入现有线索处理页。
- 没有联系方式时不显示无效拨号按钮。

### P1-04 资料页房源筛选与展示

预期结果：

- 首页点击房源后资料页只看房源。
- 大屏或 iPad 不应只显示半张资料卡。
- 至少保证列表能完整展示；如果有双列/列表切换，要能切换。

## 4. P2 后置项

- 客户跨房源画像合并。
- 高意向自动判断。
- 企业微信主动推送“来客户了”。
- 复杂转化漏斗和 BI。
- 多员工团队客户分配。

## 6. 真机验收重点

- 房源首页四指标是否居中、不卡字、看得懂。
- 点四个指标是否进入正确页面。
- 客户看板第一屏是否能快速告诉用户“该联系谁”。
- 空态是否有下一步引导。
- 推荐包效果是否仍能找到原展示页数据。
