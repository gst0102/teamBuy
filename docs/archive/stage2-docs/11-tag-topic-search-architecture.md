# 资料整理助手标签、专题与搜索架构

## 目标

资料整理助手的资料组织方式采用“强标签、弱分类、专题聚合”，不做强制三级分类。

核心链路：

```text
随手发 -> 立即收藏 -> 规则标签 -> 轻模型补全 -> 用户整理/大模型增强 -> 加入专题/场景使用
```

## 产品原则

- 轻收藏是增强版微信收藏，不是通用笔记模板。
- 分类只承担系统基础视图，不作为用户主要管理结构。
- 标签是搜索、筛选、召回、推荐和后续 AI 理解的核心索引。
- 专题替代多级分类，用来承载“周末亲子露营 / 某小区团购 / 学习资料合集”等用户真实场景。
- 收藏必须先成功，标签补全和 AI 增强不能阻塞入库。
- 标签/专题负责组织资料，`cardType` 负责资料内部结构。房源、团购、文章、图片等资料卡分型见 `docs/stage2-docs/12-typed-content-card-architecture.md`。

## 数据结构第一版

第一版先兼容落在 `UserNote.visibilityConfig`，后续再独立表化。

```json
{
  "contentMode": "bookmark",
  "sourceType": "link",
  "systemCategory": "文章",
  "sourceName": "mp.weixin.qq.com",
  "sourceLabel": "微信公众号",
  "sourceUrl": "https://...",
  "tags": ["微信文章", "露营", "亲子"],
  "userTags": ["周末"],
  "tagLevels": {
    "rule": ["微信文章", "链接"],
    "light": [],
    "deep": []
  },
  "topics": [{ "id": "topic_001", "name": "周末亲子露营" }],
  "topicIds": ["topic_001"],
  "tagStatus": "rule_done",
  "canDeepOrganize": true
}
```

默认来源类型对齐微信收藏心智：

- 笔记
- 链接
- 图片与视频
- 语音
- 位置
- 聊天记录
- 文件
- 小程序

## 标签三层生成体系

### L1 规则标签

入库时同步生成，0 成本。

- 来源域名：`mp.weixin.qq.com -> 微信文章`
- 类型判断：链接、文件、图片、位置、聊天记录
- 关键词：房源、团购、草莓、露营、合同、Python

规则标签失败不能阻塞收藏。

### L2 轻模型标签

后续异步补全，低成本。

- 默认语义标签
- 相似资料聚类
- 常用标签推荐

失败不影响资料可见。

### L3 大模型深度标签

用户点击“整理”或内容复杂时触发。

- 长文理解
- 复杂内容判断
- 主标签 / 辅助标签
- 专题建议
- 结构化摘要

大模型输出必须结构化校验，不能直接覆盖用户标签。

## 深度整理策略

URL 文章点击“整理”后，默认生成文章摘要卡，不自动转成房源、团购或展示页。

房源卡、团购页、展示页必须由用户明确触发，或 AI 高置信判断后再让用户确认。

## 搜索与筛选

资料库第一版支持：

- 搜标题、摘要、正文、来源、标签。
- 按来源类型筛选。
- 按标签筛选。
- 按专题筛选。
- 按收藏时间 / 更新时间排序。

标签是搜索系统的核心索引，专题是用户行为结构。

## 后续表化方向

当前先不迁移，稳定后再拆表：

- `user_tags`
- `note_tags`
- `topics`
- `topic_items`
- `tag_suggestions`
- `tag_generation_jobs`

## 当前边界

- 第一版不接大模型。
- 第一版不做三级分类。
- 第一版不做标签重命名、合并、批量打标。
- 第一版专题关系先保存在 `UserNote.visibilityConfig.topicIds`。
