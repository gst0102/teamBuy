# 客户数据关系与经营看板组件化方案

更新时间：2026-06-21

## 1. 目标

把“谁看了、谁咨询了、谁下单/接龙了、展示页有没有效果”整理成一套可复用客户数据能力。

本阶段不做复杂 BI，不展示“行为强度分层”等内部判断概念；小程序只展示用户能理解的事实数据和待处理事项。

## 2. 数据关系

### 2.1 四类核心数据

| 数据对象 | 记录什么 | 归属 | 主要用途 |
| --- | --- | --- | --- |
| `ShowcaseEvent` | 展示页打开、点击资料、电话、复制微信、分享 | `showcaseId + ownerUserId` | 判断展示页发出去后有没有效果 |
| `CustomerAction` | 留资、预约、商品下单、团购接龙 | `noteId + ownerUserId` | 判断单条资料带来的客户动作 |
| `LeadReminder` | 待联系、已联系、跟进记录、客户手机号/微信 | `ownerUserId` | 承接需要人工跟进的客户 |
| 商品轻订单 | 复用 `CustomerAction(order-intent/relay-intent)` | `noteId + ownerUserId + viewerUserId` | 承接商品下单/接龙处理，不进入资金交易 |

### 2.2 展示页与笔记的关系

展示页只保存资料引用，不复制资料正文：

```text
ShowcasePage
  -> ShowcaseItem.noteId
  -> UserNote
```

客户打开展示页产生 `ShowcaseEvent`；客户点击某条资料时，事件里保存 `noteId`。因此同一条笔记可以同时拥有：

- 来自展示页的浏览/点击数据。
- 来自客户页的留资、预约、下单、接龙数据。

### 2.3 笔记与客户动作的关系

所有资料类型统一使用 `CustomerAction` 作为客户动作入口：

```text
UserNote
  -> CustomerAction
  -> 可选投影 LeadReminder
```

房源：

- `lead-contact` 留资后投影到 `LeadReminder`。
- `appointment` 预约后投影到同一条或同一客户的 `LeadReminder`。

商品 / 团购：

- `order-intent` 和 `relay-intent` 作为轻订单/接龙处理。
- 不默认投影到 `LeadReminder`，避免商品订单污染轻 SCRM。

普通销售服务 / 电子名片：

- 后续可以继续复用 `CustomerAction`。
- 需要跟进的动作投影 `LeadReminder`，不需要跟进的动作只留在动作列表。

### 2.4 客户资料的关系

客户资料第一版仍以 `LeadReminder` 为主，因为它保存了可跟进客户的手机号、微信、预算、标签和跟进记录。

展示页匿名访客只计数，不展示成实名客户。只有留资、预约、下单、接龙等动作里有明确客户信息时，才进入客户资料或动作名单。

## 3. 组件化方案

### 3.1 经营看板组件

新增一个可复用小程序组件，用于后续需要嵌入轻量看板的经营入口：

```text
components/business-dashboard/
```

组件只负责展示和抛出入口点击事件，不直接写业务数据。

展示内容：

- 打开：展示页真实打开次数。
- 访客：展示页真实访客数，匿名只计数。
- 看资料：展示页内资料点击数。
- 咨询：电话点击 + 微信复制。
- 展示页效果：看展示页发出去后的打开、访客、点击和咨询。
- 访客详情：看最近谁打开了展示页，匿名访客不实名化。
- 笔记数据：看哪些资料被点击，以及最近产生的客户动作。
- 客户资料：看客户资料、待联系和订单/接龙的处理入口。
- 最近访客：最近展示页访问事实。
- 资料点击排行：展示页内资料点击排行。

### 3.2 经营看板详情页

新增：

```text
pages/business-dashboard/index
```

页面包含 4 个看板 Tab：

- 展示页效果
- 访客详情
- 笔记数据
- 客户资料

“访客线索”页经营看板入口只负责进入这 4 个看板视图，不直接跳到线索/订单老页面。

线索、订单/接龙、客户库、展示页管理仍是处理区，只在看板详情页内通过“去处理”按钮进入。

### 3.3 后端聚合接口

新增：

```text
GET /api/dashboard/business?ownerUserId=xxx
```

返回：

- `summary`：总览指标。
- `entries`：四个处理入口：展示页效果、客户线索、订单/接龙、客户资料。
- `recentVisitors`：最近访客事实列表。
- `topNotes`：资料点击排行。
- `latestActions`：最近客户动作。

前端不在“我的”页自己拼多个接口，避免统计口径分散。

### 3.4 页面放置

第一版不在“我的”页展示整块经营看板。“我的”页只在“访客线索”区域保留一个小入口；主要入口放在底部 Tab 的“访客线索”页，点击进入 `pages/business-dashboard/index` 查看 4 个看板视图。

原则：

- 我的页负责账号、资源和常用工具，不承载大面积经营数据。
- 访客线索页负责承接访客、线索和经营看板入口。
- 经营看板详情页负责看展示页、访客、笔记和客户资料四类数据。
- 线索和订单仍然作为独立处理区。
- 展示页列表继续保留单个展示页自己的效果展开。
- 单条笔记仍然保留自己的客户动作/接龙名单。

## 4. 不做事项

- 不展示“行为强度分层 / 高意向分层”等内部概念。
- 不展示不能被系统证明的服务客户数、成交案例、好评率。
- 不新增正式订单表、支付、库存扣减、核销和分账。
- 不把匿名访客包装成实名客户。
- 不把商品轻订单默认投影到轻 SCRM。

## 5. 验收标准

P0：

- owner 可以从“访客线索”页进入经营看板。
- 看板数据来自真实 `ShowcaseEvent / CustomerAction / LeadReminder`，没有写死假数据。
- 匿名访客只展示数量或“匿名客户”，不进入客户库实名列表。
- 展示页效果、客户线索、订单/接龙、客户资料四个入口可跳转到现有处理页。
- 商品下单/接龙仍进入订单/接龙处理区，不默认变成线索。

P1：

- 最近访客能展示展示页来源和最近打开时间。
- 资料点击排行能展示资料标题和点击次数。
- 最近客户动作能展示留资、预约、下单、接龙事实。

P2：

- 跨展示页客户合并画像。
- 渠道码归因。
- 漏斗转化率、成交看板和更复杂的经营分析。
