# 房源首页四指标与客户看板一期方案

更新时间：2026-06-23

## 1. 背景

房源工作台首页已经具备基础结构，但当前“今日待处理”里的四个数字还不够好懂，用户看到“打开 / 访客 / 客户”时，不一定知道分别代表什么，也不知道点进去能处理什么。

同时，原来的“经营看板”更像展示页和资料数据后台，适合看整体效果，但不适合房产中介第一眼判断：

```text
今天谁看了房源？
谁留下了电话或微信？
谁需要马上跟进？
哪套房源有人感兴趣？
```

因此一期需要做两件事：

1. 把房源首页四个指标改成用户一眼能懂、能点击处理的入口。
2. 新增或重构一个“客户看板”，把客户动作放到第一屏。

## 2. 产品边界

### 2.1 房源工作台

房源工作台是中介的日常处理台，核心是：

```text
整理房源 -> 发给客户 -> 客户打开/咨询/预约 -> 中介跟进
```

首页不应该做成复杂后台，也不应该出现 SCRM 这类前台词。

### 2.2 展示页

展示页在本项目里的定位仍然是：

```text
把多套房源打包成一个推荐页，一起发给客户。
```

它不是客户看板本身，也不是首页四指标里的默认主角。展示页应作为客户看板里的一个“推荐包效果”来源，让中介知道某个多房源推荐包有没有被打开、客户点了哪套房。

前台建议逐步把房源场景里的“展示页”解释成：

```text
房源推荐包
```

但底层可以继续复用现有 `showcases` 能力。

### 2.3 客户看板

客户看板不是复杂 CRM，也不是 BI 报表。

一期定义为：

```text
告诉中介今天来了哪些客户、看了什么、谁需要跟进。
```

客户看板默认第一屏必须围绕“处理客户”，而不是围绕“展示页效果”。

## 3. 首页四个指标

房源首页“今日待处理”建议改名为：

```text
今日概览
```

副标题建议：

```text
房源、浏览和客户反馈一眼看清
```

如果仍保留“今日待处理”，第四项必须改成“待跟进”，否则前三项只是数据，第四项才是待处理，语义会混乱。

### 3.1 推荐四指标

| 位置 | 显示文案 | 用户理解 | 统计口径 | 点击去向 |
| --- | --- | --- | --- | --- |
| 1 | 房源 | 我现在整理了多少套房源 | 当前用户有效房源资料数量 | 资料页，只看房源 |
| 2 | 打开 | 我的房源被打开了多少次 | 房源详情页真实打开次数，含单房源分享打开、推荐包内点进房源 | 客户看板-房源效果 |
| 3 | 访客 | 有多少人看过我的房源 | 去重后的房源访客数，匿名只计数 | 客户看板-最近访客 |
| 4 | 待跟进 | 有多少客户需要我处理 | 留电话、留微信、预约看房、留言咨询、高意向未处理客户 | 客户看板-待跟进 |

不建议继续用“客户”作为第四项。因为“客户 0”不够明确，用户不知道是客户总数、访客数、留资数还是待联系数。

### 3.2 空态文案

当四个数字为 0 时，页面不要只显示 0，应该配合快捷入口解释下一步。

建议空态：

```text
还没有客户动态。先新建房源，或把房源推荐包发给客户试试。
```

如果已有房源但没有客户：

```text
房源已整理好，发给客户后这里会显示打开、访客和待跟进。
```

## 4. 四指标点击实现

首页四个指标必须可点击。用户点击数字时，页面要回答他自然会问的问题。

### 4.1 房源

点击后去：

```text
pages/library/index?mode=property&cardType=property_listing
```

目标：

- 只展示房源资料。
- 顶部筛选选中“房源”。
- 支持列表 / 双列两种展示，避免 iPad 上只显示半张卡。
- 如果当前页还不支持参数，开发需补参数读取。

用户问题：

```text
我有哪些房源？
```

### 4.2 打开

点击后去：

```text
pages/business-dashboard/index?mode=property&tab=propertyEffect
```

目标：

- 展示房源效果排行。
- 按打开次数排序。
- 每行显示：房源标题、小区/区域、打开、访客、待跟进。
- 每行可点“看客户”，进入该房源客户动作页。

用户问题：

```text
哪套房源被看得最多？
```

### 4.3 访客

点击后去：

```text
pages/business-dashboard/index?mode=property&tab=visitors
```

目标：

- 展示最近访客。
- 优先按最近时间排序。
- 匿名访客只显示“匿名访客”，不伪造成实名客户。
- 已留电话、微信、预约的人升级显示为可跟进客户。

用户问题：

```text
谁来看过我的房源？
```

### 4.4 待跟进

点击后去：

```text
pages/business-dashboard/index?mode=property&tab=followup
```

目标：

- 默认展示待跟进客户。
- 只显示还没有处理完成的客户动作。
- 支持一键拨号、复制微信、标记已联系、写备注。
- 这里是客户看板默认 Tab。

用户问题：

```text
我现在该联系谁？
```

## 5. 客户看板页面设计

页面标题建议：

```text
客户看板
```

房源模式下也可以显示：

```text
房源客户看板
```

顶部不要叫 SCRM。

### 5.1 Tab 结构

一期建议 4 个 Tab：

| Tab | 默认顺序 | 作用 |
| --- | --- | --- |
| 待跟进 | 1 | 今天最该处理的客户 |
| 最近访客 | 2 | 最近谁看了房源 |
| 房源效果 | 3 | 哪套房源被看、被咨询 |
| 推荐包效果 | 4 | 多套房源推荐包的打开和点击 |

默认进入：

```text
待跟进
```

不建议默认进入“展示页效果”，否则用户会感觉这是数据后台，而不是客户处理台。

### 5.2 顶部摘要

客户看板顶部保留 4 个小指标，但要和“处理客户”相关：

| 显示文案 | 含义 |
| --- | --- |
| 待跟进 | 未处理的客户动作数 |
| 新访客 | 今日新增访客数 |
| 预约 | 今日或待处理预约数 |
| 热门房源 | 当前打开最多的房源数量或第一套热门房源入口 |

如果开发成本要低，可以沿用首页四指标，但默认 Tab 仍为“待跟进”。

## 6. 待跟进 Tab

这是客户看板的核心。

### 6.1 展示规则

优先展示：

1. 留电话 / 留微信的客户。
2. 预约看房的客户。
3. 留言咨询的客户。
4. 多次查看同一房源但还没处理的访客。

排序建议：

```text
未处理 > 今天新增 > 有联系方式 > 有预约 > 最近发生
```

### 6.2 客户卡片字段

每张客户卡建议显示：

- 客户昵称或姓名。
- 头像，没有头像时用文字兜底。
- 来源：来自哪套房源或哪个推荐包。
- 动作：看了房源、留了电话、复制微信、预约看房、留言咨询。
- 时间：刚刚 / 15分钟前 / 今天 14:30。
- 联系方式：电话、微信，有则显示；没有则不占位。

主按钮：

- 拨号。
- 复制微信。
- 已联系。
- 备注。

没有联系方式时，不要硬放“拨号”。可以显示：

```text
查看轨迹
```

### 6.3 空态

```text
暂无待跟进客户。
房源发出后，客户留电话、预约或咨询会出现在这里。
```

## 7. 最近访客 Tab

### 7.1 展示规则

最近访客用于回答：

```text
最近谁看了我的房源？
```

展示内容：

- 访客身份：实名客户 / 匿名访客。
- 最近查看的房源。
- 查看次数。
- 最近查看时间。
- 是否已有联系方式。
- 是否已转为待跟进。

### 7.2 操作

可选操作：

- 查看轨迹。
- 看过的房源。
- 转待跟进。

如果是匿名访客，只能展示事实，不显示假头像、假姓名、假电话。

## 8. 房源效果 Tab

### 8.1 展示规则

房源效果用于回答：

```text
哪套房源更吸引客户？
```

每行显示：

- 房源标题。
- 小区 / 区域 / 价格。
- 打开次数。
- 访客数。
- 待跟进数。
- 最近客户动作时间。

主按钮：

```text
看客户
```

点击后筛选该房源相关客户动作和访客。

### 8.2 和首页“打开”的关系

首页“打开”点击进入本 Tab，并按打开次数排序。

## 9. 推荐包效果 Tab

推荐包效果承接原展示页逻辑。

这里的“推荐包”就是原展示页：

```text
多套房源一起发给客户的页面。
```

### 9.1 展示内容

每个推荐包显示：

- 推荐包名称。
- 包含几套房源。
- 打开次数。
- 访客数。
- 点进房源次数。
- 咨询 / 留资 / 预约数量。
- 最近打开时间。

主按钮：

- 看效果。
- 看客户。
- 继续分享。

### 9.2 命名建议

在房源场景里，不建议只叫“展示页效果”。可以叫：

```text
推荐包效果
```

副标题：

```text
多套房源一起发给客户后的打开和点击。
```

这样既保留原来的展示页能力，又不会和客户看板的主任务混淆。

## 10. 首页快捷入口补充

房源工作台快捷入口建议保持 4 个：

| 入口 | 功能 |
| --- | --- |
| 新建房源 | 粘贴房源文案，进入房源资料编辑 |
| 记需求 | 记录客户预算、区域、户型、看房时间 |
| 房源合集 | 创建多套房源推荐包 |
| 我的名片 | 发给客户认识我 |

其中“房源合集”前台可逐步改成“推荐包”，但如果当前 Tab 已叫“合集”，也可以继续保留“房源合集”。

## 11. 一期开发清单

### 11.1 首页四指标

- 将房源模式第四项从“客户”改为“待跟进”。
- 将“今日待处理”改为“今日概览”，或补充更明确副标题。
- 四指标全部支持点击。
- 点击后带 `mode=property` 和对应 `tab` 参数进入目标页。
- 0 数据时显示引导文案，不只显示 0。

### 11.2 客户看板

- `pages/business-dashboard/index` 支持 `mode=property`。
- 支持 `tab=followup / visitors / propertyEffect / showcasePackage`。
- 房源模式默认进入 `followup`。
- UI 文案从“展示页效果优先”改为“客户处理优先”。
- 原“展示页效果”保留为“推荐包效果”Tab，不删除底层数据。
- 客户卡片支持拨号、复制微信、已联系、备注或跳转详情。

### 11.3 资料页

- 支持从首页“房源”点击进入后只看房源。
- 支持列表 / 双列切换或至少保证大屏不只显示半张卡。
- 房源卡片直接露出打开、访客、待跟进。

## 12. 验收标准

P0：

- 房源首页四个指标分别是房源、打开、访客、待跟进，用户不需要解释也能大致理解。
- 四个指标都能点击，且跳转后的页面回答对应问题。
- 客户看板默认展示待跟进客户，不默认进入展示页效果。
- 展示页 / 合集在房源场景里作为“多套房源推荐包”存在，不和客户看板混为一个概念。
- 匿名访客不被包装成实名客户。
- 发布者自己预览不计入客户打开。
- 有留资、预约、咨询时，首页和客户看板能第一时间提示。

P1：

- 房源效果按打开或最近客户动作排序。
- 推荐包效果能展示每个多房源推荐包的打开、访客、点进房源和咨询。
- 客户卡片能直接拨号、复制微信、标记已联系。
- 空态能引导用户发房源或创建推荐包。

P2：

- 客户跨房源合并画像。
- 高意向自动判断。
- 企业微信自动推送“来客户了”。
- 客户跟进自动提醒。
- 推荐包渠道归因和转化漏斗。

## 13. 不做事项

一期不做：

- 完整 CRM。
- 客户标签画像系统。
- 复杂漏斗图和 BI。
- 多员工团队管理。
- 成交金额和业绩报表。
- 企业微信主动推送自动化。
- AI 自动判断客户购买力或租房意向。

这些都可以后置。第一期必须先做到：

```text
看得懂、点得通、知道谁该跟进。
```
