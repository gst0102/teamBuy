# 企业资源搜索 V1（天眼查接入）

更新时间：2026-06-28

## 1. 背景

资源库当前已经规划了 `群资源库`，用于找渠道、找群和做群资源交换。下一步适合增加第二类资源：

> 企业资源搜索

核心目的不是把天眼查 162 个工具全部暴露给用户，而是把它收成一个“资源库里的企业查询入口”，帮助用户：

- 找目标企业。
- 看企业基本情况。
- 判断风险。
- 判断是否值得联系。
- 保存成自己的企业资源卡。

这非常适合房源、团购、服务/商机、资料四个工作台的长线资源沉淀。

## 2. 产品定位

功能名称建议：

- 前台入口：`企业资源搜索`

一句话定位：

> 搜企业、看风险、存资源。

与群资源库的关系：

- 群资源库：找渠道。
- 企业资源搜索：找客户、找合作方、找目标商家。

未来资源库结构建议：

- 群资源库
- 企业资源搜索
- 我的资源

## 3. 当前接入结论

用户已提供信息：

- 官方 MCP 服务地址：`https://mcp.tianyancha.com/v1`
- 申请入口：`https://ai.tianyancha.com`
- 支持 WorkBuddy 等客户端接入
- 能力覆盖企业数据、司法、知产、经营、历史、董监高等大类

密钥管理原则：

- 用户已拿到 Tianyancha API Key。
- 完整 API Key 不写入仓库文档、不写入前端、不提交到 Git。
- 只记录在服务器环境变量或密钥文件中，例如：
  - `TIANYANCHA_API_KEY=...`
  - 或放入 `backend/secrets/` 下的独立密钥文件
- 后端启动时读取该密钥，并由后端代理调用 MCP。

当前策略：

- 不直接向用户暴露全部 162 个工具。
- 第一版只开放 6-8 个高频查询能力。
- API Key 只放后端，不放小程序前端。
- 结果必须做缓存和频控。

注意：

- 免费额度以用户申请后的账号页面实际展示为准，不要在产品里先写死每天 500 次。

## 4. 第一版用户价值

用户进入资源库，不只是找群，还可以：

- 搜一家企业。
- 看这家公司是不是还在经营。
- 看法人、注册资本、成立时间、地址、行业。
- 看有没有明显司法风险。
- 看股东结构和历史变更。
- 保存成自己的企业资源卡，后续跟进。

### 5.1 做

- 自动爬取或批量采集
- 企业资源充值体系

## 7. 第一版开放的查询功能

推荐 6 个高频入口：

1. 基本信息
2. 股东结构
3. 司法风险
4. 经营情况
5. 历史变更
6. 知识产权

说明：

- `老板/法人` 相关信息可收在基本信息页里，不必单独做一个按钮。
- `联系方式/官网线索` 以天眼查实际可返回的公开字段为准，不单独承诺一定有手机号。

## 8. 积分建议

第一版推荐：

- 搜索企业候选：免费
- 基本信息：10 分
- 股东结构：20 分
- 司法风险：20 分
- 经营情况：20 分
- 历史变更：20 分
- 知识产权：20 分
- 保存企业资源卡：免费或后续 10 分，第一版建议免费

原则：

- 搜索不收费，否则用户会觉得门槛太高。
- 基本信息做低门槛，让用户先看到价值。
- 深度查询按功能扣积分。

## 9. 缓存与频控

### 9.1 缓存

必须做缓存。

建议规则：

- 同企业同查询功能 24 小时内优先走缓存。
- 同一用户短时间重复点同一功能，不重复扣积分。
- 平台内部也应有缓存，避免浪费总额度。

### 9.2 频控

建议规则：

- 单用户每日查询次数上限。
- 单功能每日调用上限。
- 单用户短时间重复查询同企业时限流。

目的：

- 保护免费额度。
- 防止恶意刷查询。

## 10. 保存企业资源卡

“保存企业资源卡”是本产品自己的能力，不是天眼查原生功能。

逻辑：

- 天眼查负责返回原始公开数据。
- 后端负责清洗、结构化和字段裁剪。
- 小程序负责展示成一张企业资源卡。

第一版企业资源卡字段建议：

- 企业名称
- 经营状态
- 法人
- 成立时间
- 注册资本
- 所属行业
- 所在城市
- 地址
- 官网/公开线索（有则展示）
- 风险提示摘要
- 查询时间
- 数据来源：天眼查公开信息

按钮：

- `保存到我的资源`
- `生成企业摘要卡（后续）`

第一版更建议直接用“保存到我的资源”，不要把“导出”做太早。

## 12. MCP 接入实现建议

后端接入原则：

- 只在后端配置 Tianyancha API Key
- 小程序前端调用自己的后端接口
- 后端代理调用 MCP
- 后端负责积分扣减、缓存、频控、日志记录

服务器配置建议：

```text
TIANYANCHA_MCP_URL=https://mcp.tianyancha.com/v1
TIANYANCHA_API_KEY=你的真实 key
```

后端使用方式：

- 服务端请求头带 `Authorization: <TIANYANCHA_API_KEY>`
- 不在任何前台接口中回传完整 key
- 日志中也不要打印完整 key

建议能力拆分：

- `/api/resources/enterprise/search`
- `/api/resources/enterprise/{id}/basic`
- `/api/resources/enterprise/{id}/shareholders`
- `/api/resources/enterprise/{id}/risk`
- `/api/resources/enterprise/{id}/operations`
- `/api/resources/enterprise/{id}/history`
- `/api/resources/enterprise/{id}/ip`
- `/api/resources/enterprise/{id}/save`

注意：

- 不要把 API Key 写进前端、小程序配置或 Git。
- 查询前先判断积分是否足够。
- 若命中缓存，避免重复扣分。

## 13. 开发交接建议

优先级建议：

1. 先接后端 MCP 验证基本查询通路。
2. 做搜索候选和企业卡页。
3. 开基本信息、司法风险、历史变更 3 个最常用功能。
4. 再补股东结构、经营情况、知识产权。
5. 做缓存和积分扣减。
6. 做保存企业资源卡。

## 14. 验收标准

P0：

- 用户能从资源库进入企业资源搜索。
- 用户能搜索企业名称或统一信用代码。
- 搜索结果能展示候选企业。
- 用户能查看企业基本信息。
- 用户能查看至少 3 个深度查询功能。
- 查询前能校验积分是否足够。
- 同企业同功能 24 小时内优先走缓存。
- 企业查询结果能保存到我的资源。
- API Key 不暴露在前端。

P1：

- 开放 6 个高频查询功能。
- 保存企业资源卡支持标签和自定义标签。
- 企业卡能展示公开风险提示摘要。
- 首页资源库入口展示企业查询已开通状态。

P2：

- 企业摘要卡分享。
- 企业资源导出。
- 企业资源更复杂筛选。
- 与客户雷达、商机工作台更深联动。
