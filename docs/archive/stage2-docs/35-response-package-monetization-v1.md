# 回应包与双向收费产品方案 V1

更新时间：2026-06-30

## 1. 核心定位

回应包不是普通 AI 文案，也不是单纯把联系方式展示给用户。

它的定位是：

> 当用户看到一个适合自己的需求或商机时，系统从用户已有资料里挑出最适合回应对方的内容，组合成一份可发送、可追踪、可跟进的成交资料包。

一句话：

```text
把“我看到了机会”变成“我知道该拿什么去联系对方”。
```

## 2. 回应包解决什么问题

没有回应包时，用户看到需求后的真实卡点是：

```text
这个机会不错
  ↓
我该怎么说？
  ↓
我该发什么资料？
  ↓
发过去对方看没看？
  ↓
什么时候二次跟进？
```

回应包要解决的是：

```text
选资料
写开场
发链接
追反馈
```

这也是区别于普通需求广场、黄页、微信群资源的核心竞争力。

## 3. 使用场景

### 3.1 供给方回应需求

这是第一优先级。

示例：

```text
需求：长沙商家找本地推广渠道
用户：本地推广服务商
系统推荐：
  - 长沙本地推广服务介绍页
  - 电子名片
  - 过往案例合集
  - 首次私信话术
  - 二次跟进提醒
```

### 3.2 需求方查看供给

需求方看到供给卡后，可以：

```text
查看资料
保存供给
申请联系
要求对方发送回应包
```

第一版不建议让系统自动替供给方发回应包，避免误发和骚扰。

### 3.3 用户在资源库中提前优化资料

即使没有具体需求，系统也可以提示用户：

```text
这份资料适合回应：
  - 本地商家找推广
  - 装修客户找服务商
  - 企业找供应商
```

但真正生成回应包，建议发生在用户选择了具体需求之后。

## 4. 回应包组成

第一版回应包建议由 5 个部分组成。

### 4.1 对方需求摘要

结构化展示：

```text
对方要什么
城市
行业
联系方式状态
有效期
可信状态
```

### 4.2 系统推荐资料

从用户自己的资料体系中选择：

```text
服务介绍页
房源合集
商品合集
案例合集
电子名片
企业资源卡
日常资料卡
```

每个资料展示推荐理由：

```text
城市匹配
行业匹配
服务匹配
有案例
适合首次发送
```

### 4.3 首次联系话术

系统生成一段可复制的短话术。

原则：

- 短
- 像真人
- 不夸张
- 不硬广
- 能自然带出资料链接

示例：

```text
你好，我看到你在找长沙本地推广合作。我们这边主要做本地商家获客和社群推广，我整理了一份服务介绍和案例，可以先给你参考。
```

### 4.4 可追踪资料链接

回应包发出去后，需要记录：

```text
是否打开
打开时间
打开次数
是否点击联系方式
是否保存
是否转发
```

第一版可先做打开、点击联系方式、保存三类行为。

### 4.5 跟进建议

系统根据反馈给下一步建议：

```text
对方未打开：24 小时后换短话术再提醒
对方已打开未联系：补发案例或报价入口
对方点击联系方式：标记高意向
对方保存资料：建议当天跟进
```

## 5. 关键流程

### 5.1 从线索详情生成回应包

```text
打开线索详情
  ↓
点击生成回应包
  ↓
系统推荐资料
  ↓
用户确认 / 替换资料
  ↓
生成回应话术和追踪链接
  ↓
用户复制发送或通过微信客服发送
  ↓
雷达跟踪反馈
```

### 5.2 从供需广场生成回应包

```text
看到一条需求卡
  ↓
查看详情
  ↓
生成回应包
  ↓
选择自己的供给资料
  ↓
发送给需求方
```

### 5.3 从我的机会生成回应包

```text
系统推送高匹配机会
  ↓
用户打开我的机会
  ↓
一键生成回应包
  ↓
进入跟进台
```

## 6. 权限与收费策略

第一版建议采用“免费尝到价值，再逐步收费”。

### 6.1 免费额度

建议：

```text
新用户：免费生成 5 次回应包
普通用户：每月免费 3 次回应包
```

免费回应包包含：

```text
推荐 1-2 个资料
生成首次联系话术
生成普通追踪链接
基础打开提醒
```

### 6.2 积分消耗

超过免费额度后，可用积分消耗。

建议：

```text
生成普通回应包：20 分
生成增强回应包：30 分
查看高级跟进建议：10 分
刷新推荐资料：5 分
```

增强回应包可包含：

```text
多资料组合
案例优先推荐
二次跟进话术
更完整雷达反馈
```

### 6.3 会员权益

会员可以包含：

```text
每月更多回应包额度
更多供给卡发布数量
更高推荐优先级
查看谁保存 / 谁点击联系方式
更长雷达追踪周期
高级跟进建议
```

### 6.4 双向收费

双向收费不是第一天就强推，而是后续可打开。

需求方可收费点：

```text
发布高优先级需求
让需求置顶
只接收认证供给方回应
查看更多供给方资料
```

供给方可收费点：

```text
生成更多回应包
查看联系方式
优先推荐给需求方
发布更多供给卡
查看雷达反馈
开通保证金认证
```

前期更建议主要收供给方，因为供给方有更强的成交动机。

## 7. 保证金机制

保证金不是“平台担保成交”，而是“服务可信认证”。

前台表达建议：

```text
已缴保证金
平台认证供给方
优先响应
```

避免表达：

```text
平台保证成交
平台担保效果
100% 可靠
```

### 7.1 适合保证金的供给类型

优先适合：

```text
装修服务
本地推广
房产中介
招聘服务
供应链合作
企业服务
渠道招商
```

不建议第一版覆盖所有类目。

### 7.2 保证金权益

保证金用户可获得：

```text
认证标识
供给卡更高可信展示
回应包里展示认证状态
需求方筛选“只看认证供给方”
争议处理优先通道
```

### 7.3 扣罚规则

保证金扣罚必须谨慎，不能只靠单次举报。

建议分级：

| 情况 | 处理 |
|---|---|
| 信息过期但无恶意 | 提醒修改，不扣 |
| 联系方式无效 | 降权，要求补正 |
| 多人举报无法联系 | 暂停展示，人工复核 |
| 虚假身份 / 虚假服务 | 下架供给，扣积分，视情况扣保证金 |
| 恶意骚扰 / 诈骗风险 | 封禁，扣保证金，保留证据 |

### 7.4 保证金退还

必须提供明确规则：

```text
无未处理投诉
无进行中争议
无未完成承诺服务
申请后人工审核
审核通过后退还
```

## 8. 页面设计建议

### 8.1 线索详情页

主按钮从：

```text
生成回应资料
```

升级为：

```text
生成回应包
```

副文案：

```text
系统会从你的资料里挑选最适合发给对方的内容。
```

### 8.2 回应包生成页

页面结构：

```text
对方需求
推荐资料
推荐话术
保证金 / 认证状态
生成追踪链接
```

主按钮：

```text
复制回应内容
```

次按钮：

```text
替换资料
保存到跟进
```

### 8.3 回应包雷达页

展示：

```text
已发送
对方已打开
点击联系方式
建议跟进
下次提醒
```

### 8.4 我的资料页

资料卡可新增“可回应场景”。

示例：

```text
适合回应：
长沙商家找推广
本地门店获客
开业活动引流
```

这样用户不是被动整理资料，而是在为未来成交做准备。

## 10. 第一版范围建议

P0 必须做：

- 线索详情可生成回应包。
- 从用户已有资料里选择 1-3 个资料。
- 可生成首次联系话术。
- 可生成可追踪链接。
- 已保存线索里能看到是否已生成回应包。
- 免费额度和积分消耗有记录。

P1 再做：

- 回应包打开提醒。
- 二次跟进话术。
- 谁点击联系方式。
- 会员额度。
- 供给卡优先推荐。

P2 后续做：

- 保证金认证。
- 争议处理。
- 需求方高级发布。
- 双向收费。
- 类目保证金标准。

## 11. 风险与边界

### 11.1 不自动骚扰

系统只能生成回应包，不应自动大量私信或自动联系需求方。

必须由用户确认后发送。

### 11.2 不承诺成交

回应包提高成交准备度，但不承诺成交。

### 11.3 不泄露第三方来源

前台不突出第三方平台来源，后台保留来源用于合规和追溯。

### 11.4 不把保证金做成平台担保

保证金用于服务可信和违规约束，不代表平台对交易结果兜底。

## 12. 最推荐的上线节奏

```text
第一步：免费回应包
第二步：积分消耗
第三步：会员额度
第四步：供给卡曝光付费
第五步：保证金认证
第六步：双向收费
```

这样先让用户感受到“这个工具能帮我把机会变成行动”，再让用户为节省时间、提高成交概率付费。
