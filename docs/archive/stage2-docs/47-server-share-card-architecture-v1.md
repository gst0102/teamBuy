# 后端分享卡片生成方案 v1

## 目标

普通资料、电子名片、图片资料、链接/文字资料，以及互帮互助的普通任务、小程序任务和羊毛福利，统一由后端依据服务端真实数据生成固定尺寸的分享快照。小程序只读取快照 URL，并把 URL 交给微信原生分享。

## 不变的约束

- 分享图固定为 750×600，保证不同手机分辨率下比例稳定。
- 快照绑定实体版本、指纹和模板版本；内容变化后旧图不能继续作为当前图。
- 新图生成、存储或保存失败时，继续保留旧的当前图，不能回退到头像、默认图或页面截图。
- 图片媒体只从本系统已登记的媒体地址读取，禁止渲染器访问任意外部地址。
- 电子名片使用专属名片版式，头像只作为圆形头像使用，不再铺满整张名片图。
- 任务结束、暂停、删除或剩余次数为 0 时不生成新的可分享快照。

## 请求链路

1. 发布者打开分享入口，小程序先检查当前版本的快照。
2. 当前快照不可复用时，请求后端 prepare 接口。
3. 后端重新读取数据库中的资料/任务和已登记媒体，生成 JPG，按媒体哈希去重并登记引用。
4. 后端在实体上原子更新当前快照及历史版本，返回带快照的实体。
5. 小程序只使用返回的 `imageUrl` 和目标详情页 `path` 调用原生分享。

任务详情的快照准备接口为公开 GET，因为公开任务允许未登录用户查看和转发；接口只读取可公开任务字段，不接受客户端传入的内容作为渲染源。

## 当前范围

- 本轮迁移：UserNote 分享卡、MutualHelpTask 分享卡。
- 暂不迁移：合集、商机市场、响应包等仍使用独立编辑流程的分享卡；它们继续沿用现有 Canvas 快照接口，后续可复用同一渲染器抽象。
