# 2026-06-08 teamBuy 本地构建与拉镜像部署方案

## 1. 目标

teamBuy 当前处于阶段二文档完成、阶段三尚未开始实现的状态。前期以本地开发和本地测试为主，暂不要求提供小程序 AppID、企业微信客服密钥、服务器地址和线上对象存储配置。

本方案目标是提前定义一套可复用的构建和部署流程：

1. 本地优先完成 FastAPI 后端和原生微信小程序开发。
2. 后端服务使用 Docker 镜像承载，便于后续迁移到测试机或生产机。
3. 镜像使用明确版本 tag，避免部署时不知道运行的是哪次提交。
4. 未来服务器准备好后，目标机器只执行拉镜像和 `docker compose up -d --no-build`。
5. 小程序端仍通过微信开发者工具本地调试，不进入 Docker 镜像。

## 3. 适用边界

本方案覆盖：

- 本地后端 Docker 构建
- 本地 `docker compose` 启动
- mock 环境变量
- mock 企业微信消息
- mock 小程序登录
- mock 对象存储
- 镜像 tag 规范
- 未来测试机/生产机拉镜像部署流程

本方案暂不覆盖：

- 小程序上传审核
- 企业微信真实回调配置
- 小程序 AppID 真实接入
- 真实服务器域名和 HTTPS 证书
- 真实对象存储密钥
- 大模型真实 API Key
- 线上数据库高可用

## 4. 推荐架构

### 4.1 本地开发职责

本地开发环境负责：

- 启动 FastAPI 后端
- 启动数据库
- 使用 mock 企业微信消息验证导入聚合
- 使用 mock 小程序登录验证认领、卡片、浏览、接龙
- 使用微信开发者工具打开 `miniprogram/`
- 后端镜像本地构建和冒烟测试

### 4.2 构建机职责

当前阶段构建机可以是开发者本机。

后续如果服务器构建慢，再切换为独立构建机。构建机职责：

- 拉取指定 Git 提交
- 构建后端镜像
- 打版本 tag
- 可选推送到镜像仓库
- 可选执行镜像自检

### 4.3 目标机职责

目标机是后续测试服务器或生产服务器。

目标机只负责：

- 拉取明确 tag 的后端镜像
- 拉取或同步 `docker-compose.yml`
- 配置 `.env`
- 执行 `docker compose up -d --no-build`
- 执行健康检查和功能冒烟

目标机不应在发布阶段执行后端镜像构建。

## 7. 本地 Docker 构建流程

### 7.0 Docker 加速要求

阶段三生成 `backend/Dockerfile` 和 `docker-compose.yml` 时，Python 依赖安装必须支持清华源加速。

推荐默认源：

```text
https://pypi.tuna.tsinghua.edu.cn/simple
```

Dockerfile 建议支持：

```dockerfile
ARG PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
RUN pip install --no-cache-dir -i "$PIP_INDEX_URL" -r requirements.txt
```

如果使用 `docker compose build`，应允许通过环境变量覆盖：

```text
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

### 7.1 设置镜像变量

```bash
export GIT_SHA=$(git rev-parse --short HEAD)
export APP_VERSION=v0.1-$GIT_SHA
export APP_IMAGE=teambuy-backend:$APP_VERSION
export BUILD_DATE=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
export PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

Windows PowerShell：

```powershell
$env:GIT_SHA = git rev-parse --short HEAD
$env:APP_VERSION = "v0.1-$env:GIT_SHA"
$env:APP_IMAGE = "teambuy-backend:$env:APP_VERSION"
$env:BUILD_DATE = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
$env:PIP_INDEX_URL = "https://pypi.tuna.tsinghua.edu.cn/simple"
```

### 7.2 构建后端镜像

阶段三实现 `backend/Dockerfile` 后执行：

```bash
docker build `
  --build-arg APP_VERSION=$APP_VERSION `
  --build-arg VCS_REF=$GIT_SHA `
  --build-arg BUILD_DATE=$BUILD_DATE `
  --build-arg PIP_INDEX_URL=$PIP_INDEX_URL `
  -t $APP_IMAGE `
  ./backend
```

PowerShell 推荐写法：

```powershell
docker build `
  --build-arg APP_VERSION=$env:APP_VERSION `
  --build-arg VCS_REF=$env:GIT_SHA `
  --build-arg BUILD_DATE=$env:BUILD_DATE `
  --build-arg PIP_INDEX_URL=$env:PIP_INDEX_URL `
  -t $env:APP_IMAGE `
  ./backend
```

### 7.3 本地镜像核对

```bash
docker images | grep teambuy-backend
docker image inspect "$APP_IMAGE"
```

PowerShell：

```powershell
docker images teambuy-backend
docker image inspect $env:APP_IMAGE
```

重点确认：

- 镜像 tag 包含当前 Git short sha。
- 镜像能启动 FastAPI。
- 镜像构建日志中 Python 依赖安装使用清华源或可配置源。
- 镜像不包含 `.env` 和真实密钥。

### 7.4 本地 Docker 冒烟

```bash
docker run --rm -p 18000:8000 --env-file .env "$APP_IMAGE"
curl http://127.0.0.1:18000/health
```

PowerShell：

```powershell
docker run --rm -p 18000:8000 --env-file .env $env:APP_IMAGE
```

另开一个终端：

```powershell
curl http://127.0.0.1:18000/health
```

## 8. docker compose 本地方案

阶段三建议提供 `docker-compose.yml`，至少包含：

- `backend`
- `db`，如果使用 PostgreSQL
- 可选 `redis`，如果后续需要异步任务队列

本地启动：

```bash
docker compose up -d
docker compose ps
curl http://127.0.0.1:8000/health
```

本地停止：

```bash
docker compose down
```

注意：不得使用批量删除命令清理项目文件。

## 10. 目标机拉镜像部署流程

服务器信息当前暂不需要。后续拿到服务器后按以下模板执行。

### 10.1 登录目标机

```bash
ssh <user>@<server-ip>
cd /opt/teambuy
```

### 10.2 更新部署文件

```bash
git fetch origin
git checkout main
git pull --ff-only origin main
git rev-parse --short HEAD
```

### 10.3 设置镜像变量

```bash
export APP_VERSION=v0.1-<short-sha>
export APP_IMAGE=<registry>/teambuy-backend:$APP_VERSION
```

### 10.4 只拉镜像，不本地构建

```bash
docker pull "$APP_IMAGE"
docker compose up -d --no-build backend
```

### 10.5 发布后检查

```bash
docker compose ps
curl http://127.0.0.1:8000/health
docker compose logs --tail=100 backend
```

如果后续有数据库迁移：

```bash
docker compose exec -T backend alembic upgrade head
docker compose exec -T backend alembic current
```

## 11. mock 验收流程

本地开发阶段不依赖真实 AppID 和服务器，至少要通过以下 mock 验收：

1. mock 企业微信回调可以触发导入。
2. mock `sync_msg` 可以返回文本、图片、链接消息。
3. 60 秒窗口聚合规则可以生成导入批次。
4. 规则解析可以生成卡片草稿。
5. 用户可以 mock 登录并认领导入。
6. 卡片可以编辑、保存、查看。
7. 浏览记录可以区分登录用户和匿名用户。
8. 登录用户可以提交接龙。
9. 团长可以查看名单、删除无效接龙、标记已跟进。
10. 一键复用生成新卡片，且不污染原卡片数据。

## 12. 验收标准

本地构建和拉镜像方案满足以下条件才算通过：

- [ ] 后端可以本地直接运行。
- [ ] 后端可以构建 Docker 镜像。
- [ ] Docker 构建 Python 依赖时默认使用清华源或支持 `PIP_INDEX_URL` 覆盖。
- [ ] 镜像 tag 包含 Git short sha。
- [ ] 镜像可以通过 `/health` 健康检查。
- [ ] `docker compose up -d` 可以启动后端服务。
- [ ] mock 导入链路可以跑通。
- [ ] mock 浏览统计和接龙可以跑通。
- [ ] 镜像构建不需要小程序 AppID。
- [ ] 镜像构建不需要企业微信真实密钥。
- [ ] 镜像构建不需要服务器地址。
- [ ] Git 仓库不包含真实 `.env`、密钥、Token、AppSecret。

## 13. 回滚方案

如果新镜像异常，目标机回滚到上一个稳定 tag：

```bash
export APP_IMAGE=<registry>/teambuy-backend:<previous-stable-tag>
docker compose up -d --no-build backend
curl http://127.0.0.1:8000/health
```

如果代码基线也需要回退：

```bash
git checkout <previous-stable-commit>
```

回滚后必须检查：

- `/health`
- mock 或真实导入链路
- 卡片查看
- 浏览统计
- 接龙

## 14. 阶段三开发要求

阶段三实现代码时，必须同步补齐：

- `backend/Dockerfile`
- `docker-compose.yml`
- `.env.example`
- `backend/README.md`
- 后端 `/health` 接口
- mock 企业微信消息数据
- mock 登录数据
- 基础测试命令

不要把真实 AppID、企业微信密钥、对象存储密钥、大模型 Key 写入仓库。

## 15. 推荐发布节奏

当前阶段推荐节奏：

```text
本地开发 -> 本地 mock 测试 -> 本地 Docker 构建 -> 本地 Docker 冒烟 -> 提交 Git -> 等服务器信息 -> 推镜像仓库 -> 目标机拉镜像部署
```

后续服务器和 AppID 准备好后，再补充正式环境变量、域名、HTTPS、企业微信回调 URL、小程序后台服务器域名配置。
