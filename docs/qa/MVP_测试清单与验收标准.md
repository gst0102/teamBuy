# MVP 测试清单与验收标准

## 1. 功能核心目标

验证 teamBuy v0.1 是否跑通完整闭环：

用户通过企业微信客服导入微信笔记或链接，系统聚合解析生成可编辑卡片；用户在小程序中认领、编辑、保存并分享到微信群；群用户可以查看、拨号、复制字段、实名接龙；发起人可以查看浏览统计、接龙名单，并一键复用历史卡片。

## 2. 测试范围

本测试清单覆盖：

- 企业微信客服回调与 `sync_msg`
- 微信笔记消息聚合
- 媒体下载和转存
- 卡片草稿生成
- 待认领导入
- 小程序登录
- 卡片编辑、保存、分享、查看
- 电话拨号和字段复制
- 浏览 PV/UV 与用户列表
- 实名接龙和名单管理
- 素材库搜索、分类、一键复用
- 数据隔离、安全合规、异常处理

不覆盖：

- 支付、订单、收款、分账
- 库存、核销
- 匿名接龙
- 多角色团队权限
- 复杂 CRM
- 商业化订阅和返佣

## 3. P0/P1/P2 风险清单

| 风险 | 优先级 | 验收要求 |
|---|---|---|
| 企业微信回调无法接收 | P0 | 回调 GET/POST 都必须可验证 |
| `sync_msg` 无法拉取消息 | P0 | mock 与真实接口封装都必须可测试 |
| 微信笔记无法生成卡片草稿 | P0 | 文本、图片至少能形成可编辑卡片 |
| media_id 未及时转存 | P0 | 媒体必须转为可持久访问 URL 或明确失败 |
| 导入成功但用户无法认领 | P0 | 待认领记录必须可被登录用户绑定 |
| 导入失败但没有通知 | P0 | 成功和失败都必须回发企业微信客服消息 |
| 匿名用户被展示为实名用户 | P0 | 匿名只能计入总量，不能进入用户列表 |
| 普通用户看到未脱敏昵称 | P0 | 普通用户只看到脱敏昵称 |
| 一键复用覆盖原卡片数据 | P0 | 新旧卡片浏览和接龙数据必须隔离 |
| 链接深度解析不稳定 | P1 | 不影响保存来源链接和基础标题候选 |
| 大模型不可用 | P1 | 规则解析仍可生成草稿 |
| 素材库分类搜索不完整 | P1 | 不影响卡片保存、查看、复用主链路 |
| 导出接龙名单缺失 | P2 | v0.1 不要求实现 |

## 5. 开发完成后的验收标准

- [ ] TC-001 至 TC-040 均有测试记录。
- [ ] 所有 P0 测试项通过，或明确列出阻断 Bug。
- [ ] 企业微信真实接入前，mock 链路必须完整跑通。
- [ ] 真实接入后，企业微信回调、`sync_msg`、媒体下载必须重新验收。
- [ ] 浏览统计必须区分登录用户和匿名用户。
- [ ] 接龙必须登录，不允许匿名提交。
- [ ] 普通用户昵称展示必须脱敏。
- [ ] 一键复用不得污染原卡片数据。
- [ ] Git 仓库不得包含真实密钥。

## 6. 自动化测试建议

优先自动化：

- 消息聚合规则
- 规则解析生成卡片草稿
- 导入批次状态流转
- 认领状态流转
- 浏览 PV/UV 统计
- 登录浏览用户和匿名浏览隔离
- 接龙提交和必填校验
- 接龙删除和跟进状态
- 一键复用数据隔离

建议工具：

- 后端使用 `pytest`
- API 使用 FastAPI `TestClient`
- 小程序核心逻辑可抽到 service 层做单元测试
- 小程序页面交互用人工验收或小程序自动化工具补充
