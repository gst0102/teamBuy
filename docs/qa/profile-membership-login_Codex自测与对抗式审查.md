# 我的页会员门禁与微信身份回退：自测与对抗式审查

日期：2026-08-15（追加会员视觉、微信资料组件与名片直发）

## 修改范围

- 个人页将“会员”和“推广收益”放在同一客户信号门禁下；无客户信号时不渲染入口，也不请求推广中心。
- 设置区增加“隐私说明”入口；会员协议不作为个人页设置项展示，资料编辑仍保留必要的用户服务协议和隐私政策确认。
- 真实微信登录不再提交随机昵称；后端收到空/默认资料时保留已有昵称、头像、手机号和微信号。
- 清理资料预览、合集公开事件和 dashboard 工具层的随机昵称回退。
- 会员有效期显示改为“YYYY年M月D日”，个人页会员入口改用徽章 SVG。
- 登录页和个人资料弹窗改用 `chooseAvatar` / `type="nickname"`；登录后的临时头像先上传，再更新用户资料。
- 登录页删除“登录后保存到你的账号”大卡片，仅保留必要的头像/昵称、协议和登录操作。
- 登录页进一步恢复为纯一键登录；头像、昵称和联系方式只在“我的 → 个人资料”编辑。
- “同号”改为紧凑文本动作，使用 catchtap 和受控 profileDraft.wechat 回写。
- “我的”页名片入口改为动作优先：已发布名片显示原生“发名片”分享按钮；未创建或未完善名片进入编辑器。
- 个人页分享回调复用客户预览页、分享归因和默认封面，不再先跳编辑器再绕到资料库。

## 对抗式检查

- 旧页面/旧 DOM：个人页商业入口未恢复“已有客户信息”文案；旧 `sales-template-select` 路由仍未重新注册。
- 发布与发客户：本轮未修改发布状态或“发客户”接口，未将两者合并。
- 分享图：本轮未改变分享图兜底逻辑；预览页仍使用既有默认分享图链路。
- 客户敏感数据：个人页只读取客户智能摘要和信号预览来决定是否展示入口，不把客户身份或联系方式写入本地存储。
- 无客户信号推广：`membershipVisible` 仅由真实摘要/看板数组/信号预览推导；失败或 404 返回空对象时入口保持隐藏，且不调用推广中心。
- 五类编辑器：本轮未改动资源导航映射，未引入旧编辑器跳转。
- 底部双按钮：本轮未改动五类编辑器底部操作区。
- 名片发送状态：已发布名片只显示 `open-type="share"`；未发布/未完善名片不自动发布，仍进入编辑器。
- 分享归因：分享路径使用当前 `sourceNoteId`，并记录 `profile_business_card_share` 场景；封面为空时使用默认图。

## 未覆盖与风险

- 用户已购买会员但暂时没有客户信号时，个人页按当前规则隐藏会员入口；若未来需要订阅管理入口，应单独设计非推广的账号设置路径。

## 2026-08-15 追加：名片分享图与个人页读取性能复测

### 根因与修复

- 原个人页分享回调把普通卡片 `coverUrl` 当作名片封面，导致头像/通用资料图；现在通过 `generateBusinessCardShareImage` 生成完整电子名片图。
- 原 `fetchCards` 在列表返回前等待全部媒体本地缓存；现在个人页使用 `fetchCardsMetadata`，并采用进程内用户隔离缓存先展示、后台刷新，媒体不再阻塞首屏。

## 2026-08-15 追加：个人页速度、资料名片发送与样式对抗式复查

### 结论

代码层已完成三条链路的统一修复，后端回归通过；真实小程序速度、画布导出和微信分享面板仍需用户重新编译上传后确认。

### 高风险问题

- 已修复：个人页摘要缓存写入对象却按数组判断，导致每次进入都重新请求。
- 已修复：个人页使用全量资料列表的逐卡统计/客户摘要链路；现在使用轻量业务摘要接口。
- 已修复：资料库和资料列表名片仍使用旧 `structuredData`/头像封面分支；现在统一使用销售资料和名片专用画布，图未完成前不可分享。

### 中低风险问题

- 本地 `wxfile` 分享图依赖微信当前会话的临时文件生命周期；若平台在极端情况下清理过快，用户会看到重试状态，不会静默发送错误封面。
- 轻量摘要接口暂不计算 PV/转发总数；当前个人页没有渲染这两个统计数字，未来若恢复展示需增加独立聚合字段，不能重新接回全量列表接口。
