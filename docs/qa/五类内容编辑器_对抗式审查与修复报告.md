# 五类内容编辑器 对抗式审查与修复报告

日期：2026-08-13

## 审查结论

统一对抗式审查发现 4 个可确认风险，均已在本轮修复；剩余主要风险是尚未进行微信开发者工具/真机视觉验收，不属于代码静态检查可关闭的范围。

## 已确认发现与修复

### P0：旧附件缺少 ID 时，公开读取会生成随机 ID，导致跨次行为归因失效

- 证据：旧 `media` 条目没有 `id` 时，公开净化路径原先调用 `new_id()`。
- 影响：页面看到的附件 ID 每次变化，点击事件无法稳定归因，也削弱跨资料伪造校验的可追溯性。
- 修复：用 `type + url` 的 SHA-256 摘要生成稳定 `att_` ID；新增两次公开读取 ID 一致的回归断言。
- 状态：已修复并通过测试。

### P1：编辑器直接用 `wx.openDocument` 打开远程 PDF URL

- 证据：结构化编辑器预览逻辑把 HTTPS URL 直接作为 `filePath`。
- 影响：小程序要求先下载到本地临时路径，真机上会打不开。
- 修复：统一改为 `wx.downloadFile -> wx.openDocument`；链接改为复制 HTTPS URL。
- 状态：已修复，静态语法检查通过；真机网络域名白名单仍需人工确认。

### P1：名片公开页“同款”入口不在名片分支内

- 证据：通用同款卡只在非名片/非服务分支渲染。
- 影响：名片四样式虽然可编辑，但访客无法从名片公开页生成同款。
- 修复：在名片详情页增加显式“生成我的同款名片”，仍复用同一后端生成端点；名片克隆仅保留 `styleId`，清空身份、正文、图片和来源标识。
- 状态：已修复并通过同款回归测试。

### P0：公开配置和内部小程序快照的说明文本可能残留上游联系方式

- 证据：结构字段黑名单能移除 `upstreamPhone` 等键，但 `recognitionExplanation`、`rawText` 等普通字符串仍可能包含“上游电话：手机号”。
- 影响：公开 API、内部小程序再导入或生成同款时可能暴露房东/渠道联系方式。
- 修复：公开配置和内部小程序公开结构统一执行递归文本净化；删除含上游、房东、渠道、供应商、成本、佣金、密码等标记的行，并替换独立手机号。
- 状态：已修复；完整相关后端测试 175 项通过。

## 继续保留的合理边界

- 行为事件端点使用现有请求体身份字段，和项目现有浏览事件鉴权模型一致；若未来接入正式会话鉴权，应改为服务端会话身份，不信任客户端 `viewerUserId`。
- 外部 HTTPS 链接当前采用复制后打开的降级策略，因为小程序不支持任意网页直开；这是平台约束，不宣称等价于浏览器内嵌。
- 公共页中电话/微信会尊重 `conversionConfig`；个人销售资料仍保存在用户模型，不复制到笔记内容。
- 当前未做生产数据库迁移，也未部署，符合本轮边界。

## 追加对抗式审查：真机有数据态 UI（2026-08-13）

审查对象：资料/合集一级页、通用与结构化编辑器、新建资料识别卡、客户页旧数据兼容。

确认缺陷及修复：

- P1：原生 button 在网格/固定栏内保留固有宽度，资料卡、筛选底栏和编辑器底栏会在窄屏右溢。已补齐页面横向裁剪、网格 `minmax(0, ...)` 和按钮收缩约束。
- P1：结构化编辑器把所有空字段同时铺开，违背房源/商品渐进编辑决策。已拆分核心字段、更多公开字段和私密字段；旧值存在时自动展开。
- P1：旧稀疏资料通过兜底链重复显示标题/摘要/正文，并展示巨大空封面。已按标题去重，空封面不渲染。
- P1：拥有者预览自己的客户页仍显示客户动作和生成同款，造成不适用 DOM。已用已有 `ownerUserId` 与当前用户判断隐藏，不影响外部访客。
- P1：通用编辑器仍残留可拖动保存浮球，与已确认“无浮动保存按钮”冲突。已移除 WXML 实例，保留页面底部明确保存动作。
- P2：分享图异步未完成时显示“封面准备中”，把内部实现状态暴露为主按钮文案。已改成稳定业务动作“发客户”；实际分享仍使用生成后的封面，未就绪时允许微信默认降级。

未知与剩余风险：黑色“已连接/展开”和部分绿色调试控件来自微信真机调试层，不是小程序 DOM，代码无法移除；重新关闭真机调试浮层后再做截图验收。资料/合集有数据态和编辑器长内容态仍需重新编译后的真机截图确认。
