# 会话归档五步收口：Codex 自测报告

日期：2026-08-21

## 结论

本轮本地代码和自动化测试已收口，可以进入用户手动编译、上传体验版和真机验收。

本轮没有部署后端，也没有上传小程序。

## 已修复的根因

1. 会话存档专用分组原来按同一发送人、同一会话的相邻 5 秒合并，已改为以第一条消息为起点的固定 60 秒窗口。
2. 通用 `MessageAggregator` 原来按相邻消息滚动合并，已改为固定窗口，避免 0 秒、59 秒、118 秒仍被合并成一条资料。
3. 图片归档解析产生的“媒体稍后转存”提示不再作为用户正文；图片加短说明在没有高置信结构化场景信号时归为 `image_ocr`，图片是主体，说明文字保留在资料正文和结构化 `caption` 中。
4. 共享归档核心增加 teamBuy 私聊 / teamBuy 群 / PetLove 群 / PetLove 私聊的反向路由隔离测试。

## 用户真机验收矩阵

### 1. 归档聚合

- 发送图片，60 秒内发送短文字：资料库只能新增 1 条；图片必须出现在客户效果和正文主体区域，短文字保留为说明。
- 首条消息后第 61 秒再发送文字：必须新增第 2 条资料。
- 连续发送图片、文字、图片，全部在首条消息 60 秒内：必须是 1 条资料，媒体数量正确。
- 同一时间向另一个企业微信成员发送内容：不能合并到原资料。

### 2. 四类深编辑器

逐项打开并保存：房源、商品/团购、服务/合作、电子名片。检查标题、正文、图片、结构化字段、客户预览和发布状态。

### 3. 三种输入方式

逐项测试：

- 文字：新建普通资料并保存；
- 图片：新建图片资料，确认图片直接可见，OCR 仍由用户主动触发；
- 链接：新建文章/网页链接，确认标题、摘要、封面和原文链接保留。

### 4. 分享卡片

- 未准备好静态图时只能看到“准备分享图”，不能直接发客户；
- 静态图准备完成后才显示“发客户”；
- 分享卡片必须显示当前资料静态图，不能显示资料库页面截图；
- 编辑并重新发布后，分享图必须对应新版本；
- 生成失败时只能重试，不能发送空图或旧图。

### 5. 数据和缓存安全

- 退出登录、清空缓存、重新登录后，资料、合集、会员、消息和客户雷达不能串账号；
- 未登录进入首页、资料、合集、雷达、我的页面，不得显示旧账号数据；
- teamBuy 私聊不得出现在 PetLove 社区，PetLove 群聊不得生成 teamBuy 个人资料；
- 图片缩略图出现后，进入编辑页仍必须能看到真实图片内容。

## 剩余边界

pytest 无法代替微信开发者工具和真机对 WXML 图片布局、微信分享卡最终截图、缓存和真实企业微信收发进行验收。用户完成手动验收前，本轮只能判定为“本地自动化通过，待真机确认”。
