# 分享卡片 v10 Codex 自测与对抗式审查报告

日期：2026-08-28
范围：资料、图片资料、链接、房源、商品、服务方案、电子名片、合集的分享图与原生分享回调。

## 1. 本轮结论

本地分享链路已统一到 `share_card_v10`：

- 有真实主图的资料使用 `image_first`，图片进入固定 750×600（5:4）JPG 的大图区域；图片资料使用完整图 `contain`，房源、商品、服务等商业图片使用铺满式 `cover`。
- 无真实主图的资料使用 `info_first`，固定信息卡只展示类型、标题、摘要和有限事实标签，不再绘制小主图占位。
- 电子名片使用 `identity_first`，保留头像、姓名、身份和联系方式信息层级。
- 分享动作只返回已经保存且版本匹配的 JPG；快照缺失、过期或生成失败时返回 `null` 并明确等待，不会返回资料库页面作为兜底。
- 原有“保存分享图”入口已迁移为复用 v10 快照，不再保留旧的 750×1050 独立海报渲染实现。

### 2026-08-28 收口增量

- 资料库和合集发送成功后现在以 `latestShareAt` 参与“最近”排序，并同步更新页面内存与对应缓存，列表中间发送的资料/合集会移动到第一位。
- 创建、编辑、发布、图片入库和分享快照保存会失效资料库元数据缓存；资料刷新请求增加 generation 门禁，旧响应不会把旧列表重新写回。
- 统一分享构造器取消隐式首页回退；缺少 path 或目标为资料库路径时返回 `null`，避免遗漏调用导致微信截取错误页面。

## 3. 对抗式审查结果

### P0 反例

| 反例 | 当前结果 |
| --- | --- |
| 非名片、有真实主图 | 返回 v10 JPG，`imageUrl` 为已上传地址，`path` 为资料详情页 |
| 非名片、无真实主图 | 返回 v10 信息 JPG，不使用默认头像/列表页截图 |
| 当前快照缺失、过期、生成失败 | 不允许原生分享，返回 `null`，显示准备提示 |
| v9 快照仍在数据库 | 不视为当前快照，按 v10 重新生成 |
| 快速连续进入分享入口 | 通过进程内并发合并和 generation 检查，旧生成结果不能覆盖新状态 |
| 图片下载失败 | 生成失败，不生成不完整卡片，不回退列表截图 |

### 已审查的回调场景

已静态核对资料详情、资料库、资料列表、名片、合集、供需、商机和回应包相关的 `onShareAppMessage`：

- 成功路径均要求有效 `imageUrl`，并指向目标详情或合集页面。
- 未就绪路径均禁止分享或返回 `null`，没有把资料库首页作为分享兜底。
- 详情页只有在最终分享对象构造成功后才记录分享行为，失败尝试不会污染分享统计。

## 5. 真实风险

- 本轮没有部署生产后端，也没有上传微信体验版；线上容器和体验版是否已切换到 v10，需要完成部署和上传后再验证。
- 图片能否被微信接受还取决于生产媒体地址可公网访问、HTTPS、响应头和图片尺寸；本地 smoke test 无法替代真实微信发送。
- 数据库中的历史消息和已发送的旧卡片不会被改写；只能保证同一资料后续重新发送时使用新 v10 快照。
