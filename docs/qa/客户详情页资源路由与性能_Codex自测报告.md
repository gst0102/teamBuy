# 客户详情页资源路由与性能 Codex 自测报告

日期：2026-08-27

## 结论

本轮代码修复已完成。雷达来源资料直达、客户详情热路径缓存、开始跟进入口和放弃跟进操作位置均已完成静态检查与相关回归测试；尚未部署生产，也尚未通过微信开发者工具上传体验版，需用户完成真机验收。

## 本轮修复范围

1. 雷达卡片的来源资料使用 canonical `noteId` 直达 `pages/note-preview/index`，不再把资料 ID 当作 Card ID 请求 `/api/cards`。
2. 客户详情增加按环境、用户、模式、客户和线索隔离的进程内缓存，缓存只保留 2 分钟、最多 24 条，不写入 `wx` 持久化存储；命中缓存先展示，后台静默刷新。
3. 客户详情的“开始跟进”同时支持 `customerId` 和 `leadId`，成功后清理相关缓存并返回雷达页；缺少身份时显示明确错误，不再静默无响应。
4. 客户详情和雷达卡片统一将“放弃跟进 / 恢复跟进”放在右侧；放弃、恢复和开始跟进后的列表状态会清理旧的智能缓存，避免已处理客户短暂回闪。

## 已执行检查

- `node --check`：客户详情、雷达、资源导航、客户详情缓存、App 入口。
- `python3 -m json.tool`：客户详情和雷达页面配置。
- `git diff --check`：相关改动无空白错误。
- 后端 SCRM 回归：`16 passed`。
- 对抗式检查：
  - 来源资料导航结果为 `/pages/note-preview/index?id=...`，不出现 `card-view`。
  - 缓存命中要求同环境、同用户、同模式、同客户和同线索；切换环境或超过 TTL 后必须失效。
  - 客户详情与雷达卡片的主操作均位于放弃跟进操作之前，放弃入口在右侧。
  - 客户详情缓存没有 `wx.setStorage` / `wx.getStorage`，雷达和详情页不再调用通用 Card 导航处理来源资料。

## 真机验收清单

1. 从雷达“待跟进”和“访客”卡片点击来源资料，确认打开的是对应资料正文，不是资料库或旧的 Card 页面。
2. 从雷达进入同一客户详情：首次进入观察加载；返回后再次进入，确认先显示已有内容，再后台刷新，不出现旧客户内容串线。
3. 从只有线索 ID 的客户详情点击“开始跟进”，确认有成功反馈并回到雷达；该客户不再出现在待跟进和访客列表。
4. 在雷达和客户详情分别点击右侧“放弃跟进”，确认快速返回雷达，客户从工作列表消失，并能在已放弃入口恢复。
5. 退出账号或切换账号后，确认详情缓存不复用上一账号数据。

## 尚未覆盖的项目风险

- 冷启动没有本地详情快照时仍需请求后端，无法承诺完全离线秒开；本轮解决的是雷达到详情和页面返回的热路径，并避免媒体或后台刷新阻塞首屏。
- 真机首屏耗时、网络瀑布、微信体验版构建产物和生产接口响应时间仍需在微信开发者工具及真机中确认。
