# 客户跟进状态与客户详情 对抗式审查报告

日期：2026-08-27

## 结论

源码、后端测试和页面对象级模拟的对抗式审查通过；不把它等同于真实微信真机最终通过。当前未发现会导致客户状态错误复活、跨客户操作或匿名留言串线的本地 P0 缺陷。

## 反例攻击结果

1. **连续点击开始/放弃/恢复**：客户端动作锁只允许同一客户一个请求；服务端 `operationId` 幂等，重复请求不会重复追加日志或再次推进版本。通过。
2. **请求超时或无响应**：客户端尝试按客户详情对账；无法确认时保留已从当前工作列表移除的状态，不用旧缓存回滚出队结果。通过。
3. **旧请求晚到**：情报缓存使用 generation 和当前 in-flight promise 身份保护；页面使用请求序列和卸载保护。旧响应不能删除新请求、覆盖新客户或回填旧状态。通过。
4. **版本冲突**：服务端比较 `expectedVersion`，冲突返回 409；客户端进入对账路径，不静默覆盖其他操作。通过。
5. **客户与线索错配**：服务端校验拥有者及客户身份别名交集；A 客户带 B 客户 `leadId` 返回 404。通过。
6. **匿名客户留言泄露**：留言摘要只接受精确已知登录客户身份和拥有者/买家会话关系；匿名访客不会因昵称、手机号或文本相似而被关联。通过。
7. **详情慢路径**：带 `leadId` 的详情不重新构建整套雷达；浏览/动作查询限定当前身份和最近 50 条；雷达与详情先显示缓存、再后台刷新。通过静态和模拟检查。
8. **资料路由误跳**：雷达卡片和客户详情只把 `noteId` 交给 `navigateToNoteView`，不再经过 Card/资料库兜底。通过静态检查。
9. **按钮/状态语义**：雷达卡片和详情页的放弃/恢复均保持右侧动作区；底部详情动作固定为左侧放弃/恢复、右侧开始/继续。通过结构检查；视觉仍需真机截图确认。

## 尚需人工确认的风险

- 微信开发者工具可能仍运行旧体验包；必须清缓存、重新编译并选择最新体验版。
- 本地模拟没有覆盖真实微信网络中断、请求超时、切后台和系统回收页面实例。
- Postgres 条件写入已由仓储代码和本地测试覆盖，但生产多副本并发仍需线上低风险烟测。
