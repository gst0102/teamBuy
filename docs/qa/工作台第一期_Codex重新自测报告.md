## 4. 权限 / 隐私专项复核

已执行：

```text
/tmp/teambuy-py312-test/bin/pytest backend/tests/test_app.py -q -k "public_note_preview_does_not_require_owner or showcase or customer_actions or non_owner_stats_masks_relay_private_fields or business_dashboard_aggregates_real_customer_data"
```

结果：

```text
8 passed, 88 deselected
```

这些测试证明：

- 私有资料详情对非 owner 返回 403，公开预览不要求 owner。
- 展示页公开接口不暴露资料 `ownerUserId`。
- 展示页 analytics 对非 owner 返回 403。
- 单条资料 customer-actions 对非 owner 返回 403。
- 非 owner 查看旧资源统计时会脱敏接龙隐私字段。
- 经营看板聚合能排除另一个 owner 的展示页事件。

仍不足以关闭 P0-27：

- `backend/app/api/routes_dashboard.py` 的 `GET /api/dashboard/business` 目前只接收 `ownerUserId`。
- 小程序 `pages/business-dashboard` 调用时只传当前用户 id，但接口层没有 requester 身份参数或鉴权校验。
- 因此无法证明“非 owner 直接请求 ownerUserId 时不会看到 owner 工作台数据”。

P0-27 建议修复方向：

- 后端为 `GET /api/dashboard/business` 增加 requester 身份校验，或接入真实登录态鉴权。
- 增加专项测试：owner 可读；非 owner 请求 owner 数据返回 403；匿名访客不可读后台看板。
- 前端继续只从工作台入口进入，但不能把前端入口隐藏当作权限边界。

## 5. P0-23 业务识别提示复核

当前代码位置：

- `miniprogram/pages/resource-create/index.js`
- `miniprogram/pages/resource-create/index.wxml`

当前行为：

- 识别为房源或商品后，会展示业务提示卡。
- 用户可以选择进入资料完善流程，也可以“先放笔记库”。
- 对 suggested 类型，会先调用 `confirmNoteType` 转成对应资料类型。

缺口：

- 没有根据识别结果提示“是否切换到房源工作台 / 团购工作台 / 服务工作台”。
- 没有明确的“继续当前工作台”按钮。
- 尚未覆盖服务资料识别后的工作台切换建议。

P0-23 建议修复方向：

- 在识别成功提示卡中增加工作台切换提示。
- 房源 -> 可切换 `workspaceMode=property`。
- 商品 / 团购 -> 可切换 `workspaceMode=groupbuy`。
- 服务方案 / 电子名片 -> 可切换 `workspaceMode=service`。
- 保留“继续当前工作台”，只进入资料详情，不改模式。
- 切换只保存 `workspaceMode`，不改资料 owner，不删除或隐藏任何资料。
