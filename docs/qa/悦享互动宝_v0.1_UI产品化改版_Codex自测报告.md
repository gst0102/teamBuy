## 2. 实现边界

本轮只改小程序前端 UI 和必要的前端聚合逻辑。

未改动：

- 企业微信回调、`sync_msg`、媒体转存等后端主链路
- 数据库结构
- 支付、提现、会员权益限制、CRM、订单系统
- 真实收藏、分享、下载统计接口

手动添加资源只创建 `draft` 卡片，后续仍复用现有编辑、发布、查看、接龙、管理和一键复用链路。

## 3. 数据复用方式

- 首页、资源库、访问记录、我的页复用 `GET /api/cards`
- 资源统计使用 `cards[].stats` 中已有的 `pv`、`uv`、`anonymousPv`、`loggedInViewers`、`relayCount`
- 发给客服页继续复用 `GET /api/imports/pending`、`GET /api/wecom/notifications`、`POST /api/wecom/mock-sync`
- 手动添加页调用 `POST /api/cards` 创建卡片草稿
- 资源库分类和标签由 `cards[].categoryName/tagNames` 前端聚合生成，不使用硬编码假标签
- 标签管理页调用分类标签接口，删除标签时会从用户卡片 `categoryIds` 中移除
- 匿名访问只进入统计数字，不展示身份
- 会员、邀请权益、标签管理等暂无真实接口的内容只做占位提示
