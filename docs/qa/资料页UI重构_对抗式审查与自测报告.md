# 资料页 UI 重构：对抗式审查与自测报告

日期：2026-08-13

## 范围

- 仅重构小程序 `pages/library/index` 的有资料态和首次零资料态。
- 合集、新建资料继续进入现有页面，本轮未修改其二级页面结构。
- 保留既有资料查询、分类/标签、分享追踪、客户信号和资料助手绑定接口。
- 未部署测试或生产环境，未修改数据库结构。

## 对抗式审查结论

结论：当前资料页前端与真实数据链路可以继续进入人工验收；未发现本轮引入的 P0 数据问题。

审查中主动反证并修复了以下问题：

1. **“最近”误删旧资料风险**：最近改为排序维度，不再限定最近 7 天，避免用户看不到仍可使用的旧资料。
2. **首次空态误判风险**：首次空态只由完整资料数组是否为空决定；有资料但搜索/筛选无结果时显示“没有符合条件”，不会提示添加第一份资料。
3. **网络失败误判风险**：增加加载中和加载失败状态，接口失败不会被伪装成零数据。
4. **分享次数不同步风险**：分享成功后同时更新 `stats.shareCount` 和卡片摘要，页面上的发送次数立即变化。
5. **标签伪造风险**：卡片标签只取资料类型、结构化亮点字段或后端返回的 `tagNames`，没有新增数据库字段或虚构标签。
6. **入口筛选污染风险**：分类、标签和专题计数改为基于完整资料集生成；从首页特定入口进入后清除筛选，可以恢复完整资料库。
7. **合集数量阻断风险**：合集查询失败独立降级为 0，不阻断资料主列表加载。
8. **分享追踪断链风险**：继续使用原 `onShareAppMessage`、`recordNoteView`、`shareId` 和 `sourceNoteId` 链路；UI 重构未绕过埋点。
9. **资料助手空入口风险**：资料助手按钮复用现有企业微信绑定意图接口和二维码引导，不是静态占位入口。

## 数据与数据库核对

- 资料总量：来自 `resourceStore.listCards({ ownerUserId })`，零资料判断使用完整返回数组。
- 分类：来自资料关联分类和 `listCategories`。
- 标签：来自卡片 `tagNames`；仅在实际存在标签时显示筛选。
- 发送/打开/访客：来自卡片已有 `stats.shareCount / pv / uv`。
- 客户信号：继续使用已有 `hasCustomerSignal / customerActivity / customerSummary`，点击进入雷达或管理页。
- 合集数：来自 `api.fetchShowcases(ownerUserId)`；失败时只影响计数展示。
- 本轮没有数据库迁移、表结构改动或后端写入逻辑改动。
