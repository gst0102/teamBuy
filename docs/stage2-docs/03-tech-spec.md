# 技术规格

## 1. 技术栈

前端：原生微信小程序。

后端：FastAPI。

部署：腾讯云轻量或云服务器。

数据库：推荐 PostgreSQL；如阶段三资源有限，可先用 SQLite 开发并保留迁移到 PostgreSQL 的结构。

对象存储：推荐腾讯云 COS；开发阶段可 mock 为本地静态路径。

大模型：规则优先，大模型兜底。供应商待确认。

Docker 构建：阶段三生成 `backend/Dockerfile` 时，Python 依赖安装优先使用清华源：

```text
https://pypi.tuna.tsinghua.edu.cn/simple
```

本地和镜像构建应支持通过 `PIP_INDEX_URL` 覆盖默认源。

## 2. 前端约束

- 使用原生小程序页面和组件。
- 页面必须面向真实操作，不做营销首页。
- 页面默认从素材库和待认领导入开始组织。
- 不在前端保存企业微信 Secret、Token、EncodingAESKey、大模型 Key。
- 匿名用户只允许查看和产生匿名浏览统计，不允许接龙。
- 接龙必须登录。
- v0.1 不开发 PC Web 管理端。
- 企业微信客服侧边栏/H5 发小程序卡片能力只作为 P2 技术预研，不进入 v0.1 P0。

## 3. 后端约束

- 所有密钥通过环境变量读取。
- 企业微信回调入口必须支持 GET 验证和 POST 事件接收。
- 回调处理应快速返回，耗时解析建议交给后台任务。
- 媒体文件收到后必须尽快转存。
- 原始消息必须保存，便于失败重试和排查。
- 卡片复用必须生成新卡片，不得覆盖原卡片数据。
- Dockerfile 中安装 Python 依赖时必须支持 `PIP_INDEX_URL`，默认使用清华源加速。

## 4. 状态管理

### 小程序端

小程序端维护以下状态：

- 当前登录用户
- 待认领导入数量
- 素材库筛选条件
- 当前编辑卡片草稿
- 当前查看卡片
- 接龙表单状态

### 后端

后端维护以下状态：

- 导入批次状态：`pending`、`success`、`failed`、`claimed`
- 卡片状态：`draft`、`published`、`archived`
- 接龙状态：`active`、`deleted`
- 跟进状态：`pending`、`followed`

## 5. 真实接入策略

### 企业微信客服

真实接入内容：

- 配置回调 URL
- Token 验证
- 接收消息事件
- 调用 `sync_msg`
- 获取文本、图片、链接、位置、视频消息
- 通过客服消息回发导入结果

开发 mock：

- 使用本地 JSON 模拟 `sync_msg` 返回结果。
- 使用手动 API 触发导入批次生成。

### 小程序登录

真实接入内容：

- 微信登录 code
- 后端换取 openid
- 建立用户记录

开发 mock：

- 使用 mock openid 和昵称头像。

### 客服侧边栏/H5 发卡片

v0.1 不真实接入。

后续技术预研内容：

- 小程序后台与企业微信客服绑定方式。
- 企业微信后台是否可配置客服侧边栏、客户详情或工具栏 H5。
- H5 是否可通过企业微信工具能力发送小程序卡片。
- 发送卡片时所需的用户身份、卡片路径、参数和权限边界。

开发边界：

- 不在 v0.1 中创建完整 PC 管理后台。
- 如需验证，仅新增轻量 `web-tool/` 原型，不影响 `miniprogram/` 和 `backend/` 主链路。
- 若官方能力不可用，仍以“小程序内编辑后分享卡片”为主链路。

### 对象存储

真实接入内容：

- media_id 下载
- 上传到对象存储
- 返回可访问 URL

开发 mock：

- 本地文件路径或固定测试图片 URL。

### 大模型

真实接入内容：

- 文本清洗
- 字段候选提取
- 结构化输出

开发 mock：

- 固定返回字段补全结果。
- 无 API Key 时只运行规则解析。

## 6. 解析规则

规则解析优先级：

1. 链接标题作为标题候选
2. 第一段有效文本作为标题候选
3. 第一张图片作为封面候选
4. 其余图片进入图集
5. 其余文本合并为详情
6. 手机号正则识别为联系电话候选
7. 位置消息识别为位置候选
8. 视频消息进入视频字段

大模型兜底触发条件：

- 标题为空或明显过长
- 详情文本杂乱
- 规则无法识别项目名、电话、位置
- 链接内容只有标题和 URL，缺少可读详情

## 7. 性能要求

- 卡片查看页首屏应在 2 秒内展示基本内容。
- 图片应使用压缩后的可访问 URL。
- 浏览记录写入不得阻塞页面展示。
- 导入解析可异步完成，但必须给用户明确成功或失败通知。
- 素材库列表应分页或按需加载。

## 8. 安全和合规要求

- 不把任何 Secret、Token、EncodingAESKey、AppSecret 写入前端或 Git。
- 普通用户看到的接龙昵称必须脱敏。
- 浏览用户列表只展示已登录用户。
- 匿名浏览者只计入 PV/UV，不展示身份。
- 手机号和地址只在团长管理侧展示。
- 保存来源链接，避免宣称自动抓取第三方私有内容。
- 不做支付、收款、分账，避免首版资金合规风险。

## 9. 异常处理

- 回调验证失败：记录日志并返回明确错误。
- `sync_msg` 拉取失败：导入批次标记失败，通知用户。
- 媒体下载失败：保留文本和链接，标记媒体缺失。
- 规则解析失败：尝试大模型兜底。
- 大模型失败：保留规则解析结果。
- 用户未登录接龙：引导登录。
- 匿名浏览：只计入匿名统计。
- 复用失败：不得影响原卡片。
- 客服侧边栏发卡片能力不可用：不阻断 v0.1，上线仍以小程序分享卡片为准。
