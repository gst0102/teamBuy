# 资料整理助手 P0/P1/P2 实施路线图

## 目标

本路线图用于约束后续开发顺序。排序原则不是功能是否高级，而是主链路是否成立：

- P0：能收、能整理、能认领、能追溯。
- P1：能作为稳定产品日常使用。
- P2：让产品更聪明、更好看、更能收费。

完整架构边界见：

```text
docs/stage2-docs/08-plugin-architecture.md
```

## P0：主链路必须成立

P0 目标是企业微信收到内容后，能稳定进入资料整理助手，并生成用户可认领、编辑、追溯的笔记或卡片。

### P0 第一阶段：企业微信客服 sync_msg 过渡入口跑稳

当前先以企业微信客服 `sync_msg` 作为可用入口和过渡方案。会话内容存档开通前，不能等待接口权限空转。

必须完成：

- 企业微信客服回调可接收，URL 验证必须纯文本原样返回 `echostr`。
- `sync_msg` 能拉取客服会话消息，并正确维护 cursor、锁和失败状态。
- 图片、视频等媒体下载失败时不阻断整批导入；失败写入补偿队列。
- 真实链路不能生成 mock 媒体 URL，避免误判真实转存成功。
- 企业微信消息批次转为 `ContentObject`。
- `ContentObject` 统一进入 `content-to-note`。
- 输出先兼容生成现有 `generatedCard`，保持小程序待认领、编辑、发布链路可用。
- 导入成功和失败必须有通知或可查询记录。
- 必须有回归测试覆盖：
  - 回调验证
  - `sync_msg`
  - 媒体成功转存
  - 媒体失败补偿
  - `ContentObject -> content-to-note`
  - 链接封面和来源 URL

当前状态：

- 回调新路径和纯文本验证已完成。
- 媒体失败不阻断整批导入已完成。
- `RawMessage -> ContentObject -> content-to-note -> UserNoteDraft -> generatedCard` 已完成。
- 下一步应补强 `SkillRun` 持久化、失败日志和企业微信导入通知口径。

### P0 第二阶段：正式 UserNote 和小程序笔记库

必须完成：

- 新增正式 `UserNote` 数据模型。
- 笔记支持编辑、删除、分类、搜索、封面、电话显示开关和来源追溯。
- 用户只能读取自己的笔记。
- 用户删除笔记不删除企业微信原始存档。
- 小程序新增“我的笔记”基础管理。
- 现有 `generatedCard` 逐步迁移为 `UserNote` 驱动。

### P0 第三阶段：会话内容存档接入

需要用户先开通企业微信会话内容存档。

必须完成：

- 新增 `wecom-archive-core`。
- 保存原始消息、媒体引用、外部联系人、游标、失败日志和审计记录。
- 会话内容存档消息转为 `ContentObject`，复用 `content-to-note`。
- 与企业微信客服 `sync_msg` 并行一段时间，不互相替代。
- 原始会话存档和用户笔记分离。

## P1：产品可日常使用

P1 目标是把 P0 主链路增强成用户愿意日常使用的产品能力。

必须完成：

- `SkillRun` 持久化：
  - 记录 `skillId`、状态、输入快照、输出引用、模型供应商、失败原因、成本、开始和结束时间。
- 展示页构建器第一版：
  - 用户在小程序筛选、搜索、勾选多个笔记。
  - 支持两个默认模板。
  - 配置店名、banner、简介、分类、联系方式、字段显示开关。
  - 预览和发布小程序分享页。
  - 不做支付、订单、购物车或收款。
- 支付和权益基础：
  - 免费额度。
  - 套餐权益。
  - 小程序微信支付。
  - 企业微信 H5 支付链接。
  - 支付只控制权益和额度，不耦合内容整理逻辑。

## P2：差异化和商业增强

P2 目标是提升产品竞争力，但不阻塞主链路上线。

可选增强：

- `note-to-comic-image`：
  - 单篇笔记生成漫画图、宣传图或长图。
  - 生成失败不影响原笔记。
  - 支持重试，可设为封面或展示页素材。
- AI 辅助：
  - 推荐分类。
  - 优化标题。
  - 生成店铺简介。
  - 生成 banner 文案。
  - 提取字段候选。
- 多模型 Adapter：
  - DeepSeek。
  - OpenAI。
  - 通义。
  - 智谱。
  - 所有模型输出统一结构校验。
- 运营后台：
  - 套餐管理。
  - 用量统计。
  - 失败任务重试后台。
  - 用户反馈和人工修正入口。

## 当前执行顺序

当前启动 P0 第一阶段，顺序为：

1. 稳定企业微信客服 `sync_msg` 入口。
2. 将导入链路统一到 `ContentObject -> content-to-note`。
3. 增加 `SkillRun` 持久化和失败日志。
4. 补强导入成功/失败通知和补偿查询。
5. 再进入正式 `UserNote` 和小程序“我的笔记”。
6. 用户开通会话内容存档后，并行接入 `wecom-archive-core`。

## 注意事项

- 企业微信客服和会话内容存档不是简单换接口。客服适合入口、菜单、通知、H5 支付和小程序跳转；会话内容存档适合原始聊天留痕、审计和合规。
- 两条企业微信来源可以共用后面的 `ContentObject -> content-to-note -> UserNote`，但前面的鉴权、拉取、游标、媒体、审计和合规处理不同。
- 未开通会话内容存档前，不要阻塞 P0 第一阶段；先把企业微信客服过渡入口跑稳。
