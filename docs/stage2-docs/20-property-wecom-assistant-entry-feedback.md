# 房源助手首页入口与企业微信反馈闭环

日期：2026-06-26

## 背景

房源版首批推广主路径确定为：

```text
对盘群看到房源 -> 发给企业微信房源助手 -> 自动拆房源/生成房源卡或合集 -> 小程序查看结果 -> 分享给客户或同行 -> 看反馈并跟进
```

小程序首页不推倒重做，只在现有房源工作台结构上增强“房源助手”入口。

## 产品目标

- 首页让用户明确知道：群里房源可以直接发给房源助手。
- 企业微信收到并处理完成后，必须给用户明确反馈，避免用户怀疑“发过去有没有处理”。
- 反馈应能引导用户进入小程序结果页，继续查看房源卡、加入合集或分享。

## 本期范围

### 小程序首页

- 保留现有首页顺序：
  - banner
  - 今日概览
  - 常用入口
  - 最近成果
  - 反馈
- 房源工作台 banner 的快捷提示加入“添加/发送给房源助手”。
- 常用入口第一项改为“添加房源助手”。
- 使用 `miniprogram/static/icons/wechat.svg` 作为微信图标。
- 点击房源助手入口时：
  - 优先请求 `/api/wecom/customer-service-config`。
  - 如果配置完整且微信环境支持，调用 `wx.openCustomerServiceChat`。
  - 同时复制一段简短提示，方便用户粘贴给助手。
  - 失败时提示“已复制，请粘贴给助手”。

### 企业微信完成反馈

- 导入批次完成后生成结构化 `ImportNotification`：
  - 成功：标题、消息、结果类型、结果 ID、小程序路径、动作按钮文案。
  - 失败：失败原因。
- 企业微信真实同步链路在处理完成后尝试给用户发送文本反馈。
- 第一版先发文本，内容包含：
  - 已生成/已拆出结果
  - 上游电话等私密保存提示
  - “打开小程序查看”的路径提示
- 发送失败不阻断导入；通知记录保留 `sendStatus/sendError`，便于排查。

## 不做事项

- 不把首页改成全新结构。
- 不删除五个 tab：`首页 / 资料 / 合集 / 反馈 / 我的`。
- 不在公开客户页展示上游联系方式或“隐藏了房东电话”。
- 不承诺小程序能自动变成浮窗。
- 不在本期强做企业微信小程序卡片消息；先用文本反馈打通闭环。

## 验收标准

- 首页房源模式可看到“添加房源助手/发给房源助手”。
- 常用入口标题是“常用入口”，不是“租房中介常用入口”。
- 房源助手入口按钮文字和图标不变形，使用 rpx 和 flex 居中。
- `/api/wecom/customer-service-config` 可供前端读取客服配置。
- 企业微信真实同步完成后，通知记录包含结果路径和发送状态。
- 发送失败不影响资料生成。
- 后端测试覆盖通知结构和客服发送调用。
