# PC 运营后台 V1

更新时间：2026-06-28

## 1. 背景

当前小程序端四个工作台、资料库、合集、客户动作等功能已经基本成型，下一步需要一个独立的 PC 端运营后台，解决以下几类实际运营问题：

- 每天看新增用户、活跃、资料产出、合集产出、客户动作。
- 快速看哪些用户在用，哪些合集有打开和互动。
- 批量整理和导入群二维码，不在手机里反复搬运。
- 处理用户反馈、Bug、建议和积分申诉。
- 把系统待处理项集中起来，而不是分散在日志和多个页面里。

这一版的定位不是再做一个完整 B 端 CRM，而是做一个轻量、能立刻帮项目提效的运营工作台。

## 2. 第一版目标

一句话目标：

> 让负责人每天 5 分钟看懂数据，15 分钟处理完核心运营动作。

V1 重点解决：

1. 每日总览
2. 用户和内容排行
3. 批量上传群二维码
4. 反馈工单处理
5. 系统待处理提醒

## 3. 当前后端现实边界

这块必须先说清楚，避免后台做成“看起来很全，实际上很多数据不真实”。

### 3.1 当前已经后端落库、适合直接进入 PC 后台的数据

- 用户注册数据
- 资料/笔记数据
- 合集/展示页数据
- 展示页事件数据
- 客户动作数据
- 企业微信导入批次
- 导入通知
- 媒体重试任务

### 3.2 当前仍主要在小程序本地存储、暂时不能做全局后台统计的数据

- 群资源库积分
- 企业资源搜索积分
- 帮助与反馈页面提交记录
- 用户个人资源库本地缓存

因此 V1 后台的原则是：

- 已经落库的数据，做成真实运营能力。
- 未落库的数据，不伪造总览数据。
- 对未后端化模块，在后台明确展示为“待接通”。

## 4. 页面结构

PC 端建议做成左侧导航 + 右侧工作区。

### 4.1 左侧导航

1. 总览
2. 用户排行
3. 内容排行
4. 群二维码批量上传
5. 反馈工单
6. 系统待处理
7. 积分与资源状态

### 4.2 总览页

顶部 8 张指标卡：

- 今日新增用户
- 今日新增资料
- 今日新增合集
- 今日客户动作
- 今日展示页打开
- 今日导入通知
- 待发送通知
- 待处理异常

下面两块：

- 近 7 日趋势
- 今日重点提醒

重点提醒示例：

- 今天有 3 个导入失败待看
- 有 5 个媒体重试失败
- 今天新增 7 个用户，但只有 1 个做了合集
- 今日打开最多的合集来自某个工作台

### 4.3 用户排行页

以表格为主，支持搜索。

字段建议：

- 用户昵称
- 注册时间
- 资料数
- 合集数
- 客户动作数
- 展示页打开数
- 最近活跃时间
- 用户状态标签

排序优先：

- 最近 7 日活跃排行
- 合集打开排行
- 客户动作贡献排行

### 4.4 内容排行页

分成两个列表：

- 合集排行
- 资料排行

合集排行字段：

- 合集名称
- 所属用户
- 状态
- 打开数
- 点击资料数
- 咨询动作数
- 最后打开时间

资料排行字段：

- 资料标题
- 所属用户
- 类型
- 打开数 / 互动数
- 来源工作台
- 最近互动时间

### 4.5 群二维码批量上传页

这一页是运营效率工具，不要求先和群资源库前台完全打通。

第一版形态：

- 顶部提供格式说明
- 中部一个大粘贴框
- 支持 `Tab/逗号/竖线` 三种常见格式
- 点击后先做预览解析
- 确认后保存为“上传批次”

建议字段：

- 群名称
- 城市
- 区域
- 类型
- 标签
- 二维码链接
- 有效期
- 备注

保存后后台可查看：

- 批次名称
- 导入条数
- 解析成功条数
- 解析失败条数
- 操作时间
- 操作人

### 4.6 反馈工单页

统一处理：

- Bug 反馈
- 产品建议
- 资源纠错
- 积分申诉

字段建议：

- 反馈类型
- 提交用户
- 联系方式
- 问题描述
- 附图/附件占位
- 状态
- 处理人
- 回复内容
- 奖励积分备注
- 创建时间

状态流转建议：

- 待处理
- 已查看
- 已回复
- 已采纳
- 已关闭

### 4.7 系统待处理页

聚合现有后端已经有的数据：

- 导入失败
- 待发送通知
- 媒体重试失败
- 同步任务失败

这个页面的价值很高，因为它是真正的“每天必看页”。

### 4.8 积分与资源状态页

V1 不做“可直接修改用户资源积分余额”的假功能。

这一页只展示：

- 群资源库：前端本地积分，待后端化
- 企业资源搜索：前端本地积分，待后端化
- 帮助反馈：前端本地提交，待后端化
- 后续接通后可在此页增加：
  - 用户积分调整
  - 冻结积分
  - 扣分日志
  - 排行榜

## 5. V1 必做范围

### 5.1 做

- PC 后台页面入口
- 管理员 Token 校验
- 总览数据 API
- 用户排行 API
- 内容排行 API
- 系统待处理 API
- 群二维码批量上传预览与保存
- 反馈工单创建 / 列表 / 更新状态 / 回复

### 5.2 暂不做

- 资源积分全局真实统计
- 用户积分余额直接修改
- 资源积分排行
- 群资源库前后台完全打通
- 企业资源搜索调用记录全局统计
- 微信客服自动回复打通

## 6. 数据口径

### 6.1 今日新增用户

- 口径：`users.createdAt` 在今日 00:00-23:59 内的数量

### 6.2 今日新增资料

- 口径：`user_notes.createdAt` 在今日范围内的数量

### 6.3 今日新增合集

- 口径：`showcase_pages.createdAt` 在今日范围内的数量

### 6.4 今日客户动作

- 口径：`customer_actions.createdAt` 在今日范围内的数量

### 6.5 今日展示页打开

- 口径：`showcase_events.eventType = view` 且 `createdAt` 在今日范围内

### 6.6 待处理异常

- 口径：
  - 导入失败
  - 待发送通知
  - 媒体重试失败
  - 失败同步任务

## 7. 接口建议

### 7.1 页面入口

- `GET /ops`

### 7.2 后台数据接口

- `GET /api/ops-admin/overview`
- `GET /api/ops-admin/user-leaderboard`
- `GET /api/ops-admin/content-leaderboard`
- `GET /api/ops-admin/system-queue`

### 7.3 群二维码批量上传

- `POST /api/ops-admin/group-upload/preview`
- `POST /api/ops-admin/group-upload/batches`
- `GET /api/ops-admin/group-upload/batches`

### 7.4 反馈工单

- `GET /api/ops-admin/feedback`
- `POST /api/ops-admin/feedback`
- `PATCH /api/ops-admin/feedback/{ticketId}`

## 8. UI 原则

- 页面优先清楚，不做复杂炫技。
- 总览页先让人看懂，再让人下钻。
- 排行列表密度高一点，适合运营扫描。
- 批量上传页以“解析成功/失败预览”作为核心反馈。
- 反馈工单页强调状态、回复、奖励备注三件事。
- 对暂未后端化的能力必须明确标注，不用“空数据”假装可用。

## 9. 验收标准

### P0

- 管理员能打开 PC 后台页面。
- 未带管理员 Token 不能查看后台数据。
- 总览页能返回真实用户 / 资料 / 合集 / 客户动作 / 打开等数据。
- 用户排行和内容排行能正常展示。
- 群二维码批量上传支持预览解析并保存批次。
- 反馈工单能创建、查看、更新状态和回复。
- 系统待处理页能显示导入失败 / 通知待发送 / 媒体重试失败。

### P1

- 总览支持 7 日趋势。
- 用户排行支持搜索。
- 批量上传支持成功/失败条数显示。
- 反馈工单支持按状态筛选。

### P2

- 后续接企业资源 / 群资源真实积分统计。
- 后续接微信客服通知和订阅消息。
- 后续接积分人工调整。

## 10. 开发顺序建议

1. 先做后台入口和 Token 校验
2. 做总览、排行、系统待处理 API
3. 做总览页与排行页
4. 做二维码批量上传
5. 做反馈工单
6. 最后补“积分与资源状态”占位说明
