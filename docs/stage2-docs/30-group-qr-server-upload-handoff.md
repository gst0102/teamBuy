# 群二维码批量上传到服务器交接文档

更新时间：2026-06-28

## 1. 适用场景

当用户后续拿到一批微信群二维码图片，不想自己做图床、不想自己填 Excel、不想自己回填链接时，交给 Codex 处理。

目标是：

1. 读取一批二维码图片
2. 提取可见信息
3. 上传到服务器可访问目录
4. 生成图片 URL
5. 整理成可导入的资源模板
6. 需要时再写入后台或前端展示数据

## 2. 当前推荐工作流

### 第一步：用户提供素材

用户最好给 Codex：

- 一个本地文件夹，里面放所有群二维码图片
- 或若干张明确路径的图片
- 一份简单说明文本，哪怕很粗糙也可以

说明文本建议包含：

- 群名称
- 城市
- 区域
- 类型
- 标签
- 备注

如果没有说明文本，Codex 至少可以先从图片里提取：

- 群名称
- 二维码到期时间
- 是否是微信群二维码

但以下字段通常需要用户补充：

- 城市
- 区域
- 类型
- 标签
- 备注

## 3. “二维码内容”和“二维码链接”的区别

这个必须先说清楚：

- 二维码内容：扫码后微信识别到的入群数据，不一定是普通网页链接。
- 二维码链接：二维码图片本身上传到服务器后得到的图片 URL。

资源模板批量导入时，建议使用的是：

> 二维码图片 URL

而不是扫码后的微信内部内容。

## 5. Codex 执行任务时要做什么

### 5.1 读取本地二维码图片

Codex 需要：

- 枚举用户给出的目录或文件
- 读取图片
- 尝试提取可见文案
- 记录原文件名

### 5.2 整理元信息

每个群资源至少整理出：

- 群名称
- 城市
- 区域
- 类型
- 标签
- 二维码原文件名
- 二维码图片 URL
- 有效期
- 备注

### 5.3 上传服务器

上传要求：

- 不覆盖已有同名文件
- 文件名做安全改写，建议：
  - 时间戳
  - 群名拼音/英文摘要
  - 随机短后缀
- 上传前先确认目录存在
- 上传后验证公网 URL 可访问

### 5.4 产出模板文件

Codex 应输出：

- 一份 `.csv`
- 一份 `.xlsx`（如环境允许）

列建议固定为：

```text
群名称,城市,区域,类型,标签,二维码链接,有效期,备注
```

## 6. 推荐的资源整理口径

### 类型建议

- 房源
- 团购
- 老板
- 本地生活
- 服务
- 自定义

### 标签建议

优先使用：

- 行业标签
- 城市标签
- 人群标签
- 用途标签

例如：

- Python
- 技术交流
- 长沙
- 岳麓区
- 老板资源
- 找合作

## 7. 风险提醒

- 微信群二维码通常有有效期，不能当作永久资源。
- 上传前最好记录图片上可见的到期时间。
- 如果无法确认城市/区域，不要乱猜，标记为 `待补`。
- 如果二维码涉及敏感群或私密群，不应公开放到前端列表。
- 后续正式开放前，仍建议补审核和有效期校验。
