# 企业群机器人消息模板 V1

更新时间：2026-06-29

## 1. 文档目标

本文档用于给企业群机器人配置标准消息模板。

当前已确认的实现方式是：

- 机器人无法进入外部群
- 外部群由运营本人手动转化
- 企业群由机器人通过 API 按不同 `groupId` 发送不同群消息

所以本文档只定义：

- 企业群机器人发什么
- 不同群类型分别发什么
- 每条消息适合跳到小程序哪里
- 哪些消息适合自动发，哪些要人工确认后发

## 2. 机器人在链路中的职责

推荐职责固定为：

```text
你：负责外部群引流、筛选、转化
机器人：负责企业群稳定播报
小程序：负责承接、查看、提交、生成
```

机器人不负责：

- 进入外部群
- 拉人进群
- 私聊转化
- 回复复杂问题
- 处理非标准合作沟通

机器人只负责：

- 定时发更新
- 定时发入口
- 定时发总结
- 把群成员引回小程序

## 3. 第一版统一发送节奏

建议每个企业群每天最多 3 条。

### 3.1 中午更新

时间建议：

- `11:30 - 13:30`

目的：

- 告诉群成员今天已经有新内容
- 给出当天最值得看的一条合集或结果页

### 3.2 下午入口

时间建议：

- `15:00 - 17:30`

目的：

- 告诉群成员看完以后下一步做什么
- 推动提交资源、继续查看、生成同款

### 3.3 晚间总结

时间建议：

- `20:00 - 22:00`

目的：

- 收口当天内容
- 做一次提醒
- 顺带征集资源

## 3.4 后端发送 API

第一版后端接口：

```text
GET /api/wecom/group-bot/config
POST /api/wecom/group-bot/broadcast
```

鉴权：

```text
X-Admin-Token: <WECOM_ADMIN_TOKEN>
```

后端配置：

```text
WECOM_GROUP_BOT_WEBHOOKS={"property":"https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"}
```

发送规则：

- webhook 只从后端 `WECOM_GROUP_BOT_WEBHOOKS` 按 `groupId` 查，不允许请求方直接传 webhook。
- `broadcast` 支持 `groupId` 或 `groupIds`。
- `template` 支持 `midday / afternoon / evening / custom`。
- 默认 `dryRun=true`，只返回预览；必须显式 `dryRun=false` 才真实发送。
- 第一版只发送文本，后续再扩展 markdown、图文卡片或定时任务。

示例：

```json
{
  "groupIds": ["property"],
  "template": "midday",
  "variables": {
    "topic": "岳麓区房源",
    "count": 12,
    "focus": "地铁口两房"
  },
  "miniappPath": "/pages/showcase-view/index?id=showcase_today",
  "dryRun": true
}
```

## 4. 通用模板结构

### 4.1 模板 A：中午更新

```text
今日更新：
[主题/区域] 新增 [X] 条，已整理成合集。
今天重点是 [重点方向]。
需要的直接看小程序。
```

### 4.2 模板 B：下午入口

```text
你现在可以直接做这几件事：
1. 看今天新增
2. 提交你的资源
3. 生成同款合集
需要我帮你整理的，也可以直接私聊我。
```

### 4.3 模板 C：晚间总结

```text
今天已更新 [X] 条内容，补了 [X] 个合集。
明天优先整理 [方向]。
你手里有资源也可以发我，我一起整理进去。
```

## 5. 按群类型配置模板

第一版建议先按 4 类企业群配置。

### 5.1 房源资源群

适用群：

- 长沙房源资源群
- 岳麓区房源群
- 转租求租群

#### 中午更新模板

```text
今日更新：
[区域] 新增 [X] 套房源，已整理成合集。
今天重点是 [两房/地铁口/急租/低价]。
需要的直接看小程序。
```

示例：

```text
今日更新：
岳麓区新增 12 套房源，已整理成合集。
今天重点是地铁口小区和两房。
需要的直接看小程序。
```

建议跳转：

- 房源合集页
- 区域精选页

#### 下午入口模板

```text
你现在可以直接做这几件事：
1. 看今天新增房源
2. 提交你的房源
3. 用同款模板生成你的房源合集
需要我帮你整理的，也可以直接私聊我。
```

建议跳转：

- 今日新增页
- 发布房源页
- 生成同款页

#### 晚间总结模板

```text
今天已更新 [X] 套房源，补了 [X] 个精选合集。
明天优先整理 [区域]。
你手里有房源也可以发我，我一起整理进去。
```

示例：

```text

示例：

```

建议跳转：

- 新功能入口页

#### 下午入口模板

```text

建议跳转：

```

## 6. API 配置建议字段

如果后端按 `groupId` 下发模板，第一版建议每个群至少配置这些字段：

```text
groupId
groupName
groupCategory
city
district
focusTopic
lunchTemplate
afternoonTemplate
eveningTemplate
defaultMiniappPath
status
```

字段说明：

- `groupCategory`：房源 / 合作 / 企业资源 / 内测反馈
- `focusTopic`：这个群当前重点方向
- `defaultMiniappPath`：这个群默认跳转的小程序页面
- `status`：启用 / 暂停

## 7. 消息内容变量建议

为了让机器人消息不那么死板，建议模板支持变量替换：

```text
{{city}}
{{district}}
{{topic}}
{{count}}
{{focus}}
{{collection_count}}
{{next_focus}}
{{miniapp_name}}
```

示例：

```text
今日更新：
{{district}} 新增 {{count}} 套房源，已整理成合集。
今天重点是 {{focus}}。
需要的直接看小程序。
```

## 8. 自动发送与人工确认边界

### 8.1 适合自动发

- 基于当日新增数量的更新消息
- 固定入口提醒
- 晚间总结
- 标准化资源征集

### 8.2 建议人工确认后再发

- 涉及价格争议的信息
- 容易引发误解的合作资源
- 数据不完整的企业信息
- 特殊活动、福利、限时权益

## 9. 机器人消息的禁区

企业群机器人不要反复发这些内容：

- 欢迎了解我们平台
- 请进对应群
- 大段产品介绍
- 连续几条都在要资源
- 没有承接页的空口号

企业群机器人应该始终围绕：

- 今天有什么
- 现在去哪看
- 你也可以提交

## 10. 第一版落地建议

建议按以下顺序上线：

1. 先选 1 个房源群做模板验证
2. 再扩到 1 个合作群
3. 再扩到 1 个企业资源群
4. 最后补内测反馈群

不要一开始所有企业群同时上机器人，先验证：

- 群成员会不会点小程序
- 哪种模板点击更高
- 哪类入口更容易被用
- 晚间总结会不会太重复

## 11. 第一版结论

企业群机器人第一版固定为：

```text
中午更新
下午入口
晚间总结
```

并按 `groupId` 区分模板内容。

当前最适合你的结构是：

```text
你去外部群拿人
机器人在企业群养人
小程序把人留下来
```
