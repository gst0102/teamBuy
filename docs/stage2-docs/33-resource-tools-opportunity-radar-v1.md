# 资源工具与商机雷达产品方案 V1

更新时间：2026-06-30

## 1. 核心定位

资源工具不是几个入口的堆叠，而是面向小生意人的机会雷达入口。

一句话定位：

> 每天从公开渠道、企业群、资源库和客户行为里，帮用户发现适合自己的可联系机会，并提供可行动的跟进工具。

完整闭环：

```text
官方收录线索
  ↓
清洗为可联系机会
  ↓
匹配用户画像
  ↓
精准推送给用户
  ↓
用户保存 / 联系 / 生成回应包
  ↓
雷达跟进打开和反馈
  ↓
转化为积分或会员付费
```

## 2. 当前资源工具入口重构

当前“我的”页资源工具区保留，但文案升级。

建议文案：

```text
资源工具
找渠道、查客户、看机会。
```

入口建议：

| 入口 | 定位 | 用户问题 | 状态 |
|---|---|---|---|
| 群资源库 | 找渠道 | 我去哪找客户、同行、资源群 | 已有第一版 |
| 企业资源搜索 | 查客户 / 合作方 | 这个企业值不值得跟 | 已有第一版 |
| 行业黄页 | 找名单 | 我想批量找某行业客户 | 后续开放 |
| 商机线索 | 看需求 / 找机会 | 今天有什么机会适合我 | 本文重点 |

资源工具首页只做入口，不承载大量线索列表。

## 3. 四个入口的职责边界

### 3.1 群资源库

定位：

> 找渠道。

承载能力：

- 搜索群
- 按城市 / 行业 / 用途筛选
- 查看群二维码
- 发布群资源
- 群有效期、举报、确认可进
- 积分查看二维码

解决问题：

```text
我去哪找人？
```

### 3.2 企业资源搜索

定位：

> 查客户 / 查合作方。

承载能力：

- 企业搜索
- 企业基础信息
- 风险 / 经营 / 股东 / 历史等深度信息
- 保存为我的资源
- 生成企业摘要卡

解决问题：

```text
这个客户或合作方值不值得跟？
```

### 3.3 行业黄页

定位：

> 找名单。

承载能力：

- 行业分类
- 城市筛选
- 企业名单
- 批量保存
- 批量生成跟进清单

解决问题：

```text
我想批量找到一批潜在客户。
```

### 3.4 商机线索

定位：

> 看需求 / 找机会。

承载能力：

- 需求广场
- 我的机会
- 订阅关键词
- 已保存线索
- 微信客服精准推送
- 与工作台打通生成回应包

解决问题：

```text
今天有什么机会适合我？
```

## 4. 商机线索页面结构

商机线索不要做成单一信息流，第一版建议 4 个 Tab。

```text
商机线索
  需求广场
  我的机会
  订阅
  已保存
```

如果第一版支持用户发布自己的供给，`需求广场` 建议升级为：

```text
供需广场
```

原因是该页面不再只是展示官方收录需求，还允许用户把已经整理好的资料卡、服务页、房源合集、商品合集、电子名片发布成“我能提供”的供给卡。

### 4.1 需求广场

定位：

> 官方收录的公开可联系线索池。

只展示满足以下条件的线索：

- 有明确需求
- 有联系可能
- 有行业或场景
- 通过基础风险过滤

卡片字段建议：

```text
标题
需求摘要
城市
行业
需求类型
联系方式状态：有微信 / 有电话 / 可私信 / 待核验
可信状态：可联系 / 待审核 / 风险
发布时间
操作：查看详情 / 保存 / 不感兴趣
```

前台不强调具体第三方来源，可展示为：

```text
官方收录
公开线索
今日新线索
```

### 4.2 我的机会

定位：

> 根据用户画像推荐给我的机会。

这个 Tab 是付费核心，不按时间流展示，而按匹配度展示。

卡片字段建议：

```text
推荐等级：高 / 中 / 低
机会标题
匹配理由
城市 / 行业 / 需求类型
联系方式状态
有效期
操作：查看联系方式 / 保存线索 / 标记已联系 / 生成回应包
```

示例：

```text
高匹配
长沙商家找地推合作

匹配理由：
你关注了长沙、本地商家、推广渠道。

操作：
查看联系方式 / 保存 / 生成服务介绍页
```

### 4.3 订阅

定位：

> 让系统替用户盯机会。

用户可配置：

```text
城市
行业
我能提供什么
我想找什么
关键词
联系方式要求
推送频率
```

也可以给用户简化为：

```text
我能提供：装修设计
我想找：客户
城市：长沙
```

系统自动生成关键词组合和匹配规则。

### 4.4 已保存

定位：

> 我的线索跟进库。

用户保存后可做：

- 标记已联系
- 备注
- 设置提醒
- 标记无效
- 生成跟进文案
- 生成自己的资料页 / 合集发给对方
- 生成回应包

已保存线索需要进入用户自己的资源体系，方便后续和雷达、客户跟进串起来。

### 4.5 回应包

回应包是商机线索的成交动作，不是普通 AI 文案。

定位：

> 当用户看到一个适合自己的需求时，系统从用户已有资料里挑出最适合回应对方的内容，组合成一份可发送、可追踪、可跟进的成交资料包。

回应包包含：

```text
对方需求摘要
推荐资料
首次联系话术
可追踪资料链接
跟进建议
```

典型链路：

```text
线索详情 / 我的机会
  ↓
生成回应包
  ↓
系统推荐用户已有资料
  ↓
用户确认 / 替换资料
  ↓
生成话术和追踪链接
  ↓
用户发给对方
  ↓
雷达跟踪打开、联系方式点击和后续提醒
```

详细方案见：

```text
docs/stage2-docs/35-response-package-monetization-v1.md
```

### 4.6 供需广场与用户发布供给

这是本模块的重要增长点。

商机线索不应只让用户看官方收录的需求，也应该允许用户把自己的需求和供给发布到广场里。

供需广场承载三类内容：

```text
官方收录需求
用户发布需求
用户发布供给
```

前台来源只需要区分：

```text
官方收录
用户发布
平台推荐
```

不需要突出微博、小红书等具体第三方来源。

#### 4.6.1 发布供给

发布供给时，不建议让用户重新填写长表单。

最顺的方式是：

```text
选择已有资料
  ↓
补充发布信息
  ↓
预览供给卡
  ↓
提交审核
  ↓
审核通过后进入供需广场
```

可选择的已有资料：

```text
房源卡
房源合集
服务介绍页
商机合作页
商品 / 团购合集
电子名片
企业资源卡
```

需要补充的信息：

```text
城市
行业
我想找谁
有效期
联系方式展示方式
```

供给卡展示字段：

```text
我能提供
标题
适合谁
绑定资料类型
城市
行业
联系方式状态
操作：查看资料 / 保存 / 申请联系
```

示例：

```text
我能提供
长沙本地推广服务

适合：
本地商家、开业门店、社区团购、地推活动

资料：
服务介绍页

操作：
查看资料 / 保存 / 申请联系
```

#### 4.6.2 发布需求

用户也可以发布“我要找”。

字段建议：

```text
标题
城市
行业
需求类型
联系方式
有效期
补充说明
```

示例：

```text
我要找
找装修公司合作

城市：长沙
行业：装修
联系方式：站内联系 / 微信
```

#### 4.6.3 我的发布

用户发布后需要一个管理页。

页面定位：

> 我的供给曝光台。

字段建议：

```text
展示中
待审核
已下架
被查看次数
被保存次数
剩余展示天数
操作：查看雷达 / 编辑 / 下架 / 再发布一条
```

这个页面不能只做成发布记录列表，它需要让用户感受到“我发布出去的供给正在被看见”。

### 4.7 供给卡与回应包的关系

供给卡负责“被别人发现”，回应包负责“主动回应一个具体机会”。

```text
供给卡：
我能提供什么，让需求方看见我。

回应包：
我看到一个需求后，拿什么资料去联系对方。
```

二者可以共用用户已有资料，但使用场景不同。

示例：

```text
用户有一份“长沙本地推广服务介绍页”

发布供给：
把这份资料发布成“我能提供长沙本地推广服务”的供给卡。

生成回应包：
看到“长沙商家找推广渠道”后，把这份资料、电子名片、案例合集和话术组合成回应包。
```

## 5. 线索入库规则

第一版不要追求数量，要追求“可联系”。

### 5.1 可进入需求广场的条件

必须同时满足：

```text
明确需求：
招 / 招聘 / 找 / 寻找 / 需要 / 求 / 合作 / 对接 / 招募

联系方式线索：
微信 / 电话 / 邮箱 / 私信 / 主页留资 / 原文可联系

行业或场景：
招聘 / 商家合作 / 渠道 / 供应商 / 本地服务 / 房源 / 装修 / 推广 等
```

### 5.2 只能进入待审核池的内容

- 有需求但联系方式不明确
- 有联系方式但场景模糊
- 看起来像广告群发
- 内容太旧
- 来源可信度不高

### 5.3 只能进入素材池的内容

- 行业讨论
- 吐槽
- 新闻
- 市场行情
- 没有明确行动对象的观点内容

这些可以用于运营分析，不进入前台需求广场。

## 6. 来源展示原则

用户提出的方向成立：

> 前台不需要强调微博、小红书等具体来源，默认作为官方收录线索给客户。

但后台必须保留完整来源。

### 6.1 前台展示

建议显示：

```text
官方收录
公开线索
今日新线索
```

不建议在卡片显眼位置显示：

```text
来源：微博
来源：小红书
```

### 6.2 后台保留

后台必须记录：

```text
source_platform
source_url
source_author
source_published_at
source_captured_at
raw_text
raw_images
```

原因：

- 去重
- 风控
- 追溯
- 投诉处理
- 判断时效
- 判断重复搬运

## 7. 与四个工作台如何打通

这里的“打通”不是替用户决定发什么，也不是把第三方线索直接做成合集。

正确理解：

> 线索是第三方的，但用户回应线索时，可以用我们的工作台生成自己的资料页、合集或服务介绍。

另一个更强的打通方式是：

> 用户已经整理好的资料，可以直接发布为供给卡，进入供需广场被别人发现。

这样资料整理能力从“自己发给客户”升级为“被潜在需求方发现”。

新增闭环：

```text
用户整理资料
  ↓
生成卡片 / 合集 / 服务页
  ↓
发布供给到供需广场
  ↓
被需求方发现
  ↓
对方查看 / 保存 / 申请联系
  ↓
用户雷达看到反馈
  ↓
用户愿意继续整理、发布、付费
```

### 7.1 示例：服务商机

线索：

```text
长沙商家找地推合作
```

用户：

```text
本地推广服务商
```

系统建议：

```text
用服务/商机工作台生成“本地推广服务介绍页”发给对方。
```

### 7.2 示例：房源

线索：

```text
有人求租岳麓区两房
```

用户：

```text
房产中介
```

系统建议：

```text
从房源工作台挑几套房源，生成房源合集发给对方。
```

### 7.3 示例：团购

线索：

```text
有人找团购供应链
```

用户：

```text
团购团长 / 供应链
```

系统建议：

```text
生成商品 / 团购合集，作为对接资料发给对方。
```

### 7.4 正确链路

```text
第三方线索
  ↓
匹配用户能力
  ↓
推荐用户用哪个工作台回应
  ↓
生成用户自己的资料页 / 合集
  ↓
用户自己发给对方
  ↓
雷达跟踪打开和反馈
```

### 7.5 回应包是最强打通方式

与四个工作台打通的最终表达可以升级为：

> 工作台负责把用户手里的资料做成可成交素材，商机雷达负责发现机会，回应包负责把素材送到具体机会面前。

对应关系：

| 工作台 / 资料 | 可生成的回应包内容 |
|---|---|
| 房源工作台 | 房源合集、房源对比、带联系方式房源资料 |
| 团购工作台 | 商品合集、供应链介绍、团购报价 |
| 服务 / 商机工作台 | 服务介绍页、案例合集、合作方案 |
| 日常资料工作台 | 电子名片、资料页、客户说明 |

这样用户不是只“整理资料”，而是在不断积累成交素材。

## 8. 用户画像与匹配

第一版用户画像不要复杂，先用 5 个字段。

```text
城市
行业
我能提供什么
我想找什么
关注关键词
```

示例：

```text
城市：长沙
行业：装修
我能提供：装修设计、施工
我想找：客户、渠道合作
关键词：装修公司、旧房翻新、商家合作、地推
```

匹配依据：

- 城市匹配
- 行业匹配
- 关键词匹配
- 需求类型匹配
- 联系方式完整度
- 发布时间新鲜度
- 用户历史保存 / 不感兴趣行为

## 9. 微信客服与小程序推送

微信客服和小程序消息不是简单通知，而是精准机会推送通道。

### 9.1 免费用户

规则建议：

```text
每天最多 1 次摘要
最多展示 3 条
联系方式部分隐藏
引导开通会员或消耗积分
```

示例：

```text
今天有 3 条长沙本地机会：
1. 有人找装修公司
2. 商家找推广合作
3. 招募本地服务商

打开查看详情。
```

### 9.2 付费用户

规则建议：

```text
每天 1-2 次
高匹配机会可单独提醒
可查看更多联系方式
可订阅更多关键词
可保存和跟进更多线索
```

示例：

```text
新机会提醒：
长沙有用户找装修公司，内容里留了微信。

匹配原因：
你关注了长沙 + 装修 + 找客户。

点击查看联系方式。
```

### 9.3 降频规则

建议：

- 连续 3 天未打开，降低推送频率
- 用户点“不感兴趣”，调整标签
- 同类低质量线索不重复推
- 每天推送次数设上限，避免打扰

## 10. 付费与积分设计

不要一上来把所有内容收费。

建议：

### 10.1 免费能力

- 查看部分需求广场
- 每天少量推荐
- 保存少量线索
- 订阅 1 个关键词

### 10.2 积分消耗

- 查看联系方式
- 查看高价值线索
- 查看企业深度信息
- 批量保存或导出

### 10.3 会员能力

- 每日精准推送
- 更多关键词订阅
- 更多联系方式查看额度
- 更多保存和跟进数量
- 高匹配机会优先提醒

第一版可参考：

```text
免费用户：
每天看 5 条线索
保存 10 条
订阅 1 个关键词

会员用户：
每天看 50 条线索
保存 100 条
订阅 10 个关键词
每日微信客服推送
高匹配机会优先提醒
```

### 10.4 供给发布付费点

供给发布是另一条更自然的付费线。

建议：

```text
免费：
发布 1 条供给卡
展示 7 天
普通排序

会员：
发布更多供给卡
展示 30 天
优先推荐
查看谁看了 / 谁保存了
获得更多雷达反馈
```

用户为“曝光和被发现”付费，比单纯为“看联系方式”付费更自然。

## 11. 积分后端化要求

当前小程序资源积分仍主要存在本地缓存中，适合演示，不适合正式上线。

正式上线前必须后端化。

建议后端账本：

```text
resource_wallet
- user_id
- openid
- available_points
- frozen_points
- updated_at

resource_point_ledger
- id
- user_id
- change_amount
- reason
- source_type
- source_id
- created_at

resource_unlock_records
- id
- user_id
- resource_type
- resource_id
- cost
- unlocked_at
- expire_at
```

必须支持：

- 退出重登不重复送积分
- 换手机积分不重置
- 同资源 24 小时内不重复扣
- 后台人工加减积分
- 举报奖励和虚假扣分可追溯
- 付费会员额度和积分额度可并存

## 12. MVP 开发顺序

## 13. 第一版结论

不要把这块做成普通需求广场。

应该做成：

```text
商机线索模块
  = 供需广场
  + 我的机会
  + 订阅关键词
  + 已保存跟进
```

它和资源工具的关系是：

```text
群资源库：找渠道
企业资源搜索：查客户
行业黄页：找名单
商机线索：看机会
```

它和四个工作台的关系是：

```text
第三方线索不是我们的内容资产，
但用户回应线索时，可以用我们的工作台生成自己的资料页和合集。

用户自己整理好的资料，也可以发布为供给卡进入供需广场。
```

最终差异化：

> 别人给用户一堆信息，我们给用户今天该联系的机会，以及能被别人发现的供给卡。
