# 商机线索页面 UI 规格与验收标准 V1

更新时间：2026-06-30

## 1. 文档目标

本文档用于约束“商机线索 / 机会雷达”页面开发，避免出现：

- 文档写的是雷达和机会推荐，开发只做成普通列表。
- 效果图有匹配度、雷达图、行动建议，实际页面被简化。
- 功能能跑，但真机视觉层级、按钮排版、卡片结构明显偏离参考图。

重要说明：

> UI 规格文档不能替代真机验收。  
> 本功能必须做“静态 UI 截图验收 -> 接口数据联调 -> 真机截图复验”的闭环。

## 3. 产品气质

商机线索页面不能做成普通信息流。

目标气质：

- 像“机会雷达”
- 像“生意待办”
- 像“系统帮我判断”
- 不像资讯列表
- 不像黄页列表
- 不像简单收藏夹

核心视觉语言：

```text
匹配度
雷达图
匹配理由
联系方式状态
建议动作
跟进状态
```

## 4. 页面清单

第一版建议至少包含 4 个页面 / Tab：

```text
商机线索首页 / 我的机会
需求广场 / 供需广场
线索详情
订阅雷达
已保存
```

其中第一版最重要的是：

1. 我的机会
2. 线索详情
3. 已保存
4. 订阅雷达

## 5. 我的机会页规格

### 5.1 页面目标

让用户一进来就感觉：

> 这是系统为我筛出来的机会，不是让我自己刷列表。

### 5.2 首屏必须包含

- 页面标题：`我的机会`
- 顶部雷达卡
- 匹配度数字，例如：`匹配度 92`
- 雷达图
- 当前最高匹配机会卡
- 匹配原因标签
- 建议动作区
- 主按钮：`生成回应包`
- 次按钮：`查看联系方式`、`保存`

### 5.3 雷达图要求

雷达图可以第一版用 Canvas、SVG、纯 CSS 或图片占位实现，但不能删除。

雷达图维度建议：

```text
城市
行业
需求
联系
时效
```

验收要求：

- 首屏可见雷达图。
- 雷达图不是装饰，应与匹配度同属一个模块。
- 雷达图旁边或下方必须显示匹配分数。
- 不能退化成只有一个百分比数字。

### 5.4 机会卡要求

机会卡必须包含：

```text
等级：高匹配 / 中匹配 / 低匹配
标题
摘要
匹配原因
联系方式状态
建议动作
```

示例：

```text
高匹配
长沙商家找推广渠道

匹配原因：
长沙 / 本地商家 / 推广渠道 / 有联系方式

建议动作：
生成服务介绍页发给对方
```

### 5.5 不得简化项

不得：

- 删除雷达图。
- 把匹配原因做成一行灰色备注。
- 把 `生成回应包` 降级为普通小按钮。
- 把页面做成普通线索列表。
- 首屏只展示筛选器和列表。

## 6. 需求广场页规格

### 6.1 页面目标

需求广场是公开线索池，但必须强调“可联系”，不是大杂烩。

如果支持用户发布供给，该页面建议升级为“供需广场”。

供需广场同时承载：

```text
官方收录需求
用户发布需求
用户发布供给
```

### 6.2 必须包含

- 顶部统计：
  - 今日新增
  - 可联系
  - 高匹配
  - 用户发布
- 筛选：
  - 城市
  - 行业
  - 需求类型
  - 联系方式
- 线索卡片列表
- 发布入口：`发布需求/供给`

### 6.3 线索卡片字段

```text
标题
一句话摘要
城市
行业
需求类型
联系方式状态
可信状态
发布时间
操作：查看详情 / 保存
```

供给卡片必须额外展示：

```text
我能提供
绑定资料类型：服务介绍页 / 房源合集 / 商品合集 / 名片
适合谁
操作：查看资料 / 保存 / 申请联系
```

### 6.4 来源展示要求

前台不显眼展示微博、小红书等具体来源。

可显示：

```text
官方收录
公开线索
今日新线索
```

后台仍必须保留真实来源字段。

### 6.5 发布需求 / 供给入口

供需广场必须提供明确发布入口。

入口文案建议：

```text
发布需求/供给
```

进入后先选择：

```text
我要找
我能提供
```

如果选择 `我能提供`，优先让用户选择已有资料，而不是重新填写大段内容。

可选择资料类型：

```text
房源卡
房源合集
服务介绍页
商机合作页
商品合集
电子名片
```

流程：

```text
选择已有资料
  ↓
补充信息
  ↓
供给预览
  ↓
提交审核
```

### 6.6 我的发布

用户发布后需要可管理。

我的发布页必须包含：

```text
展示中
待审核
已下架
被查看
被保存
剩余展示天数
操作：查看雷达 / 编辑 / 下架
```

不得只做成发布记录列表。

## 7. 线索详情页规格

### 7.1 页面目标

线索详情页不是原文页，而是行动页。

用户打开后必须知道：

- 对方要什么
- 适合谁联系
- 怎么联系
- 我下一步能做什么

### 7.2 页面结构

必须包含 3 段：

```text
结构化摘要
行动建议
跟进状态
```

### 7.3 结构化摘要

字段建议：

```text
城市
行业
需求类型
联系方式状态
有效期
可信状态
```

### 7.4 行动建议

必须突出“生成回应包”。

根据用户工作台模式推荐：

```text
房源用户：生成房源合集
团购用户：生成商品合集
服务用户：生成服务介绍页 / 商机合作页
普通资料用户：生成资料页 / 名片
```

按钮层级：

- 主按钮：`生成回应包`
- 次按钮：`查看联系方式`
- 辅助按钮：`保存到我的资源`

副文案建议：

```text
系统会从你的资料里挑选最适合发给对方的内容。
```

### 7.5 跟进状态

必须包含：

```text
标记已联系
设置提醒
备注
标记无效
```

### 7.6 回应包生成页规格

回应包生成页是从“线索详情 / 我的机会 / 供需广场需求卡”进入的行动页。

页面目标：

> 帮用户快速确定：我该发什么资料、怎么开口、发出后怎么看反馈。

必须包含：

```text
对方需求摘要
推荐资料
推荐理由
首次联系话术
认证 / 保证金状态
追踪链接
```

推荐资料卡字段：

```text
资料名称
资料类型
推荐理由
是否可替换
```

主按钮：

```text
复制回应内容
```

次按钮：

```text
替换资料
保存到跟进
```

不得简化为只生成一段文案。

### 7.7 回应包雷达页规格

回应包发出后，需要能进入雷达反馈。

必须展示：

```text
是否打开
打开时间
点击联系方式
保存状态
建议跟进动作
下次提醒
```

第一版如果还没有完整事件能力，也要保留页面结构和空态：

```text
等待对方打开
暂无点击联系方式
建议 24 小时后跟进
```

## 8. 订阅雷达页规格

### 8.1 页面目标

订阅页不是复杂搜索表单，而是配置“系统替我盯机会”。

### 8.2 必须包含

```text
我在找
我能提供
城市
关键词
联系方式要求
推送频率
```

### 8.3 交互建议

优先使用标签点选，不要让用户大量手填。

示例标签：

```text
我在找：客户 / 合作方 / 渠道 / 供应商 / 人才
我能提供：装修设计 / 地推 / 房源 / 供应链 / 本地服务
城市：长沙 / 上海 / 深圳 / 全国
```

用户填写后展示“正在为你盯”：

```text
长沙 + 装修 + 找客户
长沙 + 商家合作 + 地推
```

### 8.4 主按钮

底部主按钮：

```text
保存雷达订阅
```

## 9. 已保存页规格

### 9.1 页面目标

已保存不是收藏夹，而是轻量跟进台。

### 9.2 状态分组

必须包含：

```text
待联系
已联系
跟进中
无效
```

### 9.3 卡片字段

```text
线索标题
状态
提醒时间
最近动作
备注摘要
是否已生成回应包
操作：打开资料 / 标记已联系 / 设置提醒
```

### 9.4 不得简化项

不得只做成普通收藏列表。

必须体现：

- 跟进状态
- 最近动作
- 下一步按钮

## 10. 视觉硬要求

### 10.1 总体风格

- 轻商务
- 克制
- 清楚
- 信息密度适中
- 不做营销落地页
- 不做花哨插画页

### 10.2 色彩

建议：

```text
主色：蓝色 / 绿色
背景：浅蓝灰或白色
强调：绿色用于可联系 / 正向动作
警示：橙色用于待核验 / 即将过期
```

避免：

- 大面积紫色渐变
- 大面积深色背景
- 过多装饰性图形

### 10.3 卡片

- 卡片圆角不超过 `16rpx`。
- 卡片内必须有清晰标题层级。
- 状态标签必须 `white-space: nowrap`。
- 主按钮必须明显高于次按钮。
- 不要卡片套卡片。

### 10.4 按钮

按钮文字必须上下左右居中。

小程序 WXSS 必须使用：

```css
display: flex;
align-items: center;
justify-content: center;
```

不得只靠 `line-height` 硬凑。

### 10.5 单位

小程序页面核心尺寸使用 `rpx`。

包括：

- 字号
- 按钮高度
- 卡片间距
- 标签
- 雷达图容器
- 底部安全区

## 11. 真机验收要求

开发完成不能只看开发者工具。

必须提供：

```text
开发者工具截图
真机截图
参考图对照说明
```

至少验收以下机型或尺寸：

- 普通 iPhone 宽度
- 大屏 iPhone 宽度
- 安卓常见宽度

检查项：

- 文本不溢出
- 标签不换行异常
- 按钮文字居中
- 雷达图不变形
- 首屏核心模块可见
- 底部按钮不被安全区遮挡
- 页面滚动后模块间距正常

## 12. 开发流程要求

### 12.1 第一步：静态 UI

先不接真实接口。

目标：

- 页面结构接近参考图
- 雷达图可见
- 卡片层级正确
- 按钮和标签正常

验收通过后再接数据。

### 12.2 第二步：接 mock 数据

使用固定 mock 数据验证：

- 高匹配机会
- 有联系方式机会
- 待核验机会
- 已保存线索
- 无效线索

### 12.3 第三步：接真实接口

真实接口接入后，不能破坏静态 UI 层级。

如果数据字段缺失，必须有兜底：

- 未知城市
- 待核验
- 暂无匹配理由
- 暂无联系方式

## 13. 逐屏验收清单

### 13.1 我的机会

- 首屏看到匹配度数字。
- 首屏看到雷达图。
- 首屏看到高匹配机会。
- 卡片展示匹配原因。
- 主按钮是 `生成回应包`。
- 不像普通信息流。

### 13.2 需求广场

- 有顶部统计。
- 有筛选项。
- 线索卡片展示联系方式状态。
- 前台不突出具体第三方来源。
- 空态提示用户配置订阅或等待推荐。
- 如果命名为供需广场，必须展示“需求”和“供给”的区分。
- 必须有发布需求/供给入口。
- 用户发布的供给卡必须能看出绑定了已有资料。

### 13.3 线索详情

- 有结构化摘要。
- 有行动建议。
- 有跟进状态。
- `生成回应包` 是主操作。
- 联系方式和来源信息有权限控制空间。

### 13.4 回应包

- 不是只生成一段 AI 文案。
- 能看到对方需求摘要。
- 能看到系统推荐的用户已有资料。
- 能看到推荐理由。
- 能复制首次联系话术。
- 能生成或预留追踪链接。
- 能保存到跟进。
- 保证金 / 认证状态有展示位置。

### 13.5 订阅雷达

- 有“我在找”。
- 有“我能提供”。
- 有城市和关键词。
- 有“正在为你盯”的结果展示。
- 有保存订阅按钮。

### 13.6 已保存

- 有状态分组。
- 卡片展示最近动作。
- 卡片展示提醒或备注。
- 可标记已联系。
- 可看到是否已生成回应包。
- 不像普通收藏夹。

### 13.7 发布供给

- 可以选择已有资料。
- 可以补充城市、行业、想找谁。
- 有供给预览页。
- 有提交审核状态。
- 我的发布页能看到展示中、待审核、已下架。

## 14. 交付说明要求

开发交付时必须明确说明：

```text
当前是否为参考图版本
哪些页面已按参考图实现
哪些模块因接口或时间暂用 mock
哪些地方与参考图不同
真机截图是否已验证
```

如果只是功能版，必须写：

```text
当前不是参考图版本，仅完成基础功能。
```

## 15. 第一版结论

本页面的核心不是“展示很多线索”，而是：

> 用少量高匹配、可联系、可行动的机会，建立用户对机会雷达的信任。

第一版宁可内容少，也要页面表达准。

最不能丢的 3 个东西：

```text
雷达匹配感
生成回应包
保存后的跟进状态
```
