# 资料整理助手：内容编辑器产品设计结论

更新时间：2026-08-13

状态：产品讨论已确认，尚未进入本轮代码实现。

## 1. 总体边界

- 新建页只负责收集原始文字、图片、链接或场景资料，并完成类型、标题、核心内容和隐私确认；不在新建页要求填写完整业务表单。
- 通用编辑器采用一个统一外壳，根据来源切换文字、图片、链接三种内容模块。
- 深度编辑器共四类：房源、商品/团购、服务方案、电子名片。
- 编辑器只负责把内容做好；客户反馈统一进入雷达，标签/合集归入资料工作区，分享话术/海报归入分享确认页。
- 所有可分享资料默认接入基础 SCRM 行为记录，不在编辑器显示“开启轻 CRM”等技术开关。
- 内容创建、卡片生成、分享和生成同款免费；客户身份、完整轨迹、客户档案和跟进为会员权益。

## 2. 通用编辑器

### 2.1 文字资料

- 主字段：自动生成但可修改的标题、正文；摘要由系统自动生成，不作为默认输入字段。
- 无图时使用排版型文字封面，不使用空白图片占位或无意义插画。
- 三种展示：资料库紧凑文字卡、客户专业阅读页、微信自动文字封面。
- 客户页主操作是咨询；标题下保留轻量生成同款，正文底部只显示一行：`也想做这样的资料？ 免费生成同款 →`。

### 2.2 图片资料

- 主字段：1～9 张图片、排序/删除/追加、自动标题、选填补充说明；第一张默认封面。
- OCR 用于搜索、标题/摘要生成和隐私检测，不默认把 OCR 全文重复展示给客户。
- 长图在客户页完整展示；分享封面使用等比缩略或安全裁切，可在预览阶段调整取景。
- 系统识别到房源/商品只提示切换深度类型，不自动生成第二份资料。

### 2.3 文章链接

- 链接卡展示原文标题、封面、来源、销售推荐语和系统生成简介，不复制第三方全文。
- 客户页主操作为“查看原文”，同时保留咨询销售。
- 雷达分别记录打开本站链接详情页和点击查看原文；后者属于更高价值信号。

## 3. 裂变与分佣展示

- 普通微信分享封面保留轻量利益提示，例如：`免费用你的资料生成这样的卡片 →`，但不显示“由资料整理助手提供”。
- 客户页只保留标题下轻入口与正文底部单行入口，不做阅读中间弹窗或悬浮推广。
- 分享确认页向原作者明确提示：他人通过该资料生成同款并开通会员后，原作者可按既定规则获得分佣。
- 第一版不提供“允许复制公开内容 / 仅复用样式”的作者选择，避免增加系统复杂度。
- 生成同款必须剥离原作者身份、联系方式、客户数据、统计、私密字段和原 shareId，并创建新的归属与追踪链路。

## 4. 房源深度编辑器

### 4.1 目标与页面层级

- 客户能快速判断房源是否值得咨询；销售能快速发送、预约并回看意向信号。
- 编辑器顺序：客户实时预览、房源图片、核心信息、房源亮点、更多房源信息、公开位置与腾讯地图、仅自己可见的房源管理、保存并预览。
- 不在房源编辑器展示客户反馈、消息中心、SCRM 开关、海报、话术、标签、工作流步骤或浮动保存按钮。

### 4.2 租售与字段

- `transactionType` 为单选枚举：`rent | sale`；界面默认只展示当前值，点击后再选择出租/出售。
- 出租字段：租金、押付方式、水电物业、入住时间、客户服务费。
- 出售字段：总价、自动计算单价、朝向、楼层/电梯、装修、产权/税费说明。
- 公共核心字段：小区/楼盘、系统生成展示标题、户型、面积、商圈/区域、3～5 个亮点、补充说明、房源状态。
- “小区/标题”拆分；具体楼栋和房号不得进入公开标题。

### 4.3 腾讯地图与隐私

- 客户页显示腾讯地图预览，并提供“导航到小区/楼盘公共位置”；不得公开具体楼栋、单元、房号和密码。
- 公开位置保存小区/楼盘名称、公开地址、公共坐标和导航文案。
- 私密位置保存具体楼栋、单元、房号、精确地址/坐标、密码锁和带看备注，只允许房源所有者查看和导航。
- 上游联系人、电话/微信、上游佣金、具体房号、密码锁、看房备注、私密备注和来源链接统一折叠在“仅自己可见 · 房源管理”。
- 客户服务费与上游佣金必须分字段保存，前者可公开，后者绝对私密。

### 4.4 新建页边界

- 系统先从文字、图片或聊天内容识别出租/出售、小区、价格、户型、面积、图片、亮点和隐私信息。
- 新建确认页只确认类型、核心字段、图片和隐私归属；其他信息进入深度编辑器渐进完善。
- 默认客户动作：咨询房源、预约看房；提交预约时再收集称呼、联系方式、意向时间和选填备注。

## 5. 商品 / 团购深度编辑器

### 5.1 销售方式与范围

- 商品展示和团购接龙共用一个编辑器，销售方式为单一枚举：`inquiry | relay`，界面只显示当前方式，点击后再切换。
- `inquiry` 只产生咨询购买信号；`relay` 允许客户选择规格、数量并提交接龙。
- 第一版不接商品在线支付，不展示“立即付款”、待付款、退款、物流、优惠券或复杂订单状态；会员费支付与商品交易严格分开。
- 接龙记录负责规格、数量和履约状态，客户雷达负责客户身份、行为和跟进，两者通过客户/线索标识关联；提交接龙属于最高优先级客户信号。

### 5.2 编辑器结构

- 页面顺序：客户实时预览、商品图片、核心信息、价格与规格、商品亮点、商品说明、配送与自提、接龙设置、自提腾讯地图、仅自己可见的进货与管理、保存并预览。
- 商品主字段：商品名称、一句话卖点、1～9 张图片、简单规格、售价、有货/售罄、3～5 个亮点、选填说明。
- 默认单一价格；用户点击“添加规格”后逐行填写规格名、价格和库存状态，不实现属性组与笛卡尔积 SKU。
- 履约方式按选择动态出现快递、同城配送、到店/小区自提或线下联系字段；自提可配置腾讯地图导航。
- 团购接龙才显示截止时间、可售数量/售完即止、选填限购和履约说明。

### 5.3 公开与私密数据

- 客户售价、公开库存提示、配送/自提说明可公开。
- 供应商、供应商联系方式、进货成本、利润备注、内部库存、采购链接和私密说明统一折叠在“仅自己可见 · 进货与管理”。
- 客户参与接龙时再收集称呼、联系方式、规格、数量、履约方式和选填备注；浏览商品不强制留资。
- 生成同款不得复制供应商、成本、利润、内部库存、接龙名单、客户数据或原统计链路。

### 5.4 已认可的高保真结构

- 顶部实时预览使用商品主图、商品名、`¥xx 起`、一句话卖点和当前销售方式标签。
- 核心信息与简单规格保持紧凑；配送、自提、接龙和私密管理使用渐进展开。
- 底部只保留弱化的删除操作和主按钮“保存并预览”。
- 商品客户页与分享封面继续保留轻量生成同款；分享确认页继续展示原作者分佣利益。

## 6. 服务 / 合作通用编辑器

### 6.1 产品边界

- 用户入口统一命名为“服务/合作”，底层继续使用 `service_offer`；不再区分咨询、物流、贸易、代账等行业子类型。
- 资料整理助手只负责把已有服务资料展示清楚并记录客户兴趣，不替代行业业务系统，不为各行业建立细颗粒度字段。
- 已废弃此前“适合人群、你将获得、流程、案例、资质、地图、内部 SOP”等专业服务深度稿；不得把该稿作为开发验收标准。

### 6.2 字段与附件

- 主字段：服务/合作名称、一句话介绍、选填详细说明。
- 选填字段：服务范围、价格或合作条件。
- 资料附件支持图片、PDF 和外部链接；专业颗粒度由用户已有 PDF、长图、介绍材料和链接承载。
- 联系方式统一读取“我的”个人资料，不在每份服务资料中重复填写。
- 未填写的选填字段和空模块在客户页直接隐藏，不显示“待完善”占位。

### 6.3 SCRM 行为

- 记录服务页打开、复访、停留、图片查看、PDF 点击、链接点击和咨询动作。
- 微信文档预览只能可靠记录 PDF 被点击/打开，不能宣称客户看到第几页、读完或逐页停留。
- 客户主操作统一为“咨询详情”；编辑器只展示基础能力提示，不提供 SCRM 开关。
- 生成同款不得复制客户数据、附件访问记录、原统计链路和原作者身份信息。

## 7. 电子名片

### 7.1 定位与字段

- 电子名片是“人作为销售资产”的个人主页；服务/合作介绍业务，名片介绍人并承接联系和精选资料。
- 第一版每个用户只有一张主电子名片，个人身份与联系方式以“我的”个人资料为唯一来源，名片及其他资料统一读取。
- 必要字段：头像、姓名、职位/身份、一句话介绍。
- 选填字段：公司/门店、服务范围/服务关键词、所在城市、个人介绍、微信二维码、手机号；邮箱、网址等归入“更多联系方式”。
- “我能提供”只保留 2～6 个关键词，不在名片内重复维护服务价格、流程和方案内容。
- “精选资料”最多关联 3 项已有资料，可为服务/合作、房源/合集、商品、文字、图片、PDF 或链接；名片只引用，不复制原内容。

### 7.2 客户页、分享与行为信号

- 客户页以头像、姓名、身份、一句话介绍和联系按钮为第一层，按有无数据显示“我能提供、关于我、精选资料”。
- 微信分享封面以人为主视觉，显示头像、姓名、身份、服务关键词和轻量“免费生成你的电子名片”。
- 记录打开/复访、查看二维码、点击拨号、点击咨询、打开精选资料/PDF/链接；只能表达“查看二维码”或“点击拨号”，不能宣称已加微信或已通话。
- 电子名片生成同款固定清空原姓名、头像、公司、职位、电话、二维码、个人介绍和精选资料，只保留视觉结构，并优先读取新用户自己的个人资料。

### 7.3 四个轻样式

- 名片提供 4 个轻样式：`商务蓝`、`简洁白`、`暖灰金`、`清新绿`。
- 四种样式使用完全相同的字段、模块顺序、客户动作、SCRM 事件和分享归因，仅改变主色、背景、头像布局、分隔方式和轻装饰。
- 默认使用“商务蓝”；用户可在编辑页顶部预览旁通过“换样式”打开四宫格小预览并即时切换。
- 切换样式不得修改、补写或清空任何用户内容，不弹出“使用模板默认内容”等选择，不创建新名片，也不重置统计。
- 资料库卡片保持统一列表风格；样式主要作用于客户名片主页和微信分享封面，避免资料库列表视觉碎片化。
- 4 种样式全部免费，不建立模板商城或付费皮肤。

## 8. 开发前统一核对

1. 统一五类编辑器的数据契约、路由和同一 `UserNote` 更新规则，防止切换类型或样式后重复创建资料。
2. 统一图片、PDF、链接附件模型与公开/私密标识，明确大小、数量、格式、上传失败和删除规则。
3. 统一客户页、微信分享封面、生成同款和邀请/分佣归因字段。
4. 统一“我的”身份资料与电子名片、房源、商品、服务联系方式的单一数据源和同步规则。
5. 开发前先补测试清单，开发完成后统一做对抗式审查，重点验证数据隔离、附件事件、样式切换和生成同款剥离。
