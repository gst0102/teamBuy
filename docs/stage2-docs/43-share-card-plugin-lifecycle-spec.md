# 分享卡插件与发布发送链路规格

## 1. 目标

资料发布后，客户页链接可以立即打开；微信好友/群分享只有在当前资料版本的静态分享图已生成、上传、校验并保存后才允许进入原生发送面板。

“发布、生成、校验、发送”必须是一条有明确状态和版本边界的链路，不允许页面在没有有效 `imageUrl` 时退回微信默认页面截图。

## 2. 唯一插件边界

现有 `miniprogram/plugins/share-snapshot/index.js` 升级为唯一分享卡插件。资料库、资料列表、客户页、合集、名片和服务方案页面不得直接调用 Canvas 绘制器或自行拼接分享参数。

插件统一负责：

- 场景资料归一化；
- 唯一 `ShareCardModel`、Canvas 导出入口和内部布局策略；
- `sourceRevision + fingerprint + styleId` 版本校验；
- 同实体同版本并发合并；
- Canvas 导出、媒体上传和后端快照保存；
- `missing / preparing / ready / stale / failed` 状态；
- 当前快照读取、失败重试和微信分享参数构造。

页面只负责传入实体、展示状态和在 `ready`/`direct` 时提供 `open-type="share"`。

## 3. 统一视觉母版

所有分享动作使用同一套 `ShareCardModel` 和分享插件入口。名片使用专用 Canvas；非名片有主图时直接复用原图，没有主图时由插件按类型生成固定信息卡。这不是让所有场景强行使用一张通用版式。页面不得各自实现 Canvas，也不得把名片压扁成普通资料的文本块。

模型至少包含 `layoutId`、`title`、`badge`、按原始顺序排列的 `blocks`（`text` / `image`）、`primaryImageUrl` 和真实业务 `facts`。普通资料不能再由渲染器补写“可收藏 · 可转发”“内容信息卡”等固定内容；渲染器只绘制模型已有内容和布局策略允许的品牌元素。

- 普通资料、单图资料、房源、商品、服务和合集：只要有真实主图，统一使用 `original_media`，直接复用原图；标题、价格、户型、面积等字段放在微信原生标题和详情页，不再给原图套 Canvas 外壳；
- 没有主图的非名片资料：由插件按资料类型生成固定信息卡，最多两行标题、两行摘要、三个字段位，超出使用省略号，保存为当前版本快照后分享；
- 名片：头像、姓名、身份、公司、联系入口和名片专用视觉母版；名片必须保留“人和联系方式”的组合结构，不能退化成普通资料的标题 + 主图；
- 合集有封面时直接复用封面，没有封面时由插件生成 `showcase_info` 固定信息卡，不允许无 `imageUrl` 触发微信页面截图。

有真实主图的非名片场景默认使用 `original_media`：分享插件直接复用已登记的本系统媒体 URL，不绘制、不二次压缩、不重新拼接。该模式仍必须执行 owner、发布状态、revision、fingerprint、styleId 和托管媒体 URL 校验；名片仍使用同一插件内的专用 Canvas 布局。

当前分享版本为 `share_card_v7`。无图资料按 `text_info`、`image_info`、`link_info`、`property_info`、`product_info`、`service_info` 生成固定信息卡；合集无封面使用 `showcase_info`；旧的 `property_summary`、`image_single`、`resource_default` 快照不能继续作为当前发送图。

## 4. 状态机

```text
missing -> preparing -> ready
                    \-> failed -> preparing
ready + 版本变化 -> stale -> preparing
```

状态来源优先级：

1. 当前实体的服务端 `shareSnapshot`；
2. 插件同页面内存中的同版本任务；
3. 插件失败记录和可重试时间；
4. 不能用单独的 `shareImageReady` 布尔值替代状态判断。

`ready` 必须同时满足：

- `status=ready`；
- `url` 是本系统可访问的媒体地址；
- `sourceRevision` 等于当前资料版本；
- `fingerprint` 等于当前场景内容和媒体指纹；
- `styleId` 属于当前分享卡母版版本；
- 当前用户、实体和接口环境匹配。

`direct` 只适用于有真实主图的非名片资料，必须携带该主图 `imageUrl`；无主图资料必须经过 `missing -> preparing -> ready` 快照流程，并受发布状态、实体归属、当前 revision 和公开路径校验约束。

## 5. 业务流程

### 5.1 发布

```text
保存资料
  -> 服务端安全校验
  -> shareState=published、revision+1
  -> 客户页链接立即可用
  -> 插件后台预热当前版本分享图
```

发布不等待图片生成完成，但发布成功后必须立刻启动预热任务。客户页在预热期间显示资料内容和“分享图准备中”，不打开原生分享面板。

### 5.2 生成

插件根据资料类型生成统一 `ShareCardModel`。只有名片调用 Canvas 渲染器；非名片有主图时直接复用已登记原图 URL。需要保存快照时，按以下顺序执行：

```text
Canvas 导出临时文件
  -> 上传媒体
  -> 校验返回地址
  -> PATCH 当前版本快照
  -> 再次读取并校验快照
  -> 状态变为 ready
```

任何一步失败都不能保存临时 `wxfile://` 地址，也不能删除旧的有效快照。

非名片无主图时由插件生成对应类型的信息卡并保存快照；分享回调必须返回快照 `imageUrl` 和客户页路径，不能让微信自动截取资料库或详情页。

### 5.3 校验

编辑、重新发布、媒体变化或模板版本变化时，旧快照变为 `stale`。页面只能使用当前版本快照，不能因为 URL 存在就继续发送旧图。

公开客户页只返回当前版本的快照元数据；版本不匹配的快照从公开响应中移除。

### 5.4 发送

原生微信分享按钮只在 `ready` 或非名片 `direct` 状态渲染：

- `ready`：显示“好友/发客户”，允许 `open-type="share"`；
- `direct`：显示“好友/发客户”，不附加不存在的 `imageUrl`；
- `missing/stale`：显示“准备分享图”，调用插件生成；
- `preparing`：显示进度，不打开微信面板；
- `failed`：显示“重试分享图”；
- 回调再次校验实体 ID、revision、fingerprint 和 URL，缺图时不构造默认无图分享。

不能让一个点击同时启动异步生成和原生分享面板。冷启动时允许用户先准备、后发送；正常路径由发布后的预热任务保证一键发送。

## 6. 性能和并发

- 同一实体、用户、版本、样式和指纹使用插件级 in-flight 合并；
- 资料库只预热可见卡片，不能一次串行生成整个资料库；
- 列表先展示元数据，不等待分享图；
- 当前有效快照优先复用，版本变化才重生成；
- 失败任务保留可重试状态，不循环自动重试；
- 本地内存缓存必须按环境、接口地址、用户、实体和版本隔离。

## 7. 安全边界

- 分享图保存接口继续要求 owner、已发布状态和精确 `sourceRevision`；
- 分享图 URL 必须属于本系统媒体存储；
- 不把客户手机号、微信号、雷达数据或私密字段写入分享图源数据和本地持久化缓存；
- 分享图只展示客户公开内容；
- 资料停止分享、删除或版本变化后，旧图不能继续作为当前发送图。

## 8. 验收标准

1. 新发布资料客户页可以立即打开；分享图完成前不能打开微信发送面板。
2. 文字、图片、链接、房源、商品、服务、名片和合集均由同一个插件进入生成与发送；名片和无图类型化资料/合集使用 Canvas，其他有主图场景直接复用原图，无图场景必须生成当前版本快照。
3. 资料库、资料列表、客户页和合集入口发送出的当前版本缩略图一致。
4. 微信聊天卡片不出现资料库页面截图、默认页面截图或无图卡片。
5. 编辑后、重新发布后和模板升级后旧图自动失效并重新生成。
6. 图片资料的二维码、竖图和人物主体不被裁剪；无图资料不伪造默认缩略图。
7. 生成失败显示可理解的失败状态和重试入口，不永久显示“准备中”。
8. 后端测试覆盖当前快照、旧版本快照、非法地址、非 owner、未发布资料和发布状态变化。

## 9. 实施顺序

1. 扩展现有 `share-snapshot` 插件，集中场景适配、状态和生成入口。
2. 资料库、资料列表、客户页改为只调用插件。
3. 合集、名片、服务方案和旧卡片入口接入同一插件和同一 `ShareCardModel`。
4. 移除页面级 Canvas 生成、按类型分叉的旧渲染器和无图分享兜底。
5. 增加版本/样式/指纹回归测试，再进行微信开发者工具真机验收。
