# 互帮互助角色页面 V2 设计方案

## 结论

分享好友的入口和发布者管理入口不应打开同一套操作页面。

- 分享链接默认进入“执行者任务详情”：好友只需要理解任务、打开目标小程序、提交材料。
- 发布者从“我的”进入“发布者任务管理”：发布者需要查看进度、处理提交、通过结算或要求补交。
- 两个页面共享同一份 `MutualTask` 数据，但使用不同的操作权限和状态投影。

## 1. 当前分享卡为什么看起来没有渲染成功

当前微信聊天里的卡片并不是没有生成，而是使用了微信默认的页面截图。现有 `onShareAppMessage` 返回了标题和详情路径，但没有任务专用的 `imageUrl`，所以微信截取了任务详情长页面作为卡片缩略图。

这会带来三个直接问题：

1. 截图包含顶部 Tab、主题切换、连接浮层等页面内容，不像一张任务卡。
2. 页面很长，聊天卡片缩放后标题、验收标准和按钮都不可读。
3. 分享卡的展示内容无法稳定表达奖励、剩余次数和“点击完成”的核心信息。

这不是继续调整详情页间距能够根治的问题。根因是“分享预览图”和“业务详情页”被当成了同一个视觉产物。

## 2. 两个页面的职责

### 2.1 执行者任务详情

页面唯一目标：让执行者能够安全完成一次任务。

信息顺序（按任务类型显示）：

1. 任务标题、任务类型、奖励积分、剩余次数和截止状态；
2. 完成路径：小程序任务为打开目标小程序 → 返回提交；普通任务为按标准完成 → 提交材料；羊毛为查看说明 → 使用福利；
3. 任务说明；
4. 普通任务显示验收标准，羊毛显示解锁/查看规则；
5. 小程序任务显示目标入口和提交材料，普通任务显示提交材料，羊毛显示福利入口和可选打赏；
6. 固定底部主按钮。

执行者页面不显示：发布者的待验收列表、结算按钮、暂停任务按钮、发布者积分管理入口。

### 2.2 发布者任务管理

页面唯一目标：让发布者能判断提交是否符合标准，并管理任务是否继续开放。

信息顺序：

1. 任务状态、任务标题、每次消耗/奖励和剩余次数；
2. 已完成、待验收、剩余数量三个进度数字；
3. 待验收提交列表；
4. 查看任务说明和验收标准；
5. 分享任务、暂停发布等管理动作。

发布者页面不显示执行者的“打开目标小程序”“提交完成”或“领取福利”主按钮；羊毛管理页也不显示验收区。

## 3. 分享和路由

推荐路由：

```text
好友点击分享卡
  → /subpackages/my-tools-mutual-help/task-detail/index?id=<taskId>&source=share
  → 执行者任务详情
  → 点击目标小程序卡片
  → wx.navigateToMiniProgram({ shortLink })
  → 返回后提交完成

发布者从“我的”点击自己的任务
  → /subpackages/my-tools-mutual-help/task-manage/index?id=<taskId>
  → 发布者任务管理
```

分享链接不能根据客户端传入的 `ownerUserId` 决定页面权限。正式版必须由服务端根据登录用户和任务所有权返回 `viewerRole=owner/executor`，并在服务端校验发布者的验收动作。

## 4. 专用任务分享图

分享回调仍然分享“资料整理助手”这个小程序，但需要返回任务专用的固定比例分享图：

- 比例固定为 5:4，输出 JPG/PNG；
- 顶部显示“互帮互助任务”；
- 中部显示任务分类、标题；小程序/普通任务显示完成奖励，羊毛显示免费查看或解锁费用；
- 下部显示剩余次数或“长期开放”；
- 不放任务详情页的 Tab、主题设置和提交输入框；
- `path` 只指向执行者任务详情页；
- 任务关闭、删除或过期时，分享入口必须失效或显示已结束状态。

目标小程序的原生分享卡不能由资料整理助手伪造。详情页里的“目标小程序”仍是本项目自己的可点击卡片，负责调用 `wx.navigateToMiniProgram`。

## 5. 第一性原理验收条件

- 执行者打开分享链接后，第一屏能看到“要做什么/能获得什么、还剩多少”；羊毛需要明确是免费查看还是付费解锁，不把它误导成有固定完成奖励的任务。
- 执行者不用进入发布者页面就能完成一次任务。
- 发布者不用进入执行者页面就能看到待验收提交并进行处理。
- 分享图不再使用详情页长截图；聊天卡片标题、奖励和任务状态可读。
- 未知任务 ID、已下架任务、非任务所有者的管理路径都不能静默展示错误任务或开放管理动作。

## 6. 当前实现边界

本方案已进入小程序本地演示实现，但不代表正式服务端和真机链路已经完成。当前互帮互助仍主要使用本地演示数据，正式上线前还需要：

- `MutualTask` 服务端发布、详情和分享查询接口；
- 执行者提交、发布者验收、补交和积分流水接口；
- 任务内容/验收图片的媒体资产登记和权限；
- 任务分享图生成与快照版本校验；
- 真实微信好友打开、目标小程序跳转和返回提交验收。

## 7. 页面实现跟进（2026-08-31）

- 顶部 `任务` Tab 已切换为发布者任务管理列表；执行者完成任务后只从自己的大厅过滤掉，不会删除全局任务。
- 发布成功后进入发布者管理详情；分享和“查看执行者页面”进入执行者详情。执行者详情不再显示四个模块 Tab，发布者访问执行者页时只读，不能领取或提交自己的任务。
- 发布者管理详情已提供任务状态、已完成/待验收/剩余进度、任务内容和验收标准预览，以及暂停/恢复发布和分享入口。待验收列表当前保留本地演示空态，真实提交接口接入后再展示执行者提交。
- 主要页面卡片、表单分区和内容段分隔线统一提升为 `2rpx`；深色模式同步覆盖边界颜色。
- 本轮已接入任务专用分享图：两个任务详情角色页共用现有分享快照插件，生成固定 `750×600` JPG 并上传到 `/api/uploads/share-snapshot`；图片准备完成前隐藏/禁用分享入口，回调没有可用 `imageUrl` 时不返回分享对象，避免微信退回默认页面截图。
- 任务分享快照目前随本地演示任务保存，尚未有 `MutualTask` 服务端详情、分享 token 和快照持久化接口；因此同一设备的本地演示链路可以使用专用 `imageUrl`，跨设备好友打开仍需下一阶段后端任务查询。

## 8. 任务分享图实现跟进（2026-08-31）

- `task-share.js` 统一生成任务分享源：小程序任务使用信息卡，含图片的普通任务使用图片优先卡；卡片展示任务类型、标题、执行者奖励、剩余次数和截止信息。
- 发布者管理详情和执行者详情都挂载 `shareCardCanvas`，生成完成后保存 `shareSnapshot` 元数据（样式版本、源版本、指纹、公开图片地址）到当前本地演示任务。
- `onShareAppMessage` 统一返回执行者详情路径和任务专用 `imageUrl`；未登录、生成失败、地址不可用或快照过期时直接阻止分享，不允许默认详情页截图兜底。
- 这不是目标小程序的原生卡片。目标小程序仍由执行者详情中的本项目卡片调用 `wx.navigateToMiniProgram` 打开。

## 9. 多任务入口实现跟进（2026-08-31）

- 任务详情统一展示 `taskLinks`。小程序短链接使用 `wx.navigateToMiniProgram`，普通任务同样可以包含小程序入口，但仍按普通任务的材料验收规则处理。
- 已配置业务域名的 HTTPS 入口进入专用 `web-view` 页面；未配置的 HTTPS 入口复制到剪贴板，并明确提示用户使用手机浏览器打开。当前仅允许 `teambuy.lifelove.top` 进入 `web-view`，不自动放行第三方域名。
- 发布者管理详情和执行者详情都可以打开入口；`isOwner` 只影响领取、提交和结算，不影响验证入口。
- 本轮只完成本地演示的前端入口编排和旧 `shortLink` 兼容，尚未完成服务端任务查询、跨设备链接访问、第三方业务域名校验和微信真机验收。

## 10. 羊毛任务页面与互动跟进（2026-08-31，修订）

- 发布者页面的羊毛策略只配置查看方式和使用后可选打赏开关；不配置固定完成奖励，也不显示验收标准字段。
- 羊毛详情按“摘要/评论 → 解锁 → 完整福利说明/使用入口 → 可选打赏”的顺序组织；解锁费用仅在明确确认后扣除，同一任务只收费一次。
- 羊毛不显示提交材料、发布者验收或 5 天自动通过；普通任务继续显示验收标准并进入提交/验收流程。
- 普通任务和羊毛任务的详情页均展示评论摘要、推荐标签和举报入口；发布者管理详情增加评论列表以及待处理举报/退款提示。
- 首页任务大厅新增羊毛筛选，并保留用户自己发布的未删除任务，避免“我发布后大厅看不到”与产品核心预期冲突。
- 分享源对羊毛只显示免费查看/解锁费用、可选打赏和剩余信息，不公开付费完整内容；分享仍指向本项目任务详情并要求专用静态 `imageUrl`。
