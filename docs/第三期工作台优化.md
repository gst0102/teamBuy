# 第三期工作台优化交接归档

更新时间：2026-06-25
项目：teamBuy / 资料整理助手
当前分支：`main...origin/main [ahead 18]`

## 1. 项目背景与目标

`teamBuy` 当前正式产品方向是“资料整理助手”。产品不是单一资料库，而是以“企业微信导入 + 小程序整理 + 客户页分享 + 客户反馈回流”为基础，逐步扩展为多个独立场景工作台。

长期架构原则：

- 稳定基座负责企业微信通信、内容归档、用户身份、资料库、展示页、客户动作、看板和支付权益。
- 具体业务场景通过可插拔的 Skill / 工作台承载，例如房源、团购商品、电子名片/服务方案。
- 小程序端要避免“只是换皮”，每个工作台必须有自己的资料类型、首页统计、资料库过滤、客户看板语境、详情页和分享前检查。
- 企业微信导入内容进入系统后，必须正确识别场景并归属到当前用户；低置信度不能强行写入错误业务类型。

第三期工作台优化的核心目标：

- 把首页、资料库、合集、客户看板从通用资料模式推进为多工作台模式。
- 让房源、团购/商品、电子名片/服务三个场景都具备独立的业务心智和基础闭环。
- 修复用户真机测试中暴露的 UI 排版、资料隔离、模板一致性、保存后资料可见、客户页分享和看板统计问题。

## 2. 当前阶段目标

当前阶段重点已经从“能创建资料”推进到“每个工作台能独立完成业务闭环”：

- 房源工作台：房源资料、客户看板、访客/跟进数据、房源筛选标签只在房源场景出现。
- 团购/商品工作台：商品资料、接龙/订单、商品合集、普通下单和接龙名单处理。
- 电子名片/服务工作台：电子名片、服务方案、客户页预览、咨询/预约回流、案例合集。
- 首页底部工作台入口已经从“工作台”改为“客户看板”，工作台切换主要通过首页和我的入口承担。
- 本阶段结束前的主要状态是：三类工作台的 P0/P1 主链路基本完成，剩余重点是用户真机复测、UI 细节收口和下一个新工作台启动。

  - 团购分数高于房源分数。
  - 命中商品、价格、取货、规格、截止、接龙等信号。

  - 只有普通下单：显示“处理订单”。
  - 只有访客、无订单：不显示处理按钮。

- 商品合集编辑页底部按钮布局多轮修复，最终按块盒、等分、留 margin、宽度 100% 的方式收口。
