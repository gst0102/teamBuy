## 1. 项目背景与目标

`teamBuy / 资料整理助手` 已经从早期“资料整理工具”升级为更接近私域经营和成交辅助的系统。

当前核心表达可以理解为：

> 资料发出去，机会看得见。

产品希望帮助用户完成以下闭环：

1. 把微信群、企业微信、手动输入、图片、链接里的信息整理成资料。
2. 把单条资料或多条资料打包成可分享页面。
3. 发给客户后看到打开、反馈、留资、预约和客户动态。
4. 通过雷达页判断谁值得跟、为什么跟、下一步怎么跟。
5. 通过资源工具找到更多渠道和企业线索。
6. 后续通过企业微信群运营、小程序承接和群资源入口形成增长飞轮。

长期架构仍遵循 `AGENTS.md` 和 `docs/stage2-docs/08-plugin-architecture.md`：

- 稳定基座：企业微信通信、会话存档、身份、支付/积分、笔记库、展示页、权限。
- 可插拔能力：内容整理、资料卡、客户雷达、企业资源搜索、群资源库、机器人网关等。
- 用户身份锚点：小程序微信 `openid`，企业微信身份只作为来源映射。
- AI 只做识别、建议和兜底，不直接越权写库、扣费、发通知或查询他人数据。

## 2. 当前阶段目标

第六期的阶段目标是把产品从“功能堆叠”收成“用户一眼知道下一步做什么”的工作台体验。

已经明确的五个 Tab 首屏心智：

- 首页：今天先做什么。
- 资料：哪些资料适合发客户。
- 合集：把多条资料打包成一页。
- 雷达：谁值得跟进。
- 我的：资料、资源、消息和个人资料入口。

当前更具体的阶段目标：

1. 五个 Tab 视觉和文案收口，减少说明书感。
2. 房源场景保留必要高密度标签，非房源场景更轻、更适合直接转发。
3. 雷达页从“复制话术”转向“看详情、看轨迹、看联系方式、判断是否跟进”。
4. 我的页不做后台菜单，而是保留身份、资源工具、当前场景、内容入口、帮助反馈。
5. 资源工具成为后续增长补给站：群资源库、企业资源搜索、行业黄页/行业资源后续开放。
6. 企业微信机器人先做权限网关和内部/企业群辅助，不强求进入外部客户群。
7. 群资源加群路径先研究和设计清楚：我们自己的企业微信群走官方小程序加群，第三方微信群走群二维码 + 邀请人个人二维码兜底。

### 3.2 无图资料卡与轻设计卡

已确认并部分落地：

- 很多群发、合作信息、资料整理内容天然没有图片，不能只用单字占位。
- 无图时采用轻设计卡：以标题重点词作为视觉主体。
- 资料卡和合集卡仍需保留“打开小程序看完整内容 / 输入同款继续问”这类传播引导，但降低视觉权重。
- 日常资料、名片、服务方案等非房源卡需要重点测：
  - 左侧文字图居中。
  - 不压右侧标题。
  - 长标题不炸布局。
  - 按钮文字居中。

已多次修正资料列表小屏重叠问题：

- 保持列表卡整体垂直居中。
- 左侧轻设计卡使用固定宽高和 `box-sizing: border-box`。
- 左右区域通过列宽、间距和安全边距处理，不再让左图和右标题重合。

### 3.7 群资源积分规则口径

已确认的群资源积分方向：

- 新用户资源积分示例为 100 分。
- 查看群二维码会消耗积分，当前 MVP 文档为 30 分。
- 发布群资源奖励先进入冻结积分，不立即到账。
- 第三方群资源新增轻量确认规则：
  - 有 2 个不同用户点击“我已进群”且期间没有投诉，释放积分。
  - 如果未满 2 个确认，但 7 天内没有投诉，也释放积分。
  - 后台人工确认有效，也可以释放积分。
  - 2 个及以上用户投诉“没拉我 / 进不了群 / 二维码失效”，冻结积分不释放，并标记异常。
  - 多次异常的发布者，后续发布进入人工审核。
- 后续前台文案建议：
  - `发布成功后奖励进入冻结积分。2 人确认进群，或 7 天内无投诉后自动到账。若多人反馈无效，积分不释放。`

### 3.14 企业微信智能机器人权限网关 MVP

### 3.15 WorkBuddy / 企业微信机器人测试结论

已确认：

- WorkBuddy 智能机器人在企业微信内部会话/内部群中可以工作。
- API 插件 `resource_query` 能调用我方后端网关。
- 会话存档和机器人回复是两条不同路径：
  - 会话存档：负责记录、归档、生成资料，不主动回复。
  - 智能机器人：用户私聊或群里 @ Bot 时，调用插件并回复。
- 外部真正的客户群目前不能稳定拉入 Bot；不要把“外部群直接 @ Bot 自动运营”作为当前主链路。

已确认的新运营分工：

- 外部群由运营本人负责引流和转化。
- 会话存档负责收集外部群内容和群 ID。
- 机器人负责根据归档内容生成运营建议、群日报、话术和资源推荐。
- 企业微信成员最终确认并转发到对应客户群。
- 小程序负责承接和沉淀。

一句话：

> 外部群做增长，企业群做留存，小程序做转化。

## 6. 已知问题和风险

### 6.1 工作树过脏

当前最大工程风险是本地改动太多、未跟踪文件太多。

规避：

- 先按功能域分组检查。
- 不要粗暴清理。
- 不要把 `.env`、密钥、生产数据、媒体目录提交。
- 若要部署，继续采用“备份 + 定向同步 + 重建镜像 + 回滚标签”的稳妥方式。

### 6.2 资源积分还没真正后端化

风险：

- 群资源库、企业资源搜索、帮助反馈奖励都在谈积分。
- 当前前端本地积分不具备跨设备、防刷、防作弊、申诉和后台处理能力。

下一步必须做：

- 后端 `resource_points` 余额。
- 冻结积分。
- 积分流水。
- 释放/扣罚/退分。
- 投诉和人工确认。
- 同一资源重复查看不重复扣分。
- 企业查询 24 小时缓存不重复扣分。

### 6.3 群资源存在风控和信任风险

风险：

- 群二维码过期。
- 第三方群人数满或无法扫码进。
- 发布虚假群、广告群、敏感群。
- 用户投诉“没拉我 / 进不了群 / 群不对”。

已确认的规避方向：

- 第三方群资源必须支持群二维码 + 邀请人个人二维码。
- 每张卡显示更新日期。
- 奖励先进冻结积分。
- 2 人确认或 7 天无投诉再释放。
- 2 个及以上投诉标记异常。
- 多次异常用户后续人工审核。

### 6.4 外部群机器人能力不能假设可用

已确认：

- WorkBuddy Bot 在企业微信内部和内部群可用。
- 真正外部客户群目前不能稳定拉入 Bot。

规避：

- 外部群不要设计成直接 @ Bot 自动回答。
- 外部群用会话存档收集内容，用机器人生成运营建议，再由企业成员确认发送。
- 企业群可以用 Bot 做稳定播报和内部辅助。

### 6.5 天眼查接入通道限制

已确认：

- 当前可用的是天眼查 MCP。
- REST OpenAPI `searchV2` 曾返回无权限。

规避：

- 前端只调我方后端。
- key 只放后端环境。
- 深度查询按 MCP capabilities 逐步接，不猜工具名。

### 6.6 UI 真机风险

高风险区域：

- 资料列表无图轻设计卡。
- 雷达页客户卡按钮。
- 群资源库搜索框和短按钮。
- 资源工具九宫格。
- iPad / 小屏手机下数字、胶囊、按钮居中。

规避：

- 所有按钮、标签、胶囊必须 flex 居中。
- 小程序核心尺寸使用 `rpx`。
- 列表卡固定列宽、间距和 `min-width: 0`。
- 真机截图优先，模拟器只能辅助。

### 6.7 文案过多风险

用户已经多次反馈页面文字偏多。

已确认：

- 五个 Tab 顶部一句话只回答“这个页面帮我干什么”。
- 不在首屏写长说明。
- 未实现功能不要写 `后续 / 预留 / API Key / 后端 / 部署 / 本地测试` 等工程词。

## 7. 用户已经确认过的产品/技术决策

### 7.1 产品主线

- 产品名继续叫“资料整理助手”。
- 当前表达从“整理资料”升级为“资料发出去，机会看得见”。
- 房源是首批尖刀场景，但架构保留四场景。
- 不急着做会员、PDF、专题、行业通讯录、行业资源的重功能，先冷启动和闭环。

### 7.2 五个 Tab

- 首页：今天先做什么。
- 资料：哪些资料适合发客户。
- 合集：把多条资料打包成一页。
- 雷达：谁值得跟进。
- 我的：资料、资源、消息和个人资料入口。

### 7.3 房源与非房源信息密度

- 房源因为价格、地铁、户型、电梯、区域等判断信息很重要，不能过度压缩。
- 非房源场景可以更轻、更酷、更适合直接转发。

### 7.4 我的页

- 我的页不做功能拼盘。
- 会员中心暂不暴露。
- 消息入口只保留一个。
- 设置与帮助先收成必要项。
- 资源库放在比较重要的位置。
- 资源工具包括群资源库和企业资源搜索。

### 7.5 群资源库

- 群资源库先从我的页资源工具进入。
- 目前不放首页、合集、资料页等更多入口。
- 群资源卡显示日期/更新时间。
- 第三方群资源必须考虑群二维码失效，所以增加邀请人个人二维码。
- 发布奖励先冻结。
- 2 人确认或 7 天无投诉释放积分。
- 2 个及以上投诉不释放并标记异常。

### 7.6 自己的官方群入口

- 自己的官方群先只在群资源库里展示。
- 文案强调官方群、每日行业资讯/资源更新。
- 等企业群日常运营跑通后，再释放到首页、合集、资料等更多路径。

### 7.7 企业资源搜索

- 不暴露天眼查全部工具。
- 第一版只做企业搜索 + 企业卡 + 高频查询。
- 搜索免费。
- 查询项冷启动阶段 5 分/项。
- 24 小时缓存不重复扣分。
- key 只放后端。

### 7.8 机器人与企业微信

- 同一个企业微信体系里，会话存档负责记录，智能机器人负责被问时回复。
- 机器人必须经过我方权限网关。
- 机器人不能直接连接数据库。
- 群里问个人资料时，提示转私聊。
- 外部客户群不能假设能直接拉 Bot；当前以“会话存档 + 机器人生成建议 + 人工发送”为主。

### 7.9 部署

- 当前阶段采用最稳部署方式：
  - 备份。
  - 定向同步。
  - 重建镜像。
  - 保留回滚镜像。
  - 不覆盖生产 `.env`、`secrets`、媒体目录和 volume。
- 稳定后必须做 GitHub 仓库归档，避免本地或服务器崩溃。
