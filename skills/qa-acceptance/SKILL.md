# teamBuy QA 验收 Skill

## 1. 使用场景

当用户要求生成测试方案、验收标准、Bug 修复任务单、回归测试清单、上线检查表，或要求对 Codex 开发结果进行 QA 验收时使用本 Skill。

AI 测试官默认不修改业务代码，只输出测试、验收、Bug 和回归材料。

如果任务涉及首页、Tabbar、工作台模式、资料库、合集、客户看板或 UI 体验，验收官必须同时读取：

- `AGENTS.md`
- `docs/project-memory.md`
- `docs/decisions.md`
- `docs/pitfalls.md`
- `docs/stage2-docs/17-home-tabbar-workspace-mode.md`

这些任务不能只验“能点击 / 不报错”，还必须验产品心智和 UI 体验是否符合文档。

## 2. P0 验收范围

必须覆盖：

- 企业微信客服回调
- sync_msg 消息拉取
- 微信笔记消息聚合
- 媒体下载和转存
- 导入成功通知
- 导入失败通知
- 待认领导入
- 小程序登录
- 卡片草稿生成
- 卡片编辑保存
- 卡片分享查看
- 电话拨号
- 字段复制
- 登录浏览用户统计
- 匿名浏览统计
- 实名接龙
- 手机号和地址附加字段
- 接龙名单管理
- 删除无效接龙
- 标记已跟进
- 素材库搜索分类
- 一键复用
- 数据隔离和回归测试

## 3. P0 风险判定

以下情况直接判定为 P0：

- 企业微信回调无法接收。
- sync_msg 无法拉取消息。
- 微信笔记无法形成卡片草稿。
- 图片或视频 media_id 未及时转存导致素材丢失。
- 导入成功但用户无法认领。
- 导入失败但没有通知用户。
- 卡片无法保存。
- 卡片无法分享。
- 群用户无法打开卡片。
- 电话拨号不可用。
- 字段复制不可用。
- 浏览统计严重错误。
- 匿名用户被错误展示为实名浏览用户。
- 接龙无法提交。
- 接龙名单团长不可见。
- 普通用户看到未脱敏昵称。
- 删除无效接龙不可用。
- 标记已跟进不可用。
- 一键复用覆盖原卡片数据。
- 密钥、Token、AppSecret 泄露到前端或 Git。

## 4. 测试用例格式

测试用例必须使用 Markdown 表格：

```md
| 编号 | 模块 | 测试名称 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 是否适合自动化 | 备注 |
|---|---|---|---|---|---|---|---|---|
```

## 5. 信息架构与 UI 体验验收

当验收首页与 Tabbar 工作台模式一期时，必须覆盖：

- 新用户首次进入是否看到“你想先整理哪类资料？”。
- 是否能选择日常资料台、房源工作台、团购工作台、服务工作台。
- 选择后 `workspaceMode` 是否生效，首页和工作台内容是否随模式变化。
- 普通用户默认是否只看到日常资料、合集、分享效果，不出现客户、线索、接龙、看房等业务词。
- 房源工作台是否突出房源、房源合集、看房客户、待跟进。
- 团购工作台是否突出商品、团购合集、接龙名单、买家记录。
- 服务工作台是否突出电子名片、服务方案、案例合集、咨询客户。
- 客户看板是否从“我的”迁出，归位到工作台反馈中心。
- 展示页 / 合集 / 单个资料是否仍能进入各自的效果或互动详情。
- 资料库是否降噪，聚焦单条资料管理、分享和加入合集。
- 合集页是否有清晰入口和空态，用户能理解“多条资料打包成可分享资料包”。
- 首页是否避免平铺全部功能，只展示当前模式最相关的 3-4 个主入口。
- 我的页是否只保留个人资料、会员权益、设置、帮助、邀请奖励等账号内容。

UI 体验验收维度：

- 第一眼是否清楚：用户 3 秒内能否知道当前是什么工作台、下一步该点哪里。
- 模式是否干净：当前模式是否混入无关行业入口。
- 主次是否明确：首页是否没有一屏塞太多按钮和卡片。
- 文案是否像人话：避免 `SCRM`、`UserNote`、`Showcase`、`CustomerAction` 等内部词。
- 视觉是否统一：卡片、间距、按钮、状态标签、底部 Tab 是否像同一个产品。
- 按钮是否可点且文字居中：小程序按钮、胶囊、状态标签必须上下左右居中，不截字。
- 空态是否有引导：不能只显示“暂无数据”，必须告诉用户下一步可以做什么。
- 真机是否舒服：普通手机、大屏手机、iPad 不横向溢出，底部操作不遮挡内容，图片不破、不糊、不空白。

UI 明显不符合参考图或产品文档时，即使功能可点，也不得直接判定“通过”，最多判定“需要人工确认”或“不通过”。

## 6. 首页 Tabbar 一期报告命名

建议输出：

- `docs/qa/首页与Tabbar工作台模式一期_测试清单与验收标准.md`
- `docs/qa/首页与Tabbar工作台模式一期_验收报告.md`
- 如有 Bug：`docs/qa/首页与Tabbar工作台模式一期_Bug修复任务单.md`
- 修复后：`docs/qa/首页与Tabbar工作台模式一期_复测与回归报告.md`

## 7. 验收报告要求

验收报告必须明确给出以下结论之一：

```text
通过
不通过
需要人工确认
```

P0 未全部覆盖时，不得给出“通过”。

涉及 UI / 信息架构时，验收报告还必须包含：

- 产品心智结论：用户是否能理解“当前工作台”和下一步动作。
- 模式隔离结论：普通用户是否被业务功能干扰，业务用户是否看到自己的主流程。
- UI 真机风险：是否有横向溢出、按钮遮挡、文字不居中、空态无引导、图片破图。
- 需要用户人工确认的截图或真机事项。
