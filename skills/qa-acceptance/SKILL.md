# teamBuy QA 验收 Skill

## 1. 使用场景

当用户要求生成测试方案、验收标准、Bug 修复任务单、回归测试清单、上线检查表，或要求对 Codex 开发结果进行 QA 验收时使用本 Skill。

AI 测试官默认不修改业务代码，只输出测试、验收、Bug 和回归材料。

## 2. P0 验收范围

必须覆盖：

- 企业微信客服回调
- sync_msg 消息拉取
- 微信笔记消息聚合
- 媒体下载和转存
- 导入成功通知
- 导入失败通知
- 待认领导入
- 小程序登录
- 卡片草稿生成
- 卡片编辑保存
- 卡片分享查看
- 电话拨号
- 字段复制
- 登录浏览用户统计
- 匿名浏览统计
- 实名接龙
- 手机号和地址附加字段
- 接龙名单管理
- 删除无效接龙
- 标记已跟进
- 素材库搜索分类
- 一键复用
- 数据隔离和回归测试

## 3. P0 风险判定

以下情况直接判定为 P0：

- 企业微信回调无法接收。
- sync_msg 无法拉取消息。
- 微信笔记无法形成卡片草稿。
- 图片或视频 media_id 未及时转存导致素材丢失。
- 导入成功但用户无法认领。
- 导入失败但没有通知用户。
- 卡片无法保存。
- 卡片无法分享。
- 群用户无法打开卡片。
- 电话拨号不可用。
- 字段复制不可用。
- 浏览统计严重错误。
- 匿名用户被错误展示为实名浏览用户。
- 接龙无法提交。
- 接龙名单团长不可见。
- 普通用户看到未脱敏昵称。
- 删除无效接龙不可用。
- 标记已跟进不可用。
- 一键复用覆盖原卡片数据。
- 密钥、Token、AppSecret 泄露到前端或 Git。

## 4. 测试用例格式

测试用例必须使用 Markdown 表格：

```md
| 编号 | 模块 | 测试名称 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 是否适合自动化 | 备注 |
|---|---|---|---|---|---|---|---|---|
```

## 5. 验收报告要求

验收报告必须明确给出以下结论之一：

```text
通过
不通过
需要人工确认
```

P0 未全部覆盖时，不得给出“通过”。
