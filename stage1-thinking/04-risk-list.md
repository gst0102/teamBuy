# 风险清单

| 风险 | 类型 | 严重程度 | 概率 | 影响 | 缓解措施 | MVP 是否必须处理 |
|---|---|---|---|---|---|---|
| 微信笔记没有专门消息类型 | 技术风险 | 高 | 高 | 无法直接拿到完整笔记对象 | 用 sync_msg 拉取多条消息，并实现消息聚合规则 | 是 |
| 企业微信媒体 media_id 有时效 | 技术风险 | 高 | 高 | 图片、视频过期后无法下载 | 收到消息后立即转存到自有存储 | 是 |
| 消息聚合错误 | 技术风险 | 高 | 中 | 多条笔记可能合并错或拆分错 | 按 external_userid、会话、时间窗口聚合，并保留原始消息便于重试 | 是 |
| 首次导入后补绑定失败 | 产品风险 | 高 | 中 | 导入内容无法归属到用户账号 | 设计待认领列表和清晰认领入口 | 是 |
| 浏览用户身份不完整 | 产品风险 | 中 | 高 | 未登录浏览者无法展示头像昵称 | 登录用户展示头像昵称，匿名用户只计入总量 | 是 |
| 用户觉得编辑成本高 | 产品风险 | 高 | 中 | 导入后仍需大量修改，降低留存 | 规则解析优先，大模型兜底，保证卡片草稿可用 | 是 |
| 小程序链接解析受限 | 技术风险 | 高 | 高 | 无法完整解析所有小程序内容 | 首版只按优先级尽量支持，不承诺全量解析 | 是 |
| 内容版权和转发边界不清 | 合规风险 | 中 | 中 | 外部素材搬运可能有争议 | 保存来源链接，避免宣称自动抓取第三方私有内容 | 是 |
| 隐私展示不当 | 合规风险 | 高 | 中 | 浏览者和接龙者身份可能被过度展示 | 普通用户昵称脱敏，浏览列表仅展示已登录用户 | 是 |
| 首版范围过大 | 资源风险 | 高 | 高 | 上线周期延长，核心链路不稳定 | 先围绕导入、卡片、查看、统计、接龙验收，不做支付和订单 | 是 |
| 接龙附加字段过重 | 产品风险 | 中 | 中 | 群成员不愿填写 | 首版只支持手机号、地址，并由团长选择是否开启 | 是 |
| 统计数据不准确 | 技术风险 | 高 | 中 | 团长不信任数据 | 区分 PV、UV、登录用户、匿名用户，保留明细和日汇总 | 是 |
| 商业化过早 | 商业风险 | 中 | 中 | 用户未感知价值前被收费劝退 | 先验证导入复用价值，再设计订阅限制 | 否 |
| 企业微信主体一致性 | 合规风险 | 高 | 中 | 小程序和企业微信无法正常接入 | 阶段二明确主体、认证和后台配置要求 | 是 |
